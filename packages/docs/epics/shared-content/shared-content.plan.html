Docs content is tracked per branch today, which costs twice:

  • a worktree can't see another worktree's plan docs or docs edits, or main's newer ones (it has the copy it was cut with)
  • changelog.html, index.html and PAPERCUTS.md conflict on most merges: 7 of the last 50 commits were "Merge main into X", these files the repeat offenders

Every checkout (main and each worktree) gets three links, each a whole folder. The real folders live in ../spell-app-dev, at the same paths (Q9).

Link Holds
packages/docs/content ALL docs content, at the paths it has today under packages/docs: index.html, changelog.html, guide pages, epics/, solid/, dev/, templates/ ...; details/ (scratch, not committed)
goals goal sets, the goals index.html, goals.preferences.json5
agents PAPERCUTS.md, SUSPECTED-BUGS.md, CODE-DEBT.md (moved from the repo root)

The tools stay tracked in spell-app, versioned per branch: docs scripts, _assets and the goals tooling go to packages/docs/tools/, beside the content link (Q9). Templates are content (Q10).

Every docs URL gains /content/ (C6); links between pages don't change.
  • A new worktree: the WorktreeCreate hook runs spell dev shared link, so its three links are there from the start.
  • Editing: Claude, VS Code and the page server all edit through the links; the change lands in ../spell-app-dev and every checkout sees it at once.
  • Committing: after every turn, a Stop hook commits whatever changed in the peer (Q5). Nobody commits docs on a branch any more.
  • Merging a branch: it touches no shared files, so the changelog and logs can't conflict.
  • Checking: spell dev shared status shows each checkout's links and the peer's state.

The real files sit in an ordinary git repo next to the main checkout, /Users/owen/www/spell-app/spell-app-dev. No GitHub remote for now (Owen: "it's still just me").

Q3 Folder links only: three whole-folder links, packages/docs, goals and agents

The spike (P1) found that Claude's Edit tool refuses to write through a link to a single FILE ("it is a symbolic link, write to the target"). Folder links work. So each checkout gets exactly three links, each a whole folder:

  • packages/docs: every docs page as today, epics/, changelog.html, index.html, guide pages, details/ (scratch)
  • goals: the goal sets, index.html, goals.preferences.json5
  • agents: PAPERCUTS.md, SUSPECTED-BUGS.md, CODE-DEBT.md, moved from the repo root (the folder name is Owen's)

Rejected: content subfolders (packages/docs/pages/): every docs URL and link would change.

Net effect:

  • no page URL changes; links between pages keep working
  • every reference to the root logs becomes agents/...
Q4 Goals tooling goes into packages/doc-tools too

Q5 Commits in the peer are automatic, every turn

A Stop hook runs spell dev shared commit --auto in the background after every turn of every session: it commits whatever changed in ../spell-app-dev, under a lock so two sessions don't collide.

Net effect:

  • nobody commits docs by hand any more; no docs or log merge conflicts
  • the peer's history is many small auto: commits, each naming its checkout and session

Q9 Tools stay tracked in spell-app/packages/docs/tools; docs content is ONE link, packages/docs/content

Replaces Q2, Q3 and Q4 (Owen, 2026-10-04). The docs and goals scripts live at spell-app/packages/docs/tools, tracked and versioned per branch. So packages/docs stays a real folder, and its content is linked one level down:

  • packages/docs/ (tracked): package.json, AGENTS.md, tools/ (scripts, _assets, goals tooling)

C1 commands:check can fail on main while a branch has added a command

The commands map is shared, but the CLI it's checked against is per branch. Example: a worktree adds spell dev foo and its row to commands.json; until that worktree merges, yarn commands:check on main reports a row for a command that doesn't exist.

Net effect:

  • accepted for now (Owen: revisit later); a CODE-DEBT.md entry
C2 file:// pages from a worktree load the MAIN checkout's assets

The peer's packages/docs/tools link points at the MAIN checkout's spell-app/packages/docs/tools, the main checkout. A worktree that changes the CSS or the bundle sees its change only through its own page server (which mounts its own _assets), not from file://.

Net effect:

  • check-spell.js in a worktree should load pages from the page server when assets changed
C3 Search must follow links

These sessions have no Grep / Glob tools. grep -r and plain rg skip linked folders; grep -R follows them, rg needs -L (and the links are gitignored, so rg also needs --no-ignore-vcs or a root .ignore).

Net effect:

  • AGENTS.md says so (P7)
C4 Old commits and unmigrated branches replace a link with a real folder

Checking out a commit from before the cutover, bisecting, or merging a branch that still tracks the moved files makes git write real files where the link was. The peer stays safe (git never follows the link), but that checkout stops sharing until spell dev shared link repairs it.

Net effect:

  • every open worktree is migrated BEFORE it merges main (P6)
  • repair never overwrites peer content with a checkout's copy
C5 The public repo loses the docs, changelog and plans

origin is public (github.com/spell-app/spell-app). After the cutover, links to docs pages from the README or code comments are dead there and in a fresh clone without the peer (Owen: "no worries, it's still just me").

C6 Every docs URL and path gains /content/

Pages move from packages/docs/x to packages/docs/content/x. Links between pages keep working; everything else that names a docs path needs a scripted rewrite in P2:
