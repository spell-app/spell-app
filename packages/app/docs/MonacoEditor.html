MonacoEditor A Monaco editor, filling its parent: what every code editor in the app is.

Monaco, the code editor VS Code is built on, as a Solid component that fills the box it's in. Every code editor in the app is one: the code pane, the "Javascript Output" pane, and the editor in a <spell-editor>.

Written for: anyone changing a code editor in the app, or reading its code A picture, not live: Monaco needs the editor's page around it

The one in the editor's "Javascript Output" pane, without the pane's toolbar: Solitaire's Card.spell, compiled.

The "Javascript Output" pane draws one on some text, read only. It loads it lazily, so it goes inside a <Loading> that shows "Loading editor…" till it's in:

OutputEditor.tsx · the compiled javascript · 3 lines
  • Monaco is most of the app's code, and only the editor's pages need it. So it's never imported directly: the app loads it the first time it's drawn, through LazyMonaco, and a <spell-editor> through its own loader.
  • It shows model, a file's text the app keeps, which wins; else value, in language, in a model of its own. The FileEditor hands it a file's model.
  • It's made once, when it's settled into the page: draw a new one for a fresh editor, such as one per file.
  • A new value goes in only if it differs, as a new starting point: undo can't go back past it, and onChange isn't called. That's only for the person's own edits.
  • onMount and onUnmount hand out the editor itself, to add keys or follow the cursor.
  • It works inside a shadow root too, as in a <spell-editor>: it keeps mouse moves over it there, so its hovers stay up.
