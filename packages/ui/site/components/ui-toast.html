Toast A toast allows users to receive a short, non-blocking notification. Not yet: the progress bar's own colour (Fomantic's classProgress: 'red') -- it takes the toast's colour; restyle it with ui-toast::part(bar). Not ported: Attached Position (position: 'top attached' / 'bottom attached', full-width toasts like a phone's notifications) and Center Aligned content (class: 'center aligned') -- left out of the toast sheets on purpose.

You can choose how long a toast should be displayed: displayTime (display-time on the element), in milliseconds. 0 keeps it until it's clicked, and auto calculates the time from the number of words (120 a minute, at least a second).

Not ported: Use Message Style (className: { toast: 'ui message' }) -- a toast is a <ui-toast>; slot a message's content into one instead.

Define click actions on your toast with a text and/or icon, optional class and click handler.

The default click handler closes the toast, so leave it out when the button should only close it. A handler returning false keeps the toast open. In the page, put <ui-button slot="actions">s in the toast: any activated one closes it unless its click was preventDefault()ed. Yes ? A Toast can be generated out of existing DOM nodes, with any markup inside.

Just like a modal, a toast ties approve / deny to any positive / approve, negative / deny or ok / cancel button: ui-approve and ui-deny, cancelable, so preventDefault() keeps it open.

Not ported: Template, Message and Card toasts ($('.ui.message').toast()) -- a toast is a <ui-toast>; slot the content you'd have put in a message or card into one.

Each UI.toast() call returns a handle: closed resolves when the toast is gone, element is the <ui-toast>, and UI.toasts.dismiss(id) closes it early.
