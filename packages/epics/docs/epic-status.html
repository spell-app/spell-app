Its parents:

A later mark on the same item gets a new card after the old ones, which stay as the record.

Its children:

Child How many What it holds
prose any number The reading: one or two sentences, no file names.

Name Values Meaning Required
state underway, done underway (blue: Claude is on it; absent too), done (green: finished).

A slot is a place in the drawing that a child goes to: a child with slot="name" goes to that name's place, every other child to the default one (shown as default).

Slot What goes there
default The reading: what Claude understood the task to be, in a sentence or two.
summary Once done, and only when worth saying: what Owen should know about it.

A part is a piece of what the element draws in its shadow root (its own hidden markup), named so a stylesheet can reach it: epic-status::part(header).

Part What it is
base The card: blue underway, green done.
header Its heading band, a flex row: the fold chevron, who left, date right; a click folds it.
toggle The fold chevron, a <button>, first in the band: folds reading and summary.
who The heading's left: Claude • Underway / Claude • Done.
date The heading's right: done-at, else at, as 10/8/26 14:34; never wraps.
body The reading.
summary The summary, under the reading; not drawn without one.

A state is a word the element sets on itself while something is true, for styling: epic-status:state(open). Never written in the file.

State When
underway state=underway.
done state=done.
open Unfolded: it starts so (page state, never written).

The colours mean the same on every doc page: the whole scheme is on Epic Page Colours (its source: plan-doc.md, "Colours").

  • Claude • Underway: blue, Claude is working on it. An underway card turns its item's chip blue (progress) until it's done.
  • Claude • Done: green, finished. The date on the right is done-at; its tooltip says when Claude took the mark (at).
  • Its border is stronger than a reply's, so it stands out from the reply cards around it.
  • The reading first; the summary under it, across a rule, only when there is one.

It folds by its heading band: a click anywhere on the band (but on a link or a button in it) folds or unfolds it, the chevron first in the band. It starts open, since it's the text being read; folding is the reader's own and never written into the file. Folded text is still found by the browser's find-in-page, which unfolds it.

Only the epic tool writes them:

  • plan-doc status <name> <id> underway "html": a new underway card, stamped now, with Claude's reading of the task (a sentence or two, no file names); the page's spinner on
  • plan-doc status <name> <id> done ["html"]: the latest underway card turns done (done-at), the reading kept, the summary added; refused with no underway card
  • plan-doc status <name> <id> done --filed "html": a card born done (at alone)
  • plan-doc inbox <name> apply: a card born done for each pick (Chose B · <option>) and each todo it files; none for an approval
  • A rewrite of the item's text leaves its cards where they are: they never reach its Original Discussion.
