// `<ui-table>` wraps ONE native `<table>` that stays in the light DOM:  the element mirrors its class words onto
// it (`ui celled striped table`) and registers `ui-table.css` as a page sheet.  Row and cell looks are Fomantic's
// own classes on `tr` / `td` / `th`.  The examples in `src/components/ui-table/examples/elements/` are ~2000 lines;
// near-duplicates (every colour, both sizes, three attachments ...) are trimmed to a few rows each here.
// `stackable` answers to the VIEWPORT, as in Fomantic:  below 768px every table without `unstackable` stacks.

<Section title="Behaviour">
  `<ui-table>` holds ONE native `<table>`, and the table stays in the page (the light DOM):  its semantics,
  find-in-page, copy and your own CSS all work as on any table.  The element only adds the look, sorting and a
  scroller.  It copies its class words onto the table (`<ui-table celled striped>` gives
  `<table class="ui celled striped table">`), adding and removing only its own words, so your classes stay.  A
  server can write that class string itself, and the table paints before any script runs.

  Rows and cells keep Fomantic's classes on the native `tr`, `td` and `th`:  `positive`, `left red marked`,
  `collapsing`, `four wide`, `right aligned`.  No script, no extra elements.  `columns="4"` is Fomantic's
  equal-width column count;  the data mode's column list is the separate `columnDefs` property.

  `stackable` answers to the VIEWPORT, as in Fomantic:  below 768px every table stacks unless it is `unstackable`;
  `stackable="tablet"` also stacks below 992px.  A table in a narrow sidebar of a wide screen can opt in to its OWN
  width instead with `stack-by="container"`, or for a whole region with the token `--ui-table-stack-by: container` (on
  an ancestor or the page);  the attribute wins over the token.

  With `sortable`, every header in the `thead` sorts, unless it has `data-sortable="false"` (or Fomantic's
  `class="disabled"`).  A click, or Enter / Space on a focused header, first dispatches the cancelable `ui-sort`
  (`{ column, key, direction }`, where `key` is the header's `data-key`);  then `sort-column`,
  `sort-direction` and the header's `aria-sort` update.  The same header again flips the direction;  a new one
  starts `ascending`.  The element does not move your rows unless you ask:  `client-sort` reorders a simple
  table's `tbody` rows by the sorted column's text (numbers in number order);  otherwise sort the rows yourself.

<Section title="Theming">
  Theme with the public `--ui-table-*` tokens:  set one on the element, on any ancestor (`:root` included), on the
  table itself (it's in your page) or through `::part(scroller)`.  The sheet reads each through a private alias, so

  is the `scroller` part.

ui-table {

}
ui-table::part(scroller) {
  scrollbar-gutter: stable;
}

<Section title="Accessibility">
  - The table is a real `<table>` in the document, so screen readers read its rows, columns and headers natively.
    Mark headers with `th` and `scope` (`col`, `row`, `colgroup`), and name the table with a `<caption>`.
  - Row and cell states (`positive`, `error`, `warning`, colours, `marked`) are visual only:  say the same thing
    in the cell's text too.
  - Sortable headers:  put a `<button>` in each, as the WAI-ARIA sortable table pattern does.  A header without
    one is made focusable and answers Enter and Space.  The sorted header gets `aria-sort`.
  - `scrolling` and `overflowing` make the scroller a focusable `role="region"`, so keyboard users can scroll it.
    It is named by the host's `aria-label`, else the table's `<caption>`, else the translated `label` ("Table").

  | Key                    | Action                                                       |
  | ---------------------- | ------------------------------------------------------------ |
  | Tab                    | Move to each sort button (or focusable header), and to a scrolling region |
  | Enter / Space          | Sort by the focused header;  again flips the direction       |
  | Arrow keys, Page Up / Down | Scroll a focused scrolling region                        |

  - If the element fails to render, its native fallback still copies the class words onto the table and keeps
    the scroller (a named region while scrolling), so the table looks the same.  It drops sorting (`ui-sort`,
    `aria-sort`, focusable headers, `client-sort`), data mode (nothing renders without a slotted `<table>`), the
    translated `label` and later attribute changes.
</Section>

<Section title="Framework usage">
  Render the `<table>` inside `<ui-table>` as usual.  For data mode, set `rows` / `columnDefs` as properties, not
  attributes, and listen for `ui-sort`.

```jsx
// React 19
<ui-table celled sortable rows={rows} columnDefs={columns} onui-sort={(e) => setSort(e.detail)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-table celled sortable :rows="rows" :columnDefs="columns" @ui-sort="(e) => (sort = e.detail)" />
```

```jsx
// Solid 2:  no `on:` namespace, so add `ui-*` listeners in a ref callback
<ui-table
  celled
  sortable
  prop:rows={rows()}
  prop:columnDefs={columns}
  ref={(el) => el.addEventListener("ui-sort", (e) => setSort(e.detail))}
/>
```
