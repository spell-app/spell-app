1. Plan

New leaf package packages/server ($/server, namespace SRV): one set of page-serving helpers replaces six hand-rolled copies in goals, the VS Code preview, the CLI, ui's tools and the app's Express API. On it, ONE per-checkout page server serves docs, plans, goals, Spell UI docs and finally the editor (spell serve) on one port, with live reload, a shared site header and an API that edits pages in place.

    3. Overview

    What gets built; becomes packages/docs/server.html in P8.

    3.1 Structure

    packages/server/src/: barrel is node built-ins only (D4).

    • server.types.ts: Handler, RouteParams, HtmlTransform, FileTransform, Mount, ServerInfo, HttpError
    • mime.ts: ONE TYPES table (union of cli / goals / DocPreview copies)
    • safePath.ts: resolveInside(root, urlPath) -> file, or 400 / 403 / 404; dir -> index.html
    • StaticHandler: prefix -> dir mounts (longest wins), HEAD, no-store, ETag, html hooks, per-ext transform hooks
    • Request / Reply / Router / bodies: the Express subset the app's api.ts uses
    • LiveReload: SSE hub over fs.watch, 250ms debounce; client assets/live.js
    • Guard: Host allowlist, per-run token (x-server-token), same-origin check
    • ports.ts: isFree, freePort, listenPreferred
    • PidFile: status (ping + root match), ensure (spawn detached, poll), stop
    • FileLock: <file>.lock, from goals' withLock
    • open.ts: browser, new window, reused Chrome tab, VS Code
    • WebServer: node:http + all of the above
    • opt-in, not in barrel: page/ (page server, editor, CLI, Astro proxy), site/ (site header)

    3.2 Page Server
    • one per checkout root (main + each worktree): pid <root>/.spell-server.json, log .spell-server.log
    • port: prefer 4747, else any free; real port in pid file; pages read injected window.SPELL_SERVER
    • / -> docs index; /_server/ping|events|live.js|page; /ui/ -> astro dev (D10); dot files blocked
    • watches named folders only (never the whole root: node_modules, .git, worktrees flood the watcher)
    • route modules, listed in root package.json "pageServer": {"routes": [...]}: goals (P5), app (P7)
    • yarn server serve|start|ensure|stop|status|url <file>

    3.3 Editing Pages
    • writes the ORIGINAL file; never commits (D12)
    • PUT /_server/page?path=: whole page
    • PATCH /_server/page?path= {id, html, inner?}: one element by id; parse5 source locations give its byte range, so the rest of the file is untouched
    • missing id 404, duplicate id 409, stale If-Match 409, bad token 403
    • UI (D18): hover a section with an id -> edit -> source textarea -> save

    3.4 Locking

    Yes, needed (D13): several writers touch the same pages.

    • SRV.FileLock: tools that cooperate (page-edit API, yarn plan-doc, yarn goals, app saves); replaces two copied withLocks and the unused proper-lockfile lock-utils.ts
    • If-Match / ETag: writers that don't lock (VS Code, Claude's Edit): 409, caller reloads

    3.5 Site Header
    • <spell-site-header>: fixed bar; Docs, Spell UI, Plans, Goals, Editor; active one from the path
    • also: worktree / branch badge, title + breadcrumb, Open in VS Code, light / dark toggle (D17)
    • self-contained (shadow DOM), in the docs bundle and the Astro layout; in each page / template, so it shows on file:// too (D11)
    • sets --spell-site-header-height so sticky headers sit below it

    3.6 Flows
    1. open a page: caller runs yarn server ensure -> base URL -> opens base/<path> (Chrome tab, or VS Code)
    2. file changes: watcher -> SSE change -> live.js reloads if it's this page or css / js
    3. goals button: POST /api/goals/<op> + token -> Guard -> goals route module
    4. VS Code preview ?file=: page server running -> its URL; else an in-process server
    5. spell serve: ensure page server (all route modules), then Vite for editor dev, /api proxied to it

    For later: not caveats, not issues.

    1. T1 Adopt SRV.FileLock everywheredetails

    2. T2 Delete app ts.zip if staledetails

    3. T3 Review: :name* holds the whole restdetails

      P1. Chose to FIX Express 4's :filePath* (first segment only, rest in params[0]; nested project files 404 / EISDIR) over copying it. The app's QUIRK contract tests change with it in P6.

    4. T4 Review: edits require If-Matchdetails

      P2. PUT / PATCH without If-Match answer 428, over allowing blind writes. Every caller (the edit UI, editPage()) has the ETag from the page it loaded.

    5. T5 Review: live client is a stringified functiondetails

      P2. liveClient() is TypeScript served as (fn)(), over a static .js asset: the VS Code bundle (cjs) has no import.meta.url to find an asset by. Needs a __name shim (tsx keepNames).

    6. T6 Review: Vite's root paths go to astro devdetails

      P4. In dev, Astro serves its modules from the ROOT whatever base is (/@vite/client, /@fs/..., /src/...). Chose to proxy those paths to astro dev while it runs (none exists at the repo root) and its HMR websocket by its vite-hmr subprotocol, over running Astro on its own port in an iframe or a redirect.

    7. T7 Review: astro dev --ignore-lockdetails

      P4. Astro 7 backgrounds astro dev by itself when it detects an AI agent in the environment (CLAUDECODE ...), then exits; --ignore-lock keeps it in the foreground so the page server owns and stops it. Side effect: no Astro lock file, so yarn site:dev beside it won't notice it.

    8. T8 Review: Open in VS Code is a vscode://file linkdetails

      P4. The header's button is a plain vscode://file/<path> link: works from file:// too, but opens in the LAST FOCUSED VS Code window, not this session's (the window bridge would need a server endpoint).

    9. T9 Review: two theme toggles on Spell UI pagesdetails

      P4. The header's light / dark / OS button sets color-scheme on <html>; the Astro site keeps its own Light / Dark / System toggle. They can disagree. Left both: the site's toggle is part of what it documents.

    10. T10 Review: extension never starts the page serverdetails

      P4. DocPreview uses a running page server (pid file), else its own in-process SRV.WebServer (live reload, no goals buttons, no /ui/). The scripts that open docs start the page server first. Alt: have the extension spawn it (GUI VS Code may lack node on PATH).

    7. Decisions

    What was decided, and why. Settled: don't re-argue without new facts.

    1. D1 Library + ONE page serverdetails

      Not library-only. Why: docs and plans gain live reload; one URL scheme for every property.

    2. D2 TypeScript; goals runs via tsxdetails

      Why: repo convention. Accepts goals being less portable (C2).
    3. D3 Migrate goals, DocPreview, cli serve, ui StaticServer, app Expressdetails

      Vite dev servers (app, ui tools) and Astro stay; Astro is proxied at /ui/.

    4. D4 Leaf package; page/ and site/ opt-indetails
      • barrel: node built-ins only; json5 / esbuild come in as caller hooks
      • page/, site/: not in the barrel, may have deps (parse5)
      • anything may import it: ui/tools, ui/site, spell/node, cli, app, vscode, docs, goals
    5. D5 Goals endpoints move to /api/goals/*details

      Header x-goals-token becomes x-server-token. Already-open goals pages need one reload.

    6. D6 App migration starts with contract testsdetails

      Tests run against the CURRENT Express server first, then unchanged against the new router.

    7. D7 Self-namespace SRVdetails

      SRV.Router, SRV.WebServer. Owen's pick.
    8. D8 Up to 10 agentsdetails

      Owen's answer; overrides the earlier max-5 default for this work. Parallel only where files don't overlap.

    9. D9 Docs And Preview before Goalsdetails

      Owen: header and openers land first; goals then reuses them.
    10. D10 Spell UI docs: proxy astro dev at /ui/details

      Owen's pick: live HMR, no rebuild lag. Costs a second process (C5).

    11. D11 Site header in each page and templatedetails

      Owen's pick over server injection: shows on file:// too. Costs a one-time edit of every page (C6).

    12. D12 Page edits write the original file, never commitdetails

      Section edits by id splice the source byte range (parse5 locations), so nothing else in the file is reformatted.

    13. D13 Locking: SRV.FileLock + If-Matchdetails
      • FileLock serializes cooperating tools: page-edit API, plan-doc, goals, app saves
      • If-Match / ETag catches writers that don't lock (VS Code, Claude's Edit): 409, caller reloads
    14. D14 spell serve runs everythingdetails

      Once app is integrated (P7): docs, plans, goals, Spell UI, editor, one server.
    15. D15 All phases overnight, commit per phasedetails

      Owen's instruction: commit after each phase on branch unified-server without asking; leave unmerged for review (/isolate done).

    16. D16 Failing checks: record, WIP commit, continuedetails

      Record an issue, commit with a WIP: prefix, go on with phases that don't depend on it; stop only if everything after depends on it.

    17. D17 Header extrasdetails
      • worktree / branch badge
      • page title + breadcrumb
      • Open in VS Code button
      • light / dark toggle

      Badge and VS Code button hidden on file://.
    18. D18 Page edits: API + edit-section UIdetails

      Hover a section with an id -> edit -> source textarea -> PATCH; 409 -> reload prompt. API in P2, UI in P4.

    19. D19 P3: StaticServer kept as a thin wrapper over SRV.WebServerdetails

      Kept the class (listen/close, plus a new untilInterrupted) so SmokeRunner is barely touched; it owns only the import-map html hook and the esbuild .ts transform. DockerBrowserServer.freePort now calls SRV.freePort (same 127.0.0.1, port 0). Side effect: listen() now falls back to any free port if the wanted one (5199) is taken, instead of failing.

    20. D20 Spell UI site: base /ui, header via aliasdetails

      packages/ui/site now has base: "/ui"; internal URLs already went through url() (BASE_URL), so only config changed. $/server alias added to astro.config.mjs and site tsconfig (no package.json dependency needed, same as $/util). Docs.astro carries <spell-site-header> + defineSite(); site.css sticky header, sidebar, TOC and anchors are offset by --spell-site-header-height.

    21. D21 P4: header height stays out of --spell-topdetails

      The header's own :root { scroll-padding-top } already adds --spell-site-header-height to every native jump, so --spell-top and the headings' CSS scroll-margin-top leave it out (else a native jump would count it twice). spell-doc-runtime.js adds it (siteHeaderHeight(), 0 without a header) where it measures from the viewport top: h2 / h3 sticky offsets, the contents' sticky offset, its own anchor jumps, and the scroll-follow line. CSS adds it to the cheatsheet filter bar's top, the contents column's height and the narrow-screen drawer's top / height.
