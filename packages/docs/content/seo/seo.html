Static Pages for SEO

How a page of ui-* elements becomes plain HTML and one stylesheet, with no shadow DOM and no element scripts, so crawlers and readers without JavaScript see the whole page.

Plan doc: epic seo Written for: anyone publishing a static page (spell static), calling $/ui/server from code, or changing a ui-* family so it still renders statically Status: built (P1-P5) Checked on: branch seo, 2026-10-02, against the code, a fresh spell static run and the static parity report (plan: epics/seo)
  • spell static page.html writes page.static.html beside it, and the folder's shared, cached stylesheet, ui.static.css.
    • every ui-* element is rendered in node and replaced by plain HTML
    • the scripts that load the elements are removed
    • the stylesheet holds only the families the page uses, minified
  • With JavaScript off, dialogs, click popups, accordions and forms still work, through native HTML (4).
  • The same render is a library, $/ui/server, for a node server that renders per request.
  • Numbers:
    • 93 element classes in StaticCatalog, every family but ui-code, ui-include and ui-markdown
    • 287 of 342 example screenshots (every family's examples, light and dark, Chromium) differ from the live elements by 1% of pixels or less; most of the rest is known drift (9)
    • about 3 s per spell static run, mostly Vite compiling every family; pages in one run share it
  • Pages that must be read without JavaScript: crawlers, link previews, archives, very slow devices.
  • NOT for pages that need the elements' behaviour: the static page must never load the elements (9, C4).
Command Writes

spell static docs/ -o site/ every .html under docs/, same names under site/
--inline-css each page's own stylesheet in a <style>, no .css file
--css site/ui.css ONE stylesheet for every page, linked from each
--no-minify the stylesheet readable, to debug it
  • A folder means every .html in it, except *.static.html, node_modules and dot folders.
  • It never overwrites a page: -o naming an input is refused.
  • stdout lists each page written; stderr has sizes, removed scripts, and any ui-* tag it left as it was.
  • Details: packages/cli/README.md, "static".
  • elements: each ui-* of a known family becomes its rendered HTML (3)
  • scripts: a <script> or <link rel=modulepreload> that loads the elements is removed: one naming @spell-app/ui, $/ui, ui's src/ / dist/, a family folder, or the docs' spell-ui.js. Other scripts and import maps stay.
  • stylesheet: linked FIRST in <head>, before the page's own CSS, so its layer order comes first
  • page CSS: its <style>s are rewritten, and each local linked sheet that mentions elements is inlined in place, rewritten (<style data-static-from="...">) (5.3)
  • An element upgrading on a static page would take the rendered HTML for its slotted content and show it twice.
  • So the docs' spell-ui.js goes, and with it what it also bundles: the site header and the contents sidebar.

Node only. The components' JSX must be compiled for the server (generate: "ssr"), so load it through Vite's SSR, as packages/ui/tools/StaticRenderer.ts does, never through plain node / tsx.

  • StaticRender.define(...classes): the families to render, once
  • await StaticRender.prepare(html): icon packs and each family's async data (MUST be awaited: the render itself is synchronous)
  • StaticRender.page(html) / fragment(html): the rendered HTML
  • StaticStylesheet.build(families, StaticRender.sheetUsage): the stylesheet for the tags that rendered (StaticRender.lastTags)
  • StaticRender.resetUsage() between pages, so each page's stylesheet covers only that page

Whole documents (script removal, linked sheets, minify) are packages/ui/tools/StaticDocument.ts's StaticDocument.render(html, options), which spell static calls in a child process.

Every element's controller renders to a string, as it would render into its shadow root. Then each element is flattened: the host gives way to its root.

packages/ui/src/server/StaticRender.ts, render() · 32 lines 
/** Steps 2-5 on a parsed `document`. */
private static render(document: Document) {
  const ids = ServerRuntime.install().ids as unknown as ServerIds
  // generated ids skip the page's own, numbered from 1 per page
  ids.reset(document)
  const elements = [...document.querySelectorAll("*")].filter((element) =>
    StaticRender.families.has(element.localName)
  )
  StaticRender.lastTags = new Set(elements.map((element) => element.localName))
  const { hosts, dispose } = createRoot((dispose) => ({
    hosts: elements.map((element) => StaticRender.build(element)),
    dispose
  }))
  try {
    for (const { host, family } of hosts) StaticRender.recordSheets(host, family)
    const views: StaticView[] = hosts.map(({ host, family }) => ({
      element: host as unknown as Element,
      family,
      // `NoHydration`:  nothing hydrates a static page, so no `_hk` keys
      html: renderToString(() =>
        createComponent(NoHydration, {
          get children() {
            return ServerElement.run(host, () => host.controller!.mount())
          }
        })
      )
    }))
    StaticFlattener.flatten(document, views)
    StaticInteractions.wire(document, ids)
    StaticRender.rewriteStyles(document)
  } finally {
    dispose()
  }
}

All in packages/ui/src/server/ ($/ui/server, namespace SSR).

ServerRuntime The UI runtime in node: real ids, i18n, vocabulary, icons; no-op styles; any other service throws, naming itself. ServerHost A linkedom element dressed as a host: internals, setState(), renderRoot stand-ins that record what the render set. StaticRender Drives the render: define, prepare, page / fragment, sheet usage. StaticFlattener Hosts out, roots in: slots, attributes, states, list items, phrasing retags. StaticInteractions What works without JS: commands, closers, popovers, unique ids. StaticStylesheet + StaticSelectors Component sheets rewritten for light DOM, each in @scope, in the right layers. StaticPageStyles The page's own CSS, rewritten so it reaches what it reached before. StaticCatalog Every family the render supports; kept in step with the visual tests' list by a test.

  • attributes: the host's id, class, style, data-*, aria-* ... move to the root; a form control's id and ARIA names go to its native control instead, so <label for> labels it
  • states: every host state (:state(x)) as data-state="x"; owner states (in-card) also as classes, the parts' class-grammar form
  • ARIA: what the element set on ElementInternals (role="status", aria-live) becomes attributes; element references become ids (aria-labelledby="ui-modal-1")
  • author content: slotted children are marked data-ui-slotted
  • list items: a <div> item root becomes the <li>; an <article> / <a> / <button> root is wrapped in <li data-ui-li> (display: contents); a role=list <div> holding them becomes <ul>
  • paragraphs: a <div> root where only phrasing content may go (the loader above), and every rendered <div> under a <p>, becomes a <span>: a browser would end the paragraph at a <div>
  • icons: inline SVG, aria-hidden, read from the packs on disk

Shadow DOM kept CSS in two directions. Without it, the static stylesheet does both jobs:

  • a component's rules must not reach into a nested component or into author content
  • the page's rules must not reach into a component's own markup
  • Each family's sheet is wrapped in @scope (<its roots>) to (<limit>).
    • roots: [data-ui="card"] (its kind), plus .ui.card markup the PAGE wrote (class grammar outside components, or in author content)
    • limit: [data-ui-slotted]:not([data-ui]) > *, :scope [data-ui] > *: author content and other components' roots are in scope (as ::slotted() and the host reached them), their insides aren't
  • Every subject is anchored with :where(:scope, ...). Inside @scope a bare .ui.card means a card INSIDE the root, never the root itself; :where() adds no specificity.
  • Rules about the component's own markup also say :not([data-ui-slotted]): in a shadow root they could never touch author content.
  • Host rules land on the root: :host(:state(in-cards)) > .ui.card => :scope:is([data-state~="in-cards"]):is(.ui.card).
  • List groups (cards, list, feed, steps, items): each A > B also matches A > [data-ui-li] > B, through the wrapper.
  • A sheet several families adopt (items take ui-list.css) is scoped to every kind seen adopting it, and sheets are emitted in the order elements adopted them.

The stylesheet opens with @layer ui-slotted, page, ui;, then the usual ui.* layers.

  • slotted layer: ::slotted(X) rules become plain X rules in @layer ui-slotted, first of all: in a shadow root any page rule beat them
  • host-only rules (:host { --ui-color: initial }) go to @layer ui.reset, minus display: they now share an element with the root's own rules, which must still win
  • foundation: tokens and utilities keep their page selectors; reset.css, which only ever applied inside shadow roots, is scoped to every component
  • [hidden] { display: none } unlayered: a component's display would beat the browser's own

The page's own CSS is rewritten (StaticPageStyles) so it reaches what it reached before:

  • ui-card => [data-ui="card"]: the tag is gone, the root has the kind
  • ui-card::part(header) => [data-ui="card"][part~="header"] and [data-ui="card"] [part~="header"] (that's why part attributes stay)
  • :state(x) => [data-state~="x"]
  • every subject gets REACH, :where(:not([data-ui] *), [data-ui], [data-ui-slotted], [data-ui-slotted] *): h2 { border } must not draw on a section's internal heading
  • layers and order as the page wrote them: unlayered page CSS still beats component rules on roots and author content, as it beat :host / ::slotted() rules in a browser

Solid's server build runs a component's render and its effects' COMPUTE, never an effect's APPLY. The host is a linkedom element in node. So:

  • An effect whose apply writes the HOST (internals.role, ARIA, states) is this.hostEffect(compute, apply): createEffect in a browser, applied once, at once, on a server.
  • A plain createEffect there leaves the static output without it.
  • Owner states (in-card) are set by PartContext itself.

  • NEVER instanceof Element / Node / ShadowRoot / HTMLSlotElement in shared code: node has none of them. Test nodeType and localName.
  • Anything that reads the DOM in a constructor needs an isServer guard; observers, focus and measuring belong in effects (they never apply on a server).
  • A family's barrel calls customElements.define(): server code imports its files.
  • The native control spreads a staticControl() that is {} in a browser (the HOST submits there, through ElementInternals) and, on a server, its name, starting value and the UIT.STATIC_CONTROL mark (data-ui-control).
  • The flattener moves the host's id, aria-label, aria-labelledby and aria-describedby onto the marked control, then drops the mark.
  • A control that isn't a form control renders hidden inputs instead (dropdown, slider).

Each links to its decision in the plan doc.

  • Solid's own server render, over a simulated DOM or a headless browser at build time: no browser needed, renders per request, and fixes ui's SSR for everyone (D2).
  • Replace each host with its root, over keeping the tags: ~40 of 55 families then match their class-grammar examples, and native.css hides undefined ui-root / ui-popup / ui-modal (D3).
  • Server code in its own entry ($/ui/server) and the fork's @spell-app/solid-element/server: client bundles get only isServer branches (D8, D9).
  • ServerRuntime, not UIRuntime: the real one builds CSSStyleSheets in its constructor (D11).
  • hostEffect(): the server build never runs an effect's apply (D10).
  • List items in <li>: a host's role=listitem has no valid place on an <article>; a <div> root becomes the <li> itself so :first-child and .item + .item still work (D4, D20, D14).
  • States as data-state, author content as data-ui-slotted: the stylesheet needs both to stand in for :state() and the slot boundary (D13).
  • Kind = the tag without ui-, not the vocabulary noun: five pairs of tags share a noun (D41).
  • <div> => <span> in phrasing content; form ids to the native control (D43).
  • @scope from data-ui roots, over per-element attributes: no new browser floor, anchor positioning already needs newer ones (D5).
  • Subjects anchored with :where(:scope, *): without it no rule styled the root (D18).
  • Host-only rules in ui.reset, slotted rules in ui-slotted: they keep the cascade they had across the shadow boundary (D15, D42).
  • Sheets scoped to every kind seen adopting them, in adoption order (D19).
  • Page CSS rewritten and kept out with REACH (D22, D58); class grammar the page wrote is styled too (D34).
  • Native invoker commands, popovertarget, <details>: the platform does it without scripts (D47).
  • Ids from one allocator that skips the page's own (D48, D24).
  • Forms submit through the native controls, server-only attributes spread onto them, so the browser render is unchanged (D28, D55).
  • A CLI command, not a yarn script (D7); in a child process on an SSR-only Vite server, so Vite's output and the server UI runtime stay out of the CLI (D49, D17).
  • page.static.html beside the page: its relative links keep working (D50).
  • Only element-loading scripts go: other scripts may be wanted (D51).
  • Stylesheet linked first: layer order is set by first mention (D52).
  • Lightning CSS, strict, nothing lowered; a sheet it can't parse is stripped, never silently cut (D53).
  • Local linked sheets inlined in place: cascade order unchanged, no extra files (D59).

Open caveats and issues in the plan doc, as of this check.

  • No zero-JS path for tabs, hover popups, dropdown choosing, calendar picking, search, shape, slider, element dimmer, nag close (C1); hover popups show nothing (T31).
  • Open popups, modals, flyouts, page dimmers and modal sidebars render closed (C11).
  • The server can't know: a tabs history hash, a nag's dismissal, measured sizes (C2).
  • The static page must not load the elements (C4).
  • closedby=any (backdrop close) isn't in Safari (C5).
  • A block root that isn't a <div> (<ul>, <dialog>, <details>, <article> ...) inside a <p> still splits the paragraph: wrap such elements in a <div> (C20).
  • Inline-block roots in flex rows lose their host's line box: checkboxes and ratings a few pixels shorter (C13).
  • Static steps never stack on narrow screens; grid-root rules like mobile reversed don't apply (C15).
  • A few pixels of drift in card groups and clearing segments (C10); consecutive grids miss their 1rem gap (T24).
  • display: contents on <li>: older Safari drops the list-item role (C9).
  • part attributes stay in the output (C7).
  • Page CSS in remote sheets, @import rules or set by scripts isn't rewritten; H::part(p) also reaches parts of components nested in H (C21).
  • Page CSS isn't moved into @layer page: unlayered page rules beat component rules on roots (T27).
  • The stylesheet is big: minifying saves ~16% (solid-2.html, 12 families: 338 kB -> 285 kB, gzip 39.5 -> 38.2 kB) (C19).
  • A page with popups isn't minified at all: Lightning CSS can't parse @container anchored(), so the whole sheet falls back to stripping comments (I25).
  • Examples built on test-only stub owners can't match statically (C17).
  • The SSR compile passes a class type parameter as a value (I16): worked around, see Server compile traps.
  • UIRuntime's docstring claims it constructs outside a browser; it doesn't (I2).
  • The client cost of the server-only methods was never measured (T32).
