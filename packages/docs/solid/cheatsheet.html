Solid 2 Cheat Sheet

What's new or different in Solid 2, one card per feature.

  • measured against Solid 1 and against the React habits this repo is moving off
  • spell notes are where our own experiments found more than the docs say

2.0.0-rc.13, researched on rc.11 (what @spell-app/ui pins): same behaviour on both; the docs at v2.solidjs.com track rc.13.

  • why spell is built the way it is: Spell on Solid 2
  • the measurements behind the spell notes: solid/experiments/

No card matches.

Packages

New package graph changed 

import { createSignal, createStore, For, Loading } from "solid-js"
import { render, Portal, dynamic } from "@solidjs/web"
  • the reactive core is @solidjs/signals; solid-js re-exports it and holds stores too
  • solid-js/web → @solidjs/web; solid-js/store → solid-js
  • solid-js/h, /html, /universal → @solidjs/h, @solidjs/html, @solidjs/universal

JSX config changed

// tsconfig.json
"jsx": "preserve",
"jsxImportSource": "@solidjs/web"
  • solid-js no longer ships JSX types; the renderer does
  • augment custom elements on "@solidjs/web/types/jsx.js"
  • augmenting "@solidjs/web" itself fails: it only re-exports JSX

Vite plugin new

import solid from "@solidjs/vite-plugin"   // was vite-plugin-solid
plugins: [standardDecorators(), solid()]
  • Rust / OXC compiler by default: 23× to 355× faster than the Babel preset
  • our decorator pre-pass must run first
  • the Solid compiler has to see decorator-free code

Exactly one Solid per page

  • scheduler, delegated events, context and element definitions are all module state
  • two copies means two graphs that can't see each other
resolve: { dedupe: ["solid-js", "@solidjs/web"] }
Solid and @spell-app/ui go in spell-shared.js, never in spell-runtime.js. Compiled spell never imports Solid directly.

Write timing and scheduling

Writes are staged changed 

setCount(1)
count()    // still 0
flush()
count()    // 1
  • every write waits for the next microtask, or flush()
  • the price of "the UI never shows half an update"
  • holds everywhere
    • top level
    • event handlers
    • untrack
    • even inside flush(() => { set(); read() }): drains only when the callback returns
  • hence spell cells

flush() / flush(fn) new 

flush()                     // drain queued updates now
flush(() => setCount(6))    // run fn, drain as it returns
flush(() => { a(); flush(() => b()) })   // nested drains
  • never inside an action body: FLUSH_IN_ACTION
  • not in an effect's apply function or onSettled: a warning, and nothing to drain -- writes made there are already visible
  • it doesn't wait for async work; use await resolve(() => x())
Measured: about 0.7 µs per flush on a small queue. In a memo's compute it drains, on rc.11 and rc.13 (a downstream memo updates too).

batch() is gone removed

  • everything batches by default
  • several writes before a flush coalesce into one recompute per dependant

No writes in owned scope new 

createMemo(() => { setX(1) })   // dev: REACTIVE_WRITE_IN_OWNED_SCOPE
createSignal(0, { ownedWrite: true })   // opt in, narrowly
runWithOwner(null, () => setX(1))      // also escapes
  • applies in
    • component bodies
    • memos
    • effect computes
    • even a createRoot body
  • untrack does NOT exempt a write: the guard is owner-based
  • dev-only; prod doesn't check

Peek at a staged value

setX(5)
setX(p => { seen = p; return p })   // seen === 5
  • updater receives the latest staged value
  • documented behaviour, but not a read API: it's still a write

Signals and memos

Writable memo new

const [value, setValue] = createSignal(() => props.initial)
  • derived value you can also overwrite
  • resets when its inputs change
  • replaces "copy prop into state on change" and createComputed

Signal options new

createSignal(v, {
  equals: false,               // notify on every write
  ownedWrite: true,            // allow writes in owned scope
  unobserved: () => stop(),    // last subscriber left
  name: "count"                // dev / devtools
})

Memo options new

createMemo(fn, {
  lazy: true,         // compute on first read;  autodispose when unobserved
  equals: (a, b) => a.id === b.id,
  sync: true,         // promise it never returns a Promise
  loadingValue: null, // "commit #0" shown while the first async answer loads
  unobserved: () => {}
})

Memos are eager by default: they compute on creation. initialValue is gone; the compute gets prev.

  • an unowned eager memo recomputes on every relevant flush forever, even with no readers
  • a lazy memo read from untracked code recomputes every time
  • a memo read before flush() is stale, lazy ones included

getObserver() renamed 

function trackIfTracked(src) { if (getObserver()) src() }

Was getListener. It's null at top level and in a root body, and set inside memos, effect computes and JSX expressions.

enableExternalSource new 

enableExternalSource({
  factory(fn, trigger) { return { track(prev) {...}, dispose() {...} } },
  untrack(fn) {...}
})

Lets Solid computations track a non-Solid reactive system, such as MobX or Vue. It's global, and registrations chain.

This is how spell cells tell Solid about changes. Register it once, in the shared chunk.

isEqual, untrack

isEqual replaces equalFn. untrack(fn) stops tracking, not owning.

Effects and lifecycle

Split effects changed

createEffect(
  () => count(),               // compute:  tracks
  (value, prev) => {           // apply:  untracked side effects
    el.title = value
    return () => {}            // optional cleanup
  },
  { defer: true }              // skip the first run
)
  • the single-argument form is an error
  • every compute runs before any apply
  • replaces on(...) and onCleanup-in-effect
  • the apply's return value IS the cleanup
  • v => list.push(v) returns a number that Solid then calls, and that halts the whole page
  • always use braces

Error-handling effect new 

createEffect(() => load(id()), {
  effect: (data) => show(data),
  error: (err, cleanup) => report(err)
})

Catches compute-phase errors only; a throw in the effect phase isn't routed here.

onSettled new

onSettled(() => {
  const id = setInterval(tick, 1000)
  return () => clearInterval(id)
})
  • replaces onMount + onCleanup for component setup and teardown
  • also works in event handlers ("after this change settles")
  • never sees its own write

Render effect, reaction, tracked effect

createRenderEffect(() => props.t, v => { el.title = v })  // renderer plumbing
const track = createReaction(() => onChange())           // one-shot, re-arm
track(() => count())

createTrackedEffect: the docs site marks it deprecated; rc.13's types don't.

An uncaught error halts everything

  • a computation error with no boundary stops the scheduler page-wide (REACTIVITY_HALTED)
  • every later update is ignored
  • recover with resetErrorHalt()
  • better, don't let it escape:
    • <Errored>
    • effect error

Owners and roots changed

createRoot(dispose => { ...; dispose() })   // owned by its parent by default
runWithOwner(null, () => createRoot(...))  // detach (module singletons)

An effect with no owner warns NO_OWNER_EFFECT; it's never disposed.

Async lives in the graph

Async memo new

const user = createMemo(() => fetchUser(props.id))
<Loading fallback={<Skeleton />}>
  <h1>{user().name}</h1>
</Loading>
  • any memo may return a Promise or an async iterable
  • user() is a User, never undefined
  • replaces createResource
  • passing isn't reading: only the expression that reads the value waits

Held writes = built-in transitions new

  • once content has shown, a write feeding pending async is held
  • old content stays until the new answer lands
  • every other write in the same batch is held with it
  • startTransition is gone
Measured: a hold happens only when a render effect reads the async value with no <Loading> to catch it. Writes in later batches go through.

isPending / latest new 

<ul class={{ stale: isPending(() => results()) }}>
<List selected={latest(selectedId)} />   // value being worked toward

These are questions, not state. isPending is true only while a change is in flight, not for every fetch.

latest() does NOT see a plain synchronous write before flush; it only sees values held for async work.

refresh, affects, resolve new 

refresh(user)              // re-ask quietly;  isPending stays false
affects(user); refresh(user)   // re-ask AND read as pending
const v = await resolve(() => user())   // tests / imperative code

Boundaries renamed

<Loading fallback={...} on={id()}>...</Loading>   // was Suspense
<Errored fallback={(err, reset) => ...}>...</Errored>   // was ErrorBoundary
<Reveal order="sequential" collapsed>...</Reveal>   // was SuspenseList
  • Loading covers only the first load; revalidation keeps content visible
  • on is a dependency list, not a key
  • Errored heals by itself when the data underneath recovers
  • reset retries the data, not the UI

NotReadyError

  • reading a not-ready value throws it; the graph catches it and retries
  • you'll never see one unless you write a primitive: throw new NotReadyError()

Actions and optimistic state

action new

const add = action(function* (todo) {
  setTodos(s => { s.push(todo) })  // optimistic
  yield api.add(todo)                // async work
  refresh(todos)                     // reconcile with truth
})

A generator, so the transaction survives across yield; JavaScript has no async context yet. Its writes are held until the action settles.

Optimistic overlays new

const [todos, setTodos] = createOptimisticStore(() => api.list(), [])
const [saving, setSaving] = createOptimistic(false)   // "saving…" flag
  • optimistic writes are a layer over the confirmed value
  • dropped when the transaction settles, pass or fail
  • there's no rollback code
  • if the prediction matches the result, nothing re-runs

Stores

Draft-first setters changed 

const [store, setStore] = createStore({ user: { name: "A" }, list: [] })
setStore(s => { s.user.name = "B"; s.list.push("x") })
setStore(s => s.list.filter(x => x !== "x"))  // return = shallow replace

produce is gone because it's now the default. Store writes follow the same staged timing as signals.

No mutable store removed

store.a = 2   // silently IGNORED:  no throw, no warning

createMutable and modifyMutable are gone.

The editor's editor.x = y would quietly break. It moves onto spell cells instead.

Derived stores new

const items = createProjection(async () => api.list(), [], { key: "id" })
const [cache, setCache] = createStore(d => { d.x = compute() }, { x: 0 })
setStore(s => { reconcile(serverTodos, "id")(s.todos) })

Replaces createSelector and write-back patterns. Only the rows whose value changed update.

snapshot, deep, storePath

JSON.stringify(snapshot(store))    // was unwrap:  plain, untracked
createEffect(() => deep(store), save)   // track every nested change
setStore(storePath("user", "city", "Paris"))   // 1.x path-setter compat

What gets wrapped

  • plain objects, arrays and class instances are wrapped in proxies
  • Map, Date and frozen objects are stored raw
  • tracking is per property, created on first tracked read
  • { shallow: true } means records are replaced, never edited
Never put Things in a store: the proxy fails === against the raw instance.

Control flow

One <For>, three keyings changed 

<For each={items()}>{(item, i) => ...}</For>          // by identity:  item value, i accessor
<For each={items()} keyed={false}>{(item, i) => ...}  // by position:  item accessor, i number
<For each={items()} keyed={t => t.id}>{item => ...}   // by key:  item accessor

Index is gone. The callback body is an owner, not a tracking scope: read accessors in JSX or a memo.

<Repeat> new

<Repeat count={rows.length} from={first()} fallback={<Empty />}>
  {i => <Row data={rows[i]} />}
</Repeat>

Renders by count with no diffing, and i is a number. It's the building block for windowing and virtualization.

Narrowing Show / Match

<Show when={user()} fallback={<Login />}>{u => <Profile user={u()} />}</Show>
<Show when={user()} keyed>{u => ...}</Show>   // raw value;  remount on change

dynamic() new

const Active = dynamic(() => editing() ? Editor : Viewer)   // create once
return <Active value={value()} />

<Dynamic component> still exists as a convenience; the factory is canonical.

Components, props, context

Components run once

  • there's no re-render
  • the compiler turns each dynamic prop into a getter (get quantity() { return quantity() }), so the read happens where the child uses it
  • a component body is untracked
<Counter value={count()} />   // pass the VALUE
function Counter(props) { return <div>{props.value}</div> }   // read via props.x

Destructuring props freezes them (STRICT_READ_UNTRACKED).

merge / omit renamed 

const all = merge(defaults, props)       // was mergeProps
const rest = omit(props, "class", "ref")  // was splitProps

undefined is a real value in merge: it overrides.

Context is its own provider changed 

const Todos = createContext<TodosCtx>()       // no default:  missing provider throws
<Todos value={createTodos()}><List /></Todos>   // no .Provider
const Theme = createContext<"light" | "dark">("light")   // default:  primitives only

children(), lazy

const list = children(() => props.children); list.toArray()
const Heavy = lazy(() => import("./Heavy"))   // inside <Loading>;  Heavy.preload()

DOM

render() per root

const dispose = render(() => <App />, el)   // pass a FUNCTION
dispose()   // removes DOM, disposes the root and its delegated listeners
  • event delegation is scoped to each render root; clearDelegatedEvents is gone
  • a ShadowRoot works as a container (verified in rc.11 and rc.13 source, "needs integration testing" in the docs)

Refs and directive factories changed 

<button ref={el => (btn = el)} />
<input ref={autofocus} />
<button ref={[autofocus, tooltip({ content: "Save" })]} />   // compose
  • use: is gone, and so is .current or forwardRef: a component gets props.ref
  • ref callbacks run unowned, so create effects in the factory, not in the callback

class objects and arrays changed 

<li class={["todo", props.class, { done: done(), error: !!err() }]} />
  • classList is gone
  • don't concatenate class strings
  • React's className is class
  • style keys are kebab-case, and numbers get no unit

Attributes are HTML again changed 

<video muted={false} />       // boolean = presence / absence
<div tabindex="0" />          // lowercase built-in names

attr: and bool: are gone.

Custom elements: attributes by default

<ui-dropdown value="a" prop:options={opts()} />
  • on a tag with a dash, a plain name is a string attribute, and objects get stringified
  • prop:x assigns a property
  • the server emits attributes and skips prop:
spellCore.element() routes non-primitive values on ui-* tags to prop: for you.

Events changed

<button onClick={e => go(e)} />       // camelCase;  delegated per root
<button ref={on("click", fn, { capture: true })} />   // native options
const on = (t, fn, o) => el => el.addEventListener(t, fn, o)
  • on: and oncapture: are gone
  • the binding expression is not reactive: onClick={c() ? a : b} picks once
  • onChange is the native change event; use onInput per keystroke

Custom events with a dash

  • onDatechange listens for datechange, lower-casing everything after on
  • so onUiChange listens for uichange, not ui-change
  • use a ref directive with the exact name
  • a custom element dispatching a delegated name (click...) needs bubbles: true, composed: true
In hyperscript, the key "onui-change" works (rc.11 and rc.13 source), but it's undocumented. spellCore.element() maps spell's spelling explicitly.

Portal

<Portal mount={shadowRoot}><Modal /></Portal>
  • defaults to document.body
  • inside a shadow root always pass mount, or content and styles escape
  • throws on the server

Hyperscript (@solidjs/h): no compiler

Functions are the only reactivity

h("div", { id: () => props.id, class: "row" },
  () => first() + " " + last(),
  h(Child, { name: () => name() }))
  • a function prop or child is reactive, and anything else is static
  • h() returns a thunk; pass () => h(App) to render
  • fragments are arrays
  • refs must be callbacks
  • spreads need merge()

The arity trap

h(Comp, { onPick: () => go() })   // ✗ becomes a GETTER:  passes go()'s result
h(Comp, { onPick: e => go() })    // ✓ arity ≥ 1 = callback

This is for component props only; element on* props and ref are exempt. It applies to render props too, e.g. <For> children.

Cost and wiring

  • "the least efficient way to use Solid": not tree-shakeable, with no static analysis
  • @solidjs/html is slightly better
  • h.js imports @solidjs/web by bare specifier, so it must resolve to the page's single copy
Keep h inside bundled spellCore; compiled spell imports only @spell/core.

Tooling and ecosystem

Start mode, server functions new 

solid({ start: true, ssr: true })   // SolidStart is retired
export async function add(t) { "use server"; await db.insert(t) }
  • GET(...), respond(v, { headers }) and live(async function* ...) are in @solidjs/web/server-functions
  • none of this is on our path; noted so it isn't mistaken for ours

Router 2 new

// @solidjs/router@next  (2.0.0-next.32)
export const Router = createRouter({ routes: [{ path: "/", component: Home }] })
const navigate = useNavigate(); navigate(Router.paths.home())

Typed routes and one createRouter; not Solid 1's <Route> tree.

Testing

fireEvent.click(btn); flush(); expect(...)     // flush before asserting
import { render } from "@solidjs/testing-library"   // @next = 1.0.0-beta.3
  • under Node, @solidjs/web resolves to the server build, with no DOM render
  • component tests need the browser + development conditions plus jsdom or browser mode
  • an SSR test project needs its own solid() instance

Diagnostics tooling

  • import solid-js/attribution and call attribution.enable() for costs and feedback (relay / tear reports only appear after that)
  • @solidjs/web/performance-tracks paints the Chrome Performance panel
  • name: options label nodes

Dev diagnostic codes
Code Means Fix
REACTIVE_WRITE_IN_OWNED_SCOPE write in a component, memo, effect compute or root body move it to a handler or onSettled; ownedWrite
STRICT_READ_UNTRACKED reactive read in a component body or flow callback body read in JSX or a memo; don't destructure props
REACTIVITY_HALTED an uncaught computation error stopped the scheduler <Errored>, effect error; resetErrorHalt()
NO_OWNER_EFFECT effect created outside any owner, so never disposed create it inside a component or createRoot
FLUSH_IN_ACTION flush() inside an action body drop it; the action commits on settle
FLUSH_IN_EFFECT_CALLBACK flush() in an effect apply or onSettled drop it; writes continue in the same flush
UNSTABLE_LIST_IDENTITY .map() in JSX, or fresh objects per update <For>, keyed by id
IMMUTABLE_UPDATE_IN_STORE setter returned a rebuilt object mutate the draft
LOADING_ON_OUTSIDE_HOLD <Loading on> data also read outside it move the read under the boundary
ContextNotFoundError useContext with no default and no provider add the provider, or a primitive default
