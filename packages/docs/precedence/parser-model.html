Each fork: the options side by side, one recommended, favouring fewer things to know.

A. A named bounded rule (recommended)
  • the slot names what it takes: {list:single_expression}, {expression:arithmetic_expression}, {expression}
  • spell needs exactly three bounds (below); each is a rule you can read
  • no plumbing; completion's memo works as is (it keys on the rule's name)
  • ~8 lines, spell only
 B. The design doc's {x:operand}
  • "an expression bounded by MY bindingPower": the bound is implicit
  • travels as a module flag set by Sequence; every full slot must reset it
  • memo key must include the bound, or completion replays the wrong parse
  • ~14-20 lines in core; readers of Sequence and Subrule must know

expressions.ts · compound_expression becomes the expression loop · 36 lines 
/**
 * `expression`:  a single expression, then each operator suffix binding TIGHTER than `bound`, e.g. `x + 1 is 3`.
 * - The only rule registered as `expression`:  every other `expression` alias is a `single_expression`, see `getNamesForRule()`.
 * - No suffix => the single expression's own match, as is, so `match.is(known_variable)` still works on `{thing:expression}`.
 * - Suffixes' rhs is a `single_expression`, so the chain is flat:  `getAST()` groups it by `bindingPower` (shunting-yard).
 */
export class compound_expression extends SpellExpression {
  static ruleName = "expression"
  @proto static alias: string | string[] = []
  /** Suffixes must bind tighter than this to be ours:  0 takes all, see `arithmetic_expression`. */
  @proto static bound = 0

  parse(scope: P.Scope, tokens: P.Token[]): P.Match | undefined {
    const lhs = this.rules[0]!.parse(scope, tokens)
    if (!lhs) return undefined
    const chain = this.rules[1] as P.Repeat
    const suffixes: P.Match[] = []
    let rest = tokens.slice(lhs.length)
    while (rest.length) {
      const suffix = chain.rule.parse(scope, rest)
      if (!suffix || bindingPowerOf(suffix) <= this.bound) break
      suffixes.push(suffix)
      rest = rest.slice(suffix.length)
    }
    // completion:  an operator after us only EXTENDS us
    if (!rest.length) P.Expectations.current?.expect(chain, this, 1, true)
    if (!suffixes.length) {
      lhs.matchGroup = this.name
      return lhs
    }
    const matched = [lhs, ...suffixes]
    return new P.Match({ rule: this, matched, tokens: matched.flatMap((it) => it.tokens), scope })
  }
}

/** Apply every stacked operator binding at least as tightly as `power`. */
function reduceWhile(power: number) {
  for (let top = opStack.at(-1); top && bindingPowerOf(top.match) >= power; top = opStack.at(-1)) {
    const op = opStack.pop()!
    const rhs = output.pop()
    output.push(applyOperatorToRule({ ...op, rhs, lhs: output.pop() }))
  }
}

/** `expression` with arithmetic suffixes only, e.g. `x + 1` in `the absolute value of x + 1 is 3`. */
class arithmetic_expression extends compound_expression {
  static ruleName = "arithmetic_expression"
  @proto static bound = BP.takesSum // 12:  `+ - * /` yes, `is` no
}

// SpellParser
/**
 * Every rule aliased `expression` is registered as a `single_expression` instead -- except `expression` itself.
 * - So `{expression}` is a whole expression, operators and all;  `{single_expression}` is one operand without them.
 */
protected getNamesForRule(rule: P.Rule, names: string[]): string[] {
  if (rule.name === "expression") return names
  return names.map((name) => (name === "expression" ? "single_expression" : name))
}
 Sequence.ts · give-back, the one change in packages/parser · 26 lines 
/**
 * Our `index`th rule, a word, failed because the slot before it took it, e.g. `of` in `remove the card of
 *   the pile` for `remove {thisArg:expression} of {callArgs:expression}`:  re-parse that slot on tokens ending
 *   just before each place the word is, LAST first, and go on from there.
 * - Only on the way to failing:  whatever parses today parses the same.
 * - NOT in expecting mode:  a cut-short slot would record that it ran out of tokens.
 */
private giveBack(scope: P.Scope, tokens: P.Token[], index: number, start: number, matched: P.Match[]) {
  const word = this.rules[index]!
  const slot = this.rules[index - 1]!
  const taken = matched.at(-1)
  if (!taken || P.Expectations.current || !isWord(word) || isWord(slot)) return undefined
  const slotStart = start - taken.length
  for (let cut = taken.length - 1; cut > 0; cut--) {
    if (!word.test(scope, tokens, slotStart + cut)) continue
    const shorter = slot.parse(scope, tokens.slice(slotStart, slotStart + cut))
    if (shorter?.length !== cut) continue
    const rest = this.parseFrom(scope, tokens, index, slotStart + cut, [...matched.slice(0, -1), shorter])
    if (rest) return rest
  }
  return undefined
}

/**
 * How tightly each operator suffix binds:  read ONLY by `compound_expression`'s shunting-yard.
 * - Not `precedence`, which only says which of several matches of the SAME words wins.
 * - A new level is a new name here, with a why.
 */
export const BP = {
  ternary: 4, // `X if C otherwise Y`
  or: 5,
  and: 6,
  equality: 10, // `is`, `is exactly`
  comparison: 11, // `<`, `is a`, `includes`, `is empty`, quoted aliases ...
  takesSum: 12, // the bound of `arithmetic_expression`
  sum: 13, // `+ -`
  product: 14 // `* /`
}

## Adding an expression rule

- A TERM stands alone:  a literal, `the X of Y`, `the first card of …`.  `extends SpellExpression` (alias
  `expression`, registered as `single_expression`).
  - A slot at its END takes `{name:single_expression}`:  `the first card of {list:single_expression}` stops before any operator.
  - Math that should take a sum (`the absolute value of x + 1`):  `{name:arithmetic_expression}`.
  - A slot closed by a required word (`of`, `in`, `to`) stays `{name:expression}`, like a paren.
- An OPERATOR follows an expression:  `extends InfixOperatorSuffix` (`x OP y`) or `PostfixOperatorSuffix`
  (`x is empty`).  Its right side is `{expression:single_expression}`.  MUST set `bindingPower` from `BP`
  (registration throws without it);  build output in `compileASTExpression()`.
- `precedence` only settles a tie between rules matching the SAME words.  Leave it unset unless a probe shows a
  tie going wrong;  then set it, with a one-line why.
- Always NAME a slot, so `match.groups` keeps its key.  Add one mixed-operator line to the probe ledger.
  • Completion. Today the expression Choice marks x as "may continue" when an operator could follow. That Choice is gone, so the loop records it itself (sketched in §4.5); otherwise the language server's "incomplete statement" check breaks. Expectations.test.ts pins today's record.
  • Left recursion. Only isLeftRecursive guards a single expression starting with {expression} today. After: a 5-line check at registration.
  • Incremental parsing and the journal. P3 keeps parsing pure: nothing new to journal. P4-P6 add scope records and mutate some (a method's return type, exclusive): those go through the journal like claim(); first datatype wins, no widening.
  • Return types. commitStatement() runs mutateScope() BEFORE a body parses, so return inference needs a post-body hook, and a body edit that changes the return type must re-parse what follows.
  • Declarations. New keys (params, returns, itemType, exclusive, auto); SPELL_VERSION 0.8.0 → 0.9.0; regenerate the cards library; a loader shim for rule: "enumeration".
  • Speed. Baseline (P1): speedTest() 74ms, BENCH 115ms. Expect better after P3 (no double parse); give-back adds parses only to sequences already failing.
