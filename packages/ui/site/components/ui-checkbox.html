An invisible checkbox has no box: the label itself is the control, bordered while unchosen and tinted when chosen. Its content can be any markup.

Not ported: styling the label as another component (Fomantic's label class="ui purple button", ui orange message, ui teal segment) and compact invisible -- the label is in the shadow root, so it can't take another component's classes.

A checkbox can be checked. selected is the canonical name; checked is accepted as an alias, as on a native checkbox.

A checkbox can be indeterminate: neither on nor off. A click clears it, as natively.

The indeterminate state can be used to represent a value that is neither checked or unchecked. This can be useful with groups where a "master" checkbox should display the selections of several other checkboxes.

The wiring (children set the master, the master sets the children) is a few lines on ui-change: see "Grouped checkboxes" on the Usage tab. Here the states are set in markup. Fruits Apple Orange Pear Vegetables Lettuce Carrot Spinach

A disabled checkbox can't be used at all; a read-only one shows its state but can't change it.

Not ported: Fomantic's uncheckable: false setting (check once, never uncheck) -- veto the change in a ui-change listener instead (Usage tab, "Vetoing a change").
