<Section title="Behaviour">
  A `<ui-toast>` shows where it is, like any element, and stays until closed unless it has a `display-time`
  (milliseconds, or `auto`:  about as long as it takes to read).  `UI.toast()` builds one for you in a container per
  `position` (`top right` by default;  `top left`, `bottom center`, `centered` ...), in the top layer, and removes it
  once it has closed.  It returns `{ id, closed, element }`:  `closed` resolves when the toast is gone, and
  `UI.toasts.dismiss(id)` closes it early.

  What closes a toast:  the countdown, the close icon, a click on it (`close-on-click`, off with a close icon, actions
  or form controls inside), Escape while focus is inside, an action, or `host.close()`.  Each goes through the
  cancelable `ui-close` (`detail.reason`), then the exit animation, then `hidden` on the host and `ui-hide`.
  `ui-show` fires once it has appeared.

  A native `<button commandfor="id" command="--close">` closes a toast in the page with no script, the same way the
  close icon does (`detail.reason` is `close`).  Only `--close`:  a closed toast stays closed (`hidden`, never
  removed), so there is nothing for `--show` or `--toggle` to bring back;  insert a new toast instead.

  <Example title="Invoker command" description="`command=--close` dismisses the toast named by `commandfor`.">
    <ui-toast id="toast-invoker" message="Saved your changes" icon="" closable=""></ui-toast>
    <button type="button" class="ui button" commandfor="toast-invoker" command="--close">Dismiss it</button>
  </Example>

  The countdown pauses while the pointer is over the toast (`pause-on-hover`) and always while focus is inside it.
  `progress="top"` or `"bottom"` shows it as a bar (`showProgress` in `UI.toast()`), which keeps running under reduced
  motion:  it tells time, it isn't decoration.

```js
const toast = UI.toast({ message: "Moved to archive", displayTime: 5000, actions: [{ text: "Undo", click: undo }] })
await toast.closed // gone:  countdown, click, action ...

document.querySelector("#saved").addEventListener("ui-close", (event) => {
  if (event.detail.reason === "timeout" && stillSaving) event.preventDefault() // keep it up
})
```

  Actions go in the `actions` slot (`actions` in `UI.toast()`).  Fomantic's approve / deny classes and
  `<ui-button positive>` / `<ui-button negative>` fire the cancelable `ui-approve` / `ui-deny`;  any action closes the
  toast unless its click was `preventDefault()`ed (a `click` that returns `false`, in `UI.toast()`).

<Section title="Theming">
Theme with the public `--ui-toast-*` tokens:  set one on the element, on any ancestor (`:root` for every toast), or
  on the box through `::part(box)`.  `--ui-toast-width` applies on screens wider than a phone;
  phones (up to 420px) use `--ui-toast-mobile-width`.  `--ui-toast-container-distance` goes on `:root`:  the
  containers are page-level.  For `UI.toast()`'s toasts, set the rest on `:root` too.  Style the pieces with
  `::part()`:  `box` (around the toast, its bar and attached actions), `toast`, `icon`, `content`, `header`,
  `message`, `close`, `actions`, `progress` and `bar`.

```css
:root {
  --ui-toast-radius: 0.75em;
}
ui-toast::part(bar) {
  background: var(--ui-primary);
}
```

<Section title="Accessibility">
  - A toast is a `role="status"` live region, so it's announced without moving focus;  `type="error"` makes it a
    `role="alert"`, announced at once.
  - A toast never takes focus.  Tab reaches its close icon and actions;  focus inside pauses the countdown, and
    Escape closes it.
  - Keep toasts for news that can be missed.  Anything the user must act on belongs in a
    [modal](../ui-modal/) or on the page:  a toast with `displayTime: 0` and actions is a compromise.
  - The toast containers of `UI.toast()` are `region` landmarks named "Notifications" (translated).
  - KNOWN LIMIT:  while a modal `<dialog>` is open, everything outside it is inert, toast containers included.  A
    toast shown then still counts down, but can't be clicked, focused or announced.

  | Key               | Action                                           |
  | ----------------- | ------------------------------------------------ |
  | Tab               | Reach the close icon and the actions             |
  | Escape            | Close the toast (focus inside it)                |

  - If the element can't render, its native fallback still shows the message, is still announced, and its close
    button and a numeric `display-time` still close it.
</Section>

<Section title="Framework usage">
  Most apps call `UI.toast()` from an event handler.  A `<ui-toast>` in a template is an ordinary element:  listen for
  `ui-hide` to drop it from your state.

```jsx
// React 19
{saved && <ui-toast type="success" message="Saved" display-time="3000" onui-hide={() => setSaved(false)} />}
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-toast v-if="saved" type="success" message="Saved" display-time="3000" @ui-hide="saved = false" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<Show when={saved()}>
  <ui-toast type="success" message="Saved" display-time="3000" ref={(el) => el.addEventListener("ui-hide", () => setSaved(false))} />
</Show>
```

</Section>
