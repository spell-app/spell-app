<epic-code> The <epic-code> element: a folded, highlighted code block in a plan doc's prose.

A folded, highlighted code block in prose. It draws a code-well panel headed by its title, and the code inside, coloured, with a copy button; the code itself is the doc's own <pre>.

For anyone reading or writing a plan doc's markup, or changing this element.
Its vocabulary (every name it uses): EpicCode.en.ts.
Its component: EpicCode.tsx, with its style sheet (.css) and tests beside it.

Two real ones: the first starts open (open, epic ui-docs-rework, J6); the second starts folded (epic wwod-spell-ui, J44).

Its parents:

  • Anywhere prose goes: it's a prose element:
    • <epic-item>: among an item's own text, before its cards
    • <epic-answer>, <epic-more>, <epic-reply>: the cards under an item
    • <epic-option>: an option card's pros and cons
    • <epic-field>: a phase's field, or a labelled block
    • <epic-updated>: a change to a phase's plan
    • <epic-section>: an Overview sub-section's prose, or a report's
    • <epic-version>: an earlier version, kept as it was
    • another prose element (a note inside an aside), or plain HTML around it (a <li>, a <div>)

Its children:

  • ONE <pre> holding the code as text. A <pre>, so a formatter keeps its white space, and the page shows the code before the pack loads.

The <pre> is never shown once the element draws: <ui-code> in its drawing shows the code, so it appears once. It follows its <pre> live: an edit to the file redraws it.

Name Values Meaning Required

language as <ui-code language> takes it: ts, html, css, json, spell, text for none The code's language, for its colours. None: guessed. no

A slot is where the element's own children show.

Slot Holds
(default) The code: ONE <pre>, its text the code (never drawn itself).

A part is a piece of the drawing a page's CSS can reach.

Part Is
base The panel.
toggle Its heading, a <button> that folds it: the chevron, then heading.
heading The heading's words.
body What it folds; hidden (until-found) while folded.
code The <ui-code> that draws the code, highlighted, with its copy button.

A state is set by the element on itself; none is ever written in the doc.

State When
open Unfolded: the reader opened it, or it started so.
  • The brand's code well, as the docs' code blocks (ui-accordion.spell-code): a frame with a hairline, its heading small, mono and muted, the code on a card inside.
  • Coloured by its language (else guessed), with a copy button: Spell UI's <ui-code>.
  • A long listing scrolls inside itself (at most 70% of the window's height); a wide one scrolls sideways. Never the page.
  • Folded to start with, unless open. A click on the heading, or find-in-page, unfolds it.
  • No state colour. It shares its shape with <epic-aside> (EpicPanel).
  • Claude writes it inside the HTML it passes to spell dev plan-doc (add ... --details, decide --details, details --file, updated): no command makes one by itself. Code in a plan doc is ALWAYS one of these (plan-doc.md, "Prose").
  • The plan-doc tool turns the OLD hand-shaped markup into this element, so a doc never holds the old shape.
    • It does this in any HTML a command takes: add --details, decide --details, details --file, updated.
    • The code that does it: IncomingHtml and ProseRewrite.
    • Prose edited by hand in a part file isn't passed through it.
    • The old shape: ui-accordion.spell-code (and its four wrappers).
  • The converter did the same to every converted doc, keeping title, language and open (ProseUpgrader).
  • On a details page it goes as plain prose: its title over its <pre> (PlanItem.asProse()).
