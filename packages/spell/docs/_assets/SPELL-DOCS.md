# `.spell.html` docs:  built from @spell/ui widgets

How `yarn docs:update` turns the hand-written HTML docs into `.spell.html` pages rendered with @spell/ui.  Rules for
writing docs:  "Creating docs" in AGENTS.md.  Scripts are the truth where this drifts.

Repo:  /Users/owen/www/spell/parser (called PARSER).  Sister repo:  /Users/owen/www/spell/ui (called UI, package
`@spell/ui`, Fomantic UI vocabulary as `ui-*` custom elements on Solid 2 rc.11).  UI is UNFINISHED:  this pipeline is
also a test of it.  NEVER edit files in UI from here;  work around a UI problem in PARSER when reasonable, and record
it in `docs/SPELL-UI-FINDINGS.md`.

## Goal

Today PARSER's HTML docs (`docs/solid/SOLID-2.html`, `docs/solid/CHEATSHEET.html`) are hand-written semantic HTML
styled by `docs/_assets/doc.css` / `doc.js`.  They stay as the SOURCE (untouched).  A new task, `yarn docs:update`,
re-creates `<name>.spell.html` next to each source, rendered with @spell/ui widgets instead of hand-written CSS/JS,
using the LATEST UI (its current working tree).  Both must keep working:  the user compares them side by side.

## Hard constraints

- Docs are opened straight from disk (`file://`).  Browsers block ES module loading from `file://`, so the page
  loads ONE classic script `docs/_assets/spell-ui.js` (an IIFE bundle:  Solid + @spell/ui + the page runtime).  No
  `type="module"`, no `import()` at runtime, no fetches of sibling files.
- highlight.js stays:  `<script src="https://cdnjs.cloudflare.com/ajax/libs/highlight.js/11.9.0/highlight.min.js">`.
- Exactly ONE copy of Solid in the bundle (UI requires it).
- Generated files are regenerated, never hand-edited:  each starts with
  `<!-- GENERATED by yarn docs:update from <source>.html -- edit the source, not this file -->`.
- Code style for new scripts (PARSER's AGENTS.md):  2-space indent, no semicolons, double quotes, oxfmt-clean
  (`yarn oxfmt <file>`), terse docstring before each function saying WHY.  Node 22, ESM `.mjs`.

## Output page skeleton (`to-spell.mjs` writes, the runtime styles / drives, `check-spell.mjs` checks)

```html
<!doctype html>
<html lang="en">
  <!-- GENERATED by yarn docs:update from SOLID-2.html -- edit the source, not this file -->
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>{source title}</title>
    <meta name="description" content="{source description}" />
    <link rel="stylesheet" href="../_assets/spell-doc.css" />
  </head>
  <body class="spell-doc-page">
    <div class="spell-doc">
      <main class="spell-doc-main">{converted content}</main>
      <aside class="spell-doc-toc" id="spell-toc" aria-label="Contents">{contents, below}</aside>
    </div>
    <ui-button class="spell-toc-open" size="small">Contents</ui-button>
    <script src="https://cdnjs.cloudflare.com/ajax/libs/highlight.js/11.9.0/highlight.min.js"></script>
    <script src="../_assets/spell-ui.js"></script>
  </body>
</html>
```

(`../_assets/` is relative to the doc's folder;  compute it for other depths.)

## Content mapping (source -> output)

Sections and sticky headers.  The source's `<main>` is flat (h2 / h3 / h4 + content), or already wrapped in
`section.s2` / `section.s3` -- handle both.  Output:

```html
<section class="s2">
  <ui-sticky class="spell-h2"><h2 id="{same id}">{same inner HTML}</h2></ui-sticky>
  ...content...
  <section class="s3">
    <ui-sticky class="spell-h3"><h3 id="{same id}">...</h3></ui-sticky>
    ...content, h4s stay plain `<h4 id>`...
  </section>
</section>
```

- Keep every heading `id` EXACTLY (links from other files point at them).  Headings without ids get a slug id
  (same algorithm as `docs/_assets/doc.js` `slug()`).
- The runtime sets each h3 sticky's `offset` to the height of its section's h2 at runtime.

Other mappings:

| Source | Output |
|---|---|
| `div.callout` (+ `good` / `bad` / `warn` / none) | `<ui-message state="positive / negative / warning / info">`, inner content kept;  a FIRST child `<p><b>Title</b></p>` alone becomes `header="Title"` (strip a trailing `.`) |
| `div.table-wrap > table` | `<ui-table celled compact striped unstackable>` around the native `<table>`;  `td/th.num` += `right aligned`;  `td.yes` += `positive`, `td.no` += `negative`, `td.meh` += `warning` (keep the old classes too) |
| `span.tag` | `<ui-label size="mini">text</ui-label>` |
| `div.flow > div` (each `<b>Name</b>rest`) | `<ui-cards stackable>` of `<ui-card><ui-content><ui-header>Name</ui-header><ui-description>rest</ui-description></ui-content></ui-card>` |
| `<pre>` (bare or inside `details.code`) | `<ui-accordion class="spell-code" styled>` + `<ui-title>{summary text, or "TypeScript · N lines"}</ui-title><ui-content><pre>...unchanged...</pre></ui-content>`;  `open="0"` when the source `details` was `open` or the bare `<pre>` has <= 30 lines.  `<pre>` content byte-identical.  EXCEPT a `<pre>` inside a cheat-sheet card:  stays bare (no fold bar on snippets). |
| `details` (non-code) | `<ui-accordion styled>` + title / content pair |
| `p.lede`, `p.meta`, lists, links, `<code>`, `<b>` / `<em>` | unchanged (spell-doc.css styles them) |
| `a[target]` | unchanged:  href AND target kept |
| CHEATSHEET `section > .grid > .card` | `<ui-cards stackable>` of `<ui-card><ui-content>...card inner HTML...</ui-content></ui-card>`;  the card's `<h3>` stays a native `<h3 id>` inside |
| CHEATSHEET `.spell` note div | `<ui-message state="warning" size="small">` |
| CHEATSHEET `.bar` (filter input + nav) | `<div class="spell-filter"><ui-input icon="search" placeholder="{same}" data-spell-filter></ui-input></div>`;  the nav links go (the contents sidebar replaces them) |
| source `<style>`, `<script>`, `<link>` to doc.css, doc.js | dropped (skeleton adds its own) |

## Contents sidebar markup (`to-spell.mjs` writes it statically from the headings;  the runtime drives it)

```html
<aside class="spell-doc-toc" id="spell-toc" aria-label="Contents">
  <ui-sticky offset="0">
    <div class="spell-toc-inner">
      <div class="spell-toc-head">
        <b>Contents</b>
        <ui-buttons size="mini" basic>
          <ui-button data-toc="expand">expand</ui-button>
          <ui-button data-toc="collapse">collapse</ui-button>
          <ui-button data-toc="code">code</ui-button>
        </ui-buttons>
      </div>
      <ui-accordion class="spell-toc" exclusive="no">
        <!-- one title / content pair per h2 -->
        <ui-title><a href="#h2id" data-target="h2id">2. Read-after-write ...</a></ui-title>
        <ui-content>
          <!-- runs of h3s WITHOUT h4 children:  one menu -->
          <ui-menu vertical text fluid>
            <ui-item href="#h3id" data-target="h3id">What Solid 2 actually does</ui-item>
          </ui-menu>
          <!-- an h3 WITH h4 children:  a nested accordion with ONE pair -->
          <ui-accordion exclusive="no">
            <ui-title><a href="#h3id" data-target="h3id">How spell cells work</a></ui-title>
            <ui-content>
              <ui-menu vertical text fluid>
                <ui-item href="#h4id" data-target="h4id">The parts</ui-item>
              </ui-menu>
            </ui-content>
          </ui-accordion>
          <!-- ...in document order -->
        </ui-content>
        <!-- an h2 with NO children:  a pair with an empty <ui-content></ui-content> -->
      </ui-accordion>
    </div>
  </ui-sticky>
</aside>
```

- Link text:  the heading's text without `.tag` badges, whitespace collapsed.
- Every link carries `data-target="{heading id}"`:  the runtime's scroll-follow uses it, `check-spell.mjs` counts them
  (count of `[data-target]` in `#spell-toc` === count of `main h2[id], main h3[id], main h4[id]`).

## Runtime behaviour (docs/_assets/spell-doc-runtime.js + spell-doc.css)

- Layout:  `.spell-doc` = content column (max ~880px) + ~300px contents column on wide screens;  the contents
  column scrolls on its own (`.spell-toc-inner`:  max-height 100vh, overflow auto).  Under 1100px:  the aside is a
  right drawer, `.spell-toc-open` toggles it (fixed bottom-right), clicking a contents link closes it.
- Sticky headers:  h2 sticks at 0 within its `section.s2`;  h3 sticks just below its section's h2 (set the h3
  `ui-sticky` `offset`, re-measured on resize);  headings get an opaque background and `scroll-margin-top` so
  anchors land below both.
- Scroll-follow:  the active heading's contents link gets highlighted (a `ui-item` -> `selected`;  a title's `<a>` ->
  class `active`), its ancestor accordion panels open;  panels the scroll opened close again when you move on,
  panels the USER opened stay open;  keep the active link visible inside the contents column.
- Buttons:  `expand` / `collapse` open / close every contents panel;  `code` folds / unfolds every
  `ui-accordion.spell-code`.
- CHEATSHEET:  `ui-input[data-spell-filter]` filters `ui-card`s by text (every word must match), hides sections with
  no visible card, remembers the filter in `localStorage` (try/catch).
- highlight.js:  `hljs.highlightAll()` if present;  token colors in spell-doc.css (light + dark), like doc.css's
  `--hl-*`.
- Light / dark:  follow UI's scheme (it follows the OS);  page colors from UI's `--ui-*` tokens where they exist.
- Wait for UI:  run after the elements are defined (`customElements.whenDefined` for the tags used, or `UI.load()`).
