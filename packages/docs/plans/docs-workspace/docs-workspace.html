    3. Overview

    What exists after this plan. Becomes durable docs in P6.

    3.1 Structure
    • packages/docs/ (@spell-app/docs): docs for every package (D1)
    • <topic>/<topic>.html + <topic>/experiments/: one folder per doc
    • templates/: durable, cheat sheet, plans/plan.html + plans/plan-doc.md
    • plans/<name>/<name>.html: one per /plan-doc session
    • index.html: lists written by yarn docs:index
    • _assets/: one classic bundle (Solid + @spell-app/ui + runtime), page and plan CSS

    3.2 How a page works
    • Opens from file://: no server, so ONE classic script, no ES modules.
    • Icons bundled at build time, UI.icons.register()ed; packs dropped, since they can't load from disk.
    • Runtime builds the contents sidebar from the headings at load (D3).

    3.3 A /plan-doc session
    1. Name check: reuse an existing doc or folder, or pick another name.
    2. Worktree <name>, then yarn plan-doc new + open.
    3. Plan mode; after approval, fill this doc from the plan (D4).
    4. Per phase: phase N active, work, record items as found, phase N done.
    5. End of phase: bullets + AskUserQuestion built from yarn plan-doc summary.
    6. Last phase, Doc Review: turn the plan doc into durable docs.
    Aside: why a script, not hand edits?

    Ids, icons, UPDATE markers and the "updated" stamp must agree across the phase list, the phase sections and the items. Agents editing by hand drift; the script also locks the file so parallel agents take turns.

    4. Caveats
    1. C1 A skill can't rename the session or VS Code tab: ask user to run /rename

    7. Decisions

    What was decided, and why. Settled: don't re-argue without new facts.

    1. D1 packages/docs workspace holds docs, tooling, experimentsdetails

      Own deps (playwright, esbuild, oxfmt, linkedom); top of the dependency chain, like cli. Experiments import any package through the # aliases.

    2. D2 All docs hand-authored ui-* HTML; the .html -> .spell.html converter retireddetails

      User deleted the 3 .html sources. to-spell.mjs, doc.css, doc.js gone.

    3. D3 Contents sidebar built at load from headings, never hand-written
    4. D4 /plan-doc uses real plan mode; plan doc filled after ExitPlanModedetails

      Plan mode only allows editing the harness plan file, so the doc can't be written during planning.

    5. D5 Chrome; AppleScript reuses one tab per doc
    6. D6 UPDATE marker: ui-message for prose, ui-label for items, class plan-update + data-phasedetails

      No <ui-alert> in @spell-app/ui. phase N done strips them.

    7. D7 Scripts .js, not .mjs; experiments keep their names
    8. D8 Style caveman lite; lists bulleted, or numbered when order matters
    9. D9 'Transgressions' read as digressions: collapsed ui-accordion.spell-aside
    10. D10 Reload the plan doc's tab at every stage change; 'phase' does it itself
    11. D11 Pages are plain .html; the docs root is index.html, so the browser opens it for the folder
