TypeExplorer The scopes a project parses in, as a tree, with the details of the one picked.

The "Type Explorer" tab of a runner's debug pane: everything a project's code declares, and all it can use, as a tree of scopes on the left, and the details of the one picked on the right. It's how you see what spell made of your code: its types, their properties and actions, and the javascript each became.

Written for: anyone changing the runners' debug pane, or reading its code Live: a real <spell-app>, its debug pane opened on this tab

Solitaire, its debug pane open on "Type Explorer": the pane under the game IS this component. In the "Scopes" tree, open Card.spell under Solitaire and click Card, to see its details beside it.

Live, from the app's element build, which this set's pages load: /element/spell.pack.js. The app package builds it with yarn build:element.

Each runner draws one in its debug pane. VS Code's runner gives it the most: the scopes the extension sends, and a way to save docstrings and refresh:

VSCodeRunner.tsx · the Type Explorer tab · 14 lines
  • tree is the tree of scopes: from the language server in VS Code, or from the project's scope pack in a <spell-app>, which needs no parser in the page.
  • A scope's details are asked for with loadDetails() the first time it's picked, and kept until a new tree comes.
  • The right side is a ScopeDetailsPane, made afresh for each scope picked.
  • It lists things as they're declared, with a marker for each heading they're under, or in alphabetical order: the buttons in its header switch.
  • What's picked and open is kept by each scope's path, so it stays put as new trees come in, after each run. state and onStateChange remember it, else it's kept in the browser.
  • readonly, as in a <spell-app>: docstrings can't be edited.
  • Each row of its tree is a TreeRow: its arrow opens and closes it, the rest picks it. The ThingExplorer's tree uses it too.
