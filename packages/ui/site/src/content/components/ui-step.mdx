<Section title="Behaviour">
  `<ui-steps>` is an ordered list and each `<ui-step>` one item of it.  Mark the current step `selected` (Fomantic's
  `active` also works), finished ones `completed` and unavailable ones `disabled`;  the steps never change these
  themselves, so the page moves `selected` along as the user progresses.  The title is `header`, not `title`, which
  every HTML element already uses for its tooltip.

  A step with `href` is a link;  a `link` step is a button whose `click` the page handles.  A `disabled` link or
  button step is never followed.  Steps stack one per row below 768px of the group's own width (992px with
  `stackable="tablet"`), not the window's, so a step group in a narrow panel stacks even on a wide screen;
  `unstackable` keeps the row.  Steps have no custom events.

```js
const steps = document.querySelector("ui-steps")
steps.addEventListener("click", (event) => {
  const step = event.target.closest("ui-step[link]")
  if (!step) return
  steps.querySelector("ui-step[selected]")?.removeAttribute("selected")
  step.setAttribute("selected", "")
})
```

<Section title="Theming">
  Theme with the public `--ui-step-*` and `--ui-steps-*` tokens:  set one on the element, on any ancestor (a region,
  `:root`), or on the group's box through `::part(steps)`.  Every step in the group reads them from the group, so set
  them there or above, not on one step.  The content's look tokens (`--ui-step-content-padding`,
  `--ui-step-description-distance` ...) also work on one step.  Style one step's box with `ui-step::part(step)`, and
  its `icon`, `content`, `title` and `description` parts likewise.

```css
ui-steps {
  --ui-step-completed-color: var(--ui-primary);
  --ui-step-active-background: var(--ui-surface-muted);
  --ui-step-padding: 1em 1.5em;
}
ui-step::part(title) {
  font-weight: normal;
}
```

<Section title="Accessibility">
  - The group is an ordered list (`<ol>` with an explicit `role="list"`) and each step a list item, so a screen
    reader announces "list, 3 items" and each step's position.
  - The `selected` step carries `aria-current="step"`.
  - A `completed` step adds a visually hidden "Completed" (translatable):  the check alone says nothing to a screen
    reader.
  - A `disabled` step is `aria-disabled` (a disabled `link` step is a disabled `<button>`), and its dimmed text is
    that of an inactive control.
  - A step with `href` is a real `<a>`, and a `link` step a real `<button>`:  Tab reaches them and Enter follows
    them (Space too, for a button).  Plain steps are text, not tab stops.
  - Icons are decorative;  the step's title carries its meaning.
  - Without JavaScript the native fallback renders the same list, links, `aria-current` and "Completed" text.  It
    drops the `icon` glyph and a completed step's check (an ordered step's number still turns into a check), a
    `link` step without `href` becomes a plain box, and "Completed" stays English.
</Section>
