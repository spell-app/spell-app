<Section title="Behaviour">
  A reveal shows its `visible` slot and hides its `hidden` slot underneath;  on hover, while it holds keyboard focus,
  or while `active` is set, the visible content moves, fades, rotates or slides away to show the hidden one.  The
  box is as big as the hidden content.  Anything you put in the reveal without a slot joins the visible content.

  Pick one type:  `fade`, `move`, `rotate` or `slide`, each with its direction.  `instant` drops the short delay
  before the swap, and `disabled` stops it.  Under the user's reduced-motion setting the swap is instant (no
  movement, no delay), with the same end state.  Reveals have no events:  set `active` from your own code to reveal
  one without hover.

```js
const reveal = document.querySelector("ui-reveal")
document.querySelector("#show-profile").addEventListener("click", () => reveal.toggleAttribute("active"))
```

<Section title="Theming">
  Theme with the public `--ui-reveal-*` tokens:  set one on the element, on any ancestor (a region, `:root`), or on
  the reveal's box through `::part(reveal)`.  They inherit into the shadow root, where the sheet reads each through a
  private alias, so nothing inside blocks them.  The two contents are `::part(visible)` and `::part(hidden)`;  they
  read the reveal's tokens, so set tokens on the reveal (or above it), not on them.

```css
/* every reveal on the page */
:root {
  --ui-reveal-duration: 0.8s;
}
/* one gallery */
.team {
  --ui-reveal-delay: 0s;
}
ui-reveal::part(hidden) {
  border-radius: var(--ui-radius);
}
```

<Section title="Accessibility">
  - "Hidden" is visual only:  both contents stay in the accessibility tree, so a screen reader reads the visible
    content, then the hidden one, at any time.  Give each image its own `alt`.
  - Keyboard users reveal it by focusing it.  When the content has no control of its own, the reveal is a tab stop:
    a `role="group"` named by the `aria-label` you put on the host, with a focus ring.
  - When the content holds a link, button or field, that control's own focus reveals it and the reveal adds no
    extra tab stop.  A `<ui-button>` inside is not detected yet, so the reveal keeps its stop then.
  - A `disabled` reveal is not a tab stop and never reveals.
  - Under reduced motion the swap is instant, with no movement.
  - Without JavaScript the native fallback renders the same boxes and slots, so hover, focus and `active` still
    reveal.  It is always a tab stop (unless disabled), even around a focusable control, and it doesn't pass on
    the host's `aria-label`.
</Section>
