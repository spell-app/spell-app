<Section title="Behaviour">
  Set the numbers as attributes (or the matching properties) and the bar follows:  `value` is a share of `total`, or
  a percentage when there is no `total`;  `percent` wins over both.  A comma list makes several bars.  `label` fills
  in `{percent}`, `{value}`, `{total}` and `{left}`.  `ui-change` fires whenever the percentage changes after the first
  render, and `ui-complete` when it reaches 100.

```js
const progress = document.querySelector("ui-progress")
progress.addEventListener("ui-complete", () => console.log("done"))
for (let done = 0; done <= 20; done++) progress.value = String(done) // with total="20"
```

  Fomantic's JS pulsed an `active` bar by itself;  here `active` is only the look, on while you set it.

</Section>

<Section title="Theming">
  Theme with the public `--ui-progress-*` tokens:  set one on the element, on any ancestor (`:root` for every
  progress bar), or on the track through `::part(progress)`.  They inherit into the shadow root, where the sheet
  reads each through a private alias, so nothing inside blocks them.  A `size` replaces the bar height.  Style each
  bar with `::part(bar)`.

```css
:root {
  --ui-progress-radius: 999px;
}
ui-progress.slim {
  --ui-progress-bar-height: 0.75em;
}
```

<Section title="Accessibility">
  - The element itself is the `progressbar`, with `aria-valuemin`, `aria-valuemax` (the `total`, else 100) and
    `aria-valuenow`;  `aria-valuetext` reads like the bar text (`45%`, or `9 of 20`).  An indeterminate bar has no
    value, which assistive tech reads as "progress unknown".
  - Name every bar:  `aria-label` on the host, or the `label` / slotted label text.
  - Colour is never the only signal:  pair `state` with a label that says what happened.
  - The indeterminate and `active` animations stop under reduced motion.
  - If the element can't render, its native fallback is a real `<progress>` with the same value and label;  several
    bars show as one (their sum), and the bar text, colours per bar and the animated looks are dropped.
</Section>

<Section title="Framework usage">
  Numbers are plain attributes;  listen for `ui-change` / `ui-complete` like any custom event.

```jsx
// React 19
<ui-progress value={done} total={20} bar-text="ratio" onui-complete={() => setDone(true)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-progress :value="done" total="20" bar-text="ratio" @ui-complete="finished = true" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<ui-progress value={done()} total="20" bar-text="ratio" ref={(el) => el.addEventListener("ui-complete", () => setFinished(true))} />
```

</Section>
