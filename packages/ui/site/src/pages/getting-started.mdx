## Installation

`@spell-app/ui` isn't published yet. Once it is:

```sh
yarn add @spell-app/ui
```

```js
import "@spell-app/ui" // registers every ui-* element
```

Each component is also its own entry, so a page can load only what it uses. For pages with no JavaScript at all,
`ui.css` is the whole page foundation (tokens, utilities, typography) as one stylesheet.

## The contract

Every component follows the same three rules, which is what makes it work in every framework:

- **Properties for data.** Rich data (`options`, `rows`) is a JS property, a real accessor on the class, so
  frameworks find it with `key in el`. First paint never needs one: server rendering drops object props.
- **Attributes for primitives.** Strings, numbers and booleans are reflected attributes. Booleans follow HTML:
  presence, `""`, `"true"` or `"yes"` mean true; `"false"` and `"no"` mean false.
- **`ui-*` events.** Every event is a `CustomEvent` with `bubbles: true, composed: true` and a lowercase kebab
  name (`ui-change`, `ui-open`). `detail` carries the computed state, e.g. `{ value }`, plus `originalEvent`.

## Frameworks

The contract holds in React 19, Vue 3.5, Svelte 5, Solid, Angular 20 and Preact 10. One line each:

| Framework | Usage                                                                                                                 |
| --------- | --------------------------------------------------------------------------------------------------------------------- |
| React 19  | `<ui-dropdown options={arr} value="x" open onui-change={fn} />`                                                       |
| Vue 3.5   | `isCustomElement: (tag) => tag.startsWith("ui-")`, then `<ui-dropdown .options="arr" value="x" open @ui-change="fn">` |
| Svelte 5  | `<ui-dropdown options={arr} value="x" open onui-change={fn}>`                                                         |
| Solid     | `<ui-dropdown prop:options={arr} value="x" open={o} ref={(el) => el.addEventListener("ui-change", fn)}>`              |
| Angular   | `[options]="arr" (ui-change)="fn($event)"` plus `CUSTOM_ELEMENTS_SCHEMA`                                              |

- Define the elements before the framework renders them. As a backstop, every component "upgrades" a property
  set before definition (it deletes the shadowing own property and re-sets it through the setter).
- Vue may send `open="false"` when it can't find a property; the boolean converter reads that as false.

## Styling

- Components use shadow DOM, so page CSS doesn't reach inside. Instead:
  - **tokens** (`--ui-font-size`, `--ui-primary` ...) inherit into every component;
  - **utilities** (`ui-stack`, `ui-bold` ...) work on your markup and inside components;
  - **the app stylesheet**: give one stylesheet `id="ui-app-stylesheet"` and every component adopts it, so it
    can restyle component internals with Fomantic's class grammar. This site's own stylesheet is one.
- See [Theming](../theming/) for the details.
