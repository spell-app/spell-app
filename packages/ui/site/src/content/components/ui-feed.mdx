<Section title="Behaviour">
  A feed is a list of events, newest or oldest first as you order them.  Each `<ui-event>` is a label beside a
  block of content.  The label is optional:  a round picture (`image`), an `icon`, a short text in a circle
  (`label`), or anything you put in the `label` slot.  In an `ordered` feed every event gets a label for its number.

  The feed styles the [content parts](../ui-parts/) inside its events, so you write plain parts and they take the
  feed's look:  `<ui-content>` holds the event, `<ui-summary>` says what happened, `<ui-author>` names who (Fomantic's
  `.user`), `<ui-date>` says when (inline inside the summary, a line of its own outside it), `<ui-extra>` adds more
  (`text` for a block of text) and `<ui-meta>` holds small actions such as a like count.

  `connected`, `ordered`, `divided`, `basic` and `color` are set on the feed and reach every event;  `color` and
  `basic` also work on a single event.  Neither element fires events of its own.

  <VocabularyTable family="ui-feed" />
</Section>

<Section title="Theming">
  Theme with the public `--ui-feed-*` tokens:  set one on the feed, on any ancestor (`:root` for every feed), or on
  its box through `::part(feed)`;  its events inherit them.
  Style an event's pieces with `::part()`:  `event`, `label`, `image` and `icon`.  The feed's content parts also read
  a few tokens that are unset by default, so they are not in the table:  `--ui-feed-summary-color`,
  `--ui-feed-date-color`, `--ui-feed-meta-color`, `--ui-feed-meta-action-color`, `--ui-feed-extra-color` and
  `--ui-feed-extra-text-width` (default `500px`).

```css
ui-feed {
  --ui-feed-label-width: 3em;
  --ui-feed-connected-color: var(--ui-primary);
  --ui-feed-date-color: var(--ui-text-muted);
}
ui-event::part(label) {
  filter: grayscale(1);
}
```

</Section>

<Section title="Accessibility">
  - The shadow root holds a real `<ul>` (`<ol>` when `ordered`, since the numbers mean something) with an explicit
    `role="list"`, because Safari drops list semantics from unstyled lists.  Each `<ui-event>` in a feed is a
    `listitem`.
  - The `image` and `icon` labels are decorative (`alt=""`, hidden glyph):  the summary must say who and what.  Give
    a picture in the `label` slot its own `alt` (`""` when it is decoration, as in the examples).
  - A `label` text and the numbers of an `ordered` feed are drawn by CSS, so don't rely on them to carry meaning a
    screen reader must hear.
  - `disabled` fades the event, blocks the mouse and sets `aria-disabled`.  Links inside stay in the tab order;  add
    `inert` to the event when they must not be reached at all.
  - If the feed or an event can't render, its native fallback keeps the same list, event boxes, labels and class words, so the feed
    still reads in order.  It drops the `icon` label's glyph (the box stays empty) and the feed styling of the
    content parts, and counts only an event directly inside a `<ui-feed>` as a list item.
