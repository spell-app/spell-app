<Section title="Behaviour">
  The host is `display: contents` and the box lives on the `segment` part, so size and shape are set with
  `::part(segment)`.  A coloured segment recolours only its own box;  the slot resets the colour tokens for nested
  content.  Segments have no events.

  <VocabularyTable family="ui-segment" />
</Section>

<Section title="Theming">
  Theme with the public `--ui-segment-*` tokens:  set one on the element, on any ancestor (a `<ui-segments>` group,
  `:root`), or on the box through `::part(segment)`.  They inherit into the shadow root, where the sheet reads each
  through a private alias, so nothing inside blocks them.  Variations build on them:  `padded` swaps in
  `--ui-segment-padded`, and `--ui-segment-scrolling-height` replaces the viewport-based height of `scrolling`
  segments at every width.  The group's own `--_ui-segments-*` tokens are private.

```css
ui-segments.cards {
  --ui-segment-radius: 0;
}
```

<Section title="Accessibility">
  - A segment is a layout box with no role.  Use a landmark inside, or `role="region"` with an `aria-label`.
  - `loading` sets `aria-busy` and shows a visually hidden `role="status"` "Loading…" message (translatable);
    `disabled` sets `aria-disabled`, and, as in Fomantic, only dims and blocks pointer events, so disable the controls
    inside too.
  - A `scrolling` segment is a keyboard stop, so its overflow can be scrolled without a mouse.
  - Without JavaScript the native fallback renders the same `ui segment` element around a slot;  only the dark
    colour-scheme tokens of `inverted` segments are lost.
</Section>
