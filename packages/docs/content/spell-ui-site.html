Spell UI Docs Site

How the Spell UI docs (packages/ui/site/, served at /ui/) are put together since the ui-docs-rework epic, and why.

Plan doc: epic ui-docs-rework Written for: anyone changing the site's chrome, a page, or the Spell theme Status: built on branch ui-docs-rework
  • A spell theme from the brand, the default on every doc site (Spell UI docs, docs, plan docs, goals); the Spell hat is every site's favicon.
  • The chrome is written ONCE (site/_parts/layout.html); a page's file is its <head> and one <main>. Clicks swap only the main.
  • The page shows only once the layout, the theme and every element are ready: no flash, no jump (CLS 0.0002 measured locally, shown at ~250ms).
  • Content is nested <ui-section>s with nested ids (#examples-types-emphasis): foldable, sticky titles under sticky tabs, deep links land unfolded.
  • Left: the brand nav panel with the logo and the site search. Right: the repo's site header, docked, the look controls, "On this page". No top bar on wide screens.
  • packages/ui/src/styles/themes/spell.css, listed in ThemeSheets.OWN, applied on top of classic like every theme; tokens from packages/brand/spell-design-system/tokens/.
  • Spell Purple primary (violet-600 light, lilac dark), an aubergine dark mode (not black), ivory as the brown hue, lavender info.
  • Fonts: 'Spell Serif' is the INSTALLED Palatino family only (macOS / iOS, Windows, most Linux); elsewhere the generic serif. No font files ship: Owen's call (the brand's P052 fallback was ~540 KB, and AGPL). Body: the system sans.
  • Shape: pill buttons and labels, 12px inputs, 16px cards, 22px modals, layered soft shadows, round checkboxes.
  • From the interfaces.dev cheat sheet: 3px focus ring, buttons press to 0.97, no transitions while the scheme switches, tabular numbers, balanced headings, font smoothing, image outlines, scroll-margin-top.
  • Default on the Spell UI docs (ThemePreference) and in the docs bundle (spell-ui.entry.js); the theme menu lists Spell, Plain, Classic, then Fomantic's.
  • A plain left click on a link to a page of the site (or the nav's cancelable ui-navigate): the router fetches the page (UI.sources, cached), loads the families it uses, then points a <ui-include select="main#main" page-styles> at it, inside a View Transition.
  • pushState keeps the page's real URL: reload, deep links, back / forward and live reload all work as with plain pages.
  • After a swap: the title, the nav's current row, "On this page", the docked site header (spell-site:page), live reload's file, the page's inline scripts re-run, the flyout closes, focus moves to main, the hash lands.
  • <ui-include>'s new ui-insert event hands over the fragment before it goes in: the router keeps each example's authored markup (ExampleSource.keep()) and makes every relative URL absolute.
  • Anything that fails falls back to a full load.
  • yarn site:new <tag|page> in packages/ui; rules in epics/spell-ui-pages/PAGES.md.
  • The body is ONE <main id="main" class="site-main" data-toc-header="...">.
  • Styles go in main or site/_src/site.css, never <head>: a swap drops the head.

  • <ui-docs-nav>: the brand panel (the Color Set Chooser's look): ivory card, header band with the Spell lockup and the search field, folding group bands, nav rows with a lavender current row. Folds remembered.
  • <spell-site-header docked>: the repo-wide bar as a compact row (no fixed bar, no crumbs, no scheme button).
  • The right column stays on every tab (the API tab too): the page width never jumps.
  • Every tab's content is nested <ui-section sticky collapsible dividing>s, an example inside its own section.
  • Ids nest: <tab>-<section>-<example>, written INTO the markup by yarn site:sections (idempotent; site:new, site:index, site:kitchen run it). site:check fails on an id that doesn't follow its nesting.
  • A hash picks its tab, unfolds the sections around the target, and lands below the stuck titles (site/_src/SiteSections.ts). Old hashes (#types) still land, and the URL is rewritten.
  • The tabs bar sticks; top-level titles stick below it, nested ones below their parents. Folds start open and are remembered per page.
  • "On this page" lists the nested sections.

  • One page per family (a folder: one chunk, one barrel) holds its tags together: Button covers <ui-button>, <ui-buttons>, <ui-or>.
  • Tags that stand alone get their OWN page: ui-radio, ui-textarea, and the 12 Parts tags other than ui-header (80 pages in all). site/_data/pages.json's pages map names them; the nav, search, index and kitchen sink follow its hrefs.
  • Downloads don't change: families still load as one chunk each.
  • <ui-docs-search>, in the nav panel's header: one field that jumps anywhere and still filters the nav list.
  • Groups: On this page (read live), Components (every tag, by name, aka, topic), Pages, Sections (every page's, from _data/search.json, built by yarn site:data), Attributes.
  • / or ⌘K focuses it from anywhere (on phones it opens the flyout); arrows, Enter, staged Escape. Results are plain links: the router swaps the page.
  • <ui-docs-themes>: a sun / moon button showing the scheme in use (a click flips it, animated), and a palette button opening a small overlay: the theme list and "Match system".
  • ONE scheme for every site: localStorage["spell-site:scheme"] (light, dark, absent = the OS), applied as ui-light / ui-dark AND color-scheme on <html>; the docs' site header flips the same way.
  • The brand's app icon: white hat on aubergine, 22.5% corners; yarn favicon in packages/server generates it.
  • The page server injects it into every page it serves; <spell-site-header> adds it on file://; the app links its own copy.
  • Real URLs with the layout injected, over a shell page with a route: every link, reload and live reload keeps working (Q1).
  • <ui-root display="when-ready"> over <ui-root hidden>, skeletons or a cloak: already built, and a failed script never leaves a blank page (Q2).
  • Family pages, with own pages for tags that stand alone (Q3, see the plan doc's P7).
  • The site header docked in the right column, not a top bar (Q4).
  • Ids in the markup, not derived at runtime: stable, grep-able, linkable.
  • Every choice made without Owen is a judgement call in the plan doc (J1-J44).
  • A page opened from disk, or with scripts off, shows its main alone (no chrome).
  • A page's <head> styles and scripts don't follow a swap; inline scripts in main re-run on every visit.
  • Where no Palatino-family face is installed (some Linux, Android), headings fall back to the generic serif.
  • On phones the stuck stack (top bar, tabs, two titles) takes about a fifth of the screen.
