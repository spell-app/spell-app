C1 Older windows still run the old extension

The window moves rely on a new version of spell's VS Code extension. It runs only in windows opened or reloaded since 2026-10-03; a window left open from before still runs the old one.

  • Reloading a window restarts its Claude sessions, so reload when it's convenient.
  • How you'd notice: a move into a worktree's window (the handoff) misbehaves from an old window. Not checked: exactly how that shows.

Net effect:

  • nothing changes: reload each package window once, at a quiet moment
C2 You press Enter on continue in the new tab

When a session moves to its worktree's window, the new tab opens with continue already typed in its input box, but not sent. You press Enter to carry on.

  • Why: the Claude extension's initialPrompt (version 2.1.287) fills the input; it has no way to send it.
  • Where: WindowBridge.ts, its open-session case ("typed in, not sent").

Net effect:

  • nothing changes: one Enter per move
C3 "isolate as foo" renames the session one prompt late

Typing /isolate foo renames the session at once. Saying it in plain words, like "isolate as foo", renames it only on your next prompt or on resume, which may be too late.

  • Why: plain words never reach the prompt-gate.mjs hook, which only acts on the slash commands.
  • So the skill queues the title instead (then with session.py name, now spell dev session title <name>).
  • Why late matters: the move finds the old tab by its title, so it may fail to close the old tab if the rename hasn't landed yet.

Net effect:

  • nothing changes: type the slash command when you can
  • an old tab left open after a plain-words move: close it by hand
C4 No edit mode for a running epic's doc on the main server

The main checkout's page server shows a running epic's plan doc under /worktrees/<w>/, but you can't use edit mode on it there.

  • Why: PageEditor (PageEditor.ts) refuses dot paths too, and every worktree is under .claude/worktrees/.
  • To edit it: open the doc from the worktree's own page server.

Net effect:

  • nothing changes: read on the main server, edit on the worktree's
C5 Restart the main page server once after the merge

A page server started before this branch merged doesn't know how to serve worktrees. Until it's restarted, links to a running epic's doc go to the worktree's own server instead of the main one.

  • How it decides: SRV.mainServerUrl() (mainServer.ts) asks the main server for /_server/epics; an old server has no such route.
  • So the links fall back, rather than pointing at a URL the old server would 404.

Net effect:

  • restart the main checkout's page server once after this merges; then every link uses one port
