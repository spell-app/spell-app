Details Pages

When a question needs a picture, or more answers than the modal holds, Claude writes a small page, shows it in VS Code's right side bar, and Owen answers ON the page.

Plan doc: epic details Written for: anyone changing /details, its page, its route or its CLI Status: built (epic details) Checked: route and CLI tests, a Playwright click-through, and a real background wait woken by an answer sent from the page
  • The AskUserQuestion modal holds 4 options per question and 4 questions, and no pictures. A DETAILS PAGE has no such limit: tables, real code, diagrams, then option cards to pick from.
  • No VS Code extension change: the "Spell Docs" view already shows any page from the page server (node scripts/window.mjs show).
  • The answer comes back through a page server ROUTE MODULE, which writes it beside the page; a waiter Claude left running in the background sees it and exits, and that exit wakes the session.
  • Fits the modal and needs no picture: the modal.
  • Fits the modal, a picture helps: a picture page, then the modal.
  • Doesn't fit: an answer page. Rules: .claude/skills/details/SKILL.md.
  • Owen answers in chat instead: Claude stops the waiter.
  • No answer in 8 hours: the waiter exits 2, saying so, once.
  • "Change answer" on the page unlocks it; sending again replaces the answer (changes counts up).
  • templates/details.html -- context, then one ui-section.spell-question per question. Never copied by hand: yarn details new fixes the asset paths for the page's depth (pages.js atDepth(), shared with docs:new).
  • _assets/details.js -- a classic script loaded BEFORE spell-ui.js, so what it builds is upgraded with the page. From each .spell-option it builds a ui-segment card: ui-radio (or ui-checkbox under data-multiple), a Recommended label, the summary, the details folded in a ui-accordion. Then an Other ui-input per question, and a Send section.
  • _assets/details.css -- the cards, on the doc tokens (dark mode keeps working).

  • scripts/detailsRoutes.ts, a page server route module listed in the root package.json (Page server):
    • POST /api/details/answer { page, answers, notes } -- writes <slug>.answer.json beside the page, atomically; token and origin checked (guard.writeCheck)
    • GET /api/details/answer?page= -- the answer, or { answer: null }, for the page on load
  • page is the page's URL path, mapped to its file through the server's own mounts (StaticHandler.resolve()), so a worktree's page on the main server (/worktrees/<w>/...) works too. Only a page in a details/ folder of packages/docs: anything else is a 403.
  • Listed BEFORE appRoutes.ts, whose /api router ends in a catch-all 404.
Command Does
new <slug> [--title] [--epic] a page from the template; sweeps old scratch pages first
show <page> [--wait] in this session's side bar (Chrome outside VS Code); then wait
wait <page> [--timeout 8h] until an answer NEWER than its start; prints it; timeout exits 2
answer <page> the answer already sent
list / sweep [--days 14] every page; delete old scratch ones
  • scripts/details.js; run as yarn details ... from anywhere. Paths print absolute.
  • Scratch pages: packages/docs/content/details/, ignored by version control, swept after 14 days. An epic's: epics/<name>/details/, committed with its plan doc. findPages() skips both: not in the index, not checked by docs:update.
  • Every page Claude names (a details page, a plan doc, any docs page) comes as two links, from yarn docs:link <page> --hash <id> --show: the title shows it in the side bar, (_browser_) opens it in Chrome. --show also shows it at once.
  • Both go through the page server, GET /api/docs/show (scripts/showRoutes.ts): the Claude panel ignores vscode:// links, and opens localhost ones in a VS Code tab.
    • side bar: the server asks the session's VS Code window (its pid is in the link) to show the page
    • in=browser: the server opens Chrome, in front, reusing the page's tab
    • either way the tab the click opened closes itself, and VS Code comes back to the front
    • refused unless the click started it (Sec-Fetch-Site): no other site can trigger it
  • --hash: the page lands on that id, below the sticky titles, unfolded (the docs runtime does this for any #id).
  • End the turn and wake on Send, rather than block inside the turn: Owen can still type, and nothing times out in 10 minutes.
  • Page and modal by size: the modal is quicker for a small pick, so a page that fits it is a picture and the modal asks.
  • An epic's pages are committed: the decisions they led to link them, so the plan doc keeps the picture.
  • Stacked cards with folding details, all @spell-app/ui: Owen's pick (plan doc D6).
  • Locked after Send, with Change answer: one answer at a time, but a change of mind is one click.
  • Short option markup, built by script: a third of the typing per question, and card fixes reach every page.
  • A "Where we are" box on every page, questions that stand alone, plain short lines: Owen runs 5+ epics at once and reads each page cold.

Every decision and the overnight judgement calls: the plan doc.

  • Route modules load when a page server STARTS. A server running from before the route existed answers 404, and the page says "can't take answers yet": restart it (yarn server stop, then yarn server ensure).
  • A worktree's page shows from the MAIN checkout's page server, so a worktree's own route changes reach the side bar only after they merge.
  • A page server restart changes the write token: an open page must reload before Send.
