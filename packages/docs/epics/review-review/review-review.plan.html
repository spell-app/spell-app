What a review looks like once this epic is done, step by step:

  1. You type /epic review wwod (D3).
  2. The wwod plan doc opens in the Review tab of VS Code's right side bar, scrolled to the first thing worth your time (say, an unreviewed judgement call, shown with a red id badge).
  3. You read down the doc. On any item you open its action menu (the round ellipsis at the right of its title) and pick one:
    • Approve: fine as it is. The menu button turns green.
    • Add to todo: follow it up later, as a todo.
    • Add Details: Claude writes a fuller explanation into the item, in the background, with a spinner on the item until it's done. You keep reading.
    • Revisit: a text box opens under the item for your question or comment, with two buttons: revisit soon (talk it over in the next batch) and revisit now (Claude starts on it at once, and answers inline).
  4. Where an item offers options (A / B / C cards), clicking a card picks it.
  5. Anything waiting for Claude turns the page header's round send to Claude button blue. Clicking it hands the whole batch to the Claude session: approvals and picks are recorded, todos filed, and the "revisit soon" items talked through in the chat, one after another.

Why this shape: today a review is a string of modals in the chat, each showing one item without the doc around it. On the page you have the whole context, and you decide at your own pace.

The one hard limit, found while exploring:

  • Nothing outside a Claude Code session can push a message into it. A session wakes only when you type, or when a background command it started finishes.
  • The VS Code Claude extension can type a prompt into a session's tab, but only when it opens that tab fresh; into a tab that's already open, it refuses ("Your prompt was not applied").

So the page and the session meet in a file, the way details pages already work:

  • The page saves your marks through a small page-server route into an inbox file beside the plan doc, e.g. epics/wwod/wwod.inbox.json (D1).
  • The /epic review session keeps a background command waiting on that file. "Send to Claude" or "revisit now" makes it finish, which wakes the session.
  • A busy session (mid-answer) gets the wake as soon as its turn ends: that's the "queue it up to happen ASAP" you asked for, for free.
  • "Add Details" and "revisit now" run as background agents started by that session, so the chat stays free; each writes into the item and clears its spinner.
  • No session waiting (it was closed): the marks stay in the inbox until the next /epic review, and the page says so (D6).
  • Where the terse style comes from: the plan-doc rules and the /epic skill both say "caveman lite" (drop articles, fragments OK). The details-page rules already say the opposite ("Not caveman"). The plan-doc rules switch to the details-page rules.

D14 · P1 reloads: the docs runtime patches the page, the live client only fetches
