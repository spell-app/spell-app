Built in P17 (element), P18 (settings), P19 (skeletons); docs in P20. One element around a page or app. It:

  • loads each ui-* tag's family the first time the tag shows up inside it; nothing up front
  • waits until everything inside is ready (or timeout passes), then shows it and fires ui-ready
  • meanwhile shows skeletons or a loading message (display, loading)
  • sets icons, emoji, theme, size and an optional box for everything inside
  • Own entry @spell-app/ui/ui-root (D56): import "@spell-app/ui/ui-root" is the only script a page needs. Own code 7.70 kB min + gzip (docs/report.md); pages without a root pay nothing.
  • No Fomantic counterpart, so no class grammar: every attribute is a property.
  • The docs site runs on it: site/src/layouts/Docs.astro wraps every page in <ui-root display="immediately">; the site's own loader is gone (D63).
  • Docs page: site/src/content/components/ui-root.mdx.

  • RootLoader imports a family through a LITERAL import.meta.glob of every family's index.ts, so each is a literal import():

  • Watching: on first connect, a scan for undefined ui-* tags (:not(:defined)); then, while connected, a MutationObserver on the subtree loads whatever is added. An undefined tag without the ui- prefix (an app's own element) is left alone.

const FAMILIES = import.meta.glob(["../*/index.ts", "!../ui-root/index.ts"])

/****************
 * ### `RootLoader`
 * Tag => family => `import()`, once per family for the whole page (every root shares the loads).
 * - Which family defines a tag comes from `ROOT_CATALOG` (generated from the vocabularies, `yarn gen:root`), never
 *   from guessing at the tag's name.
 ****************/
export class RootLoader {
  /** Folder => its import, started once. */
  private static readonly loads = new Map<string, Promise<void>>()

  /** The folder (family) that defines `tag`;  `undefined` for a tag no family defines. */
  static folderOf(tag: string): string | undefined {
    return Object.hasOwn(ROOT_CATALOG, tag) ? ROOT_CATALOG[tag].folder : undefined
  }

  /** Import `folder`'s family (which defines its tags), once;  rejects if it can't be imported. */
  static load(folder: string): Promise<void> {
    let load = RootLoader.loads.get(folder)
    if (!load) {
      const importer = FAMILIES[`../${folder}/index.ts`]
      load = importer ? importer().then(() => undefined) : Promise.reject(new Error(`no family "${folder}"`))
      RootLoader.loads.set(folder, load)
    }
    return load
  }

Icons and emoji per root

  • Attributes on the root only (D58): <ui-icon-set> and <ui-emoji-set> are removed. A page without a root uses UI.icons.use() / EmojiData.use() in JS.
  • Per root, not page-wide (D51): outside any root, the page's set applies. Language stays page-wide for now: no lang attribute.
  • RootSettings (core, D66): root element => { icons, emoji }.
    • nearest(element, key) climbs the FLAT tree (slot, parent, shadow host): an icon inside a component's shadow finds the root around the component; a nested root inherits what it doesn't set (D52).
    • In core because icons and emoji read it, and must never import the root.
    • generation (a signal) bumps on any root's change; IconGlyph and <ui-emoji> track it, plus connected (a move to another root), and redraw.
  • Icons (D67): icons="fa7-brands, /packs/lucide/pack.js" makes a CHILD set, UI.icons.scope(packs, { assets, parent }).
    • its packs win; the parent's answer what they don't
    • parent is a function asked at each lookup, so an inner root follows the outer root's CURRENT packs
    • SVG cache and registered icons stay one per page; IconGlyph.packsFor(element) picks the set
  • Emoji: emoji="fomantic". EmojiData keeps loaded names PER SET (setFor(element); peek / get take a set), so two roots can use different sets at once.
  • assets="/ui/": the folder built-in packs load from (<assets>icon-packs/<id>/pack.js); replaces base.
  • Timing: emoji apply at once; a root's icon set is made once the runtime loads, so with display="immediately" an icon may draw from the page's packs for a moment (C12).

  private applySettings(packs: string[], emoji: string | undefined, assets: string | undefined) {
    const request = ++this.settingsRequest
    RootSettings.set(this.host, { emoji })
    if (!packs.length) return
    void UI.load().then((ui) => {
      if (request !== this.settingsRequest || !this.host.isConnected) return
      // never this root's own set:  its parent is whatever is ABOVE it
      const outer = () => {
        const above = RootSettings.parentOf(this.host)
        return above ? IconGlyph.packsFor(above, ui.icons) : ui.icons
      }
      RootSettings.set(this.host, { emoji, icons: ui.icons.scope(packs, { assets, parent: outer }) })
    })
  }

// RootSettings.ts
  static nearest<K extends keyof RootSettingsValue>(element: Element | null, key: K): RootSettingsValue[K] | undefined {
    for (let current = element; current; current = RootSettings.parentOf(current)) {
      const value = RootSettings.byRoot.get(current)?.[key]
      if (value !== undefined) return value
    }
    return undefined
  }

Theme, size and box

  • ui-root.css styles the HOST by state, never by attribute value (a translation may rename it). The host is display: contents: no box, nothing added to the page's structure.
  • theme="dark" => :state(dark): color-scheme, --ui-scheme, text colour and background, as .ui-dark. Every colour token is a light-dark() pair, so the subtree flips. Without a box it paints no background (C11).
  • size="small" => --ui-scale: var(--ui-size-small) on the host, inherited through shadow roots; medium sets nothing.
  • width / height (D60): a CSS length, or window (100dvw / 100dvh, following a phone's address bar). Either => :state(box): a block that scrolls its own content.
  • fixed => :state(fixed): position: fixed; inset: 0, overscroll-behavior: contain. A full-page app shell; on iOS the keyboard can cover fields near the bottom (documented).
  • Width, height and scale go in the root's OWN constructed sheet (RootBox), adopted into its shadow:
    • not an inline style: that's the author's
    • lengths pass CSS.supports() first, so an attribute can't inject other declarations
  • Tokens: any --ui-* in the root's style reaches everything inside, as on any element. Nothing new.
  • The theme / box / fixed states live in the root's sheet, which arrives with UI.load(): with display="immediately" the content can show a moment in the page's scheme (C11).

 UIRoot.tsx · findSkeletons() · 10 lines 
  /** Each element inside whose tag describes a skeleton, in page order, skipping those inside another one. */
  private findSkeletons(): RootSkeleton[] {
    const skeletons: RootSkeleton[] = []
    for (const element of this.host.querySelectorAll("*")) {
      const spec = Object.hasOwn(ROOT_CATALOG, element.localName) ? ROOT_CATALOG[element.localName].skeleton : undefined
      if (!spec || skeletons.some((outer) => outer.element.contains(element))) continue
      skeletons.push({ element, spec })
    }
    return skeletons
  }

Q13 Root: are page settings page-wide or per subtree? (icon packs, emoji names, lang) → D51

<ui-root icons="fa7-free">...</ui-root>
<ui-root icons="fomantic">
  <ui-icon name="home"></ui-icon>
  <!-- which pack? -->
</ui-root>

theme, size and tokens are CSS and inherit, so they are per-subtree for free. Only icons, emoji and lang are in question. (lang chooses a dictionary, which renames TAGS, and customElements is one registry per document: tags cannot be per-subtree.)

A. Page-wide (recommended)

Settings apply to the whole page, merged in order, like <ui-icon-set> today. A second root with a conflicting emoji or lang logs a warning (last wins). Cheapest: no change to UI.icons. 

icons="fa7-free fomantic"
<!-- adds to UI.icons -->

Each icon asks its nearest root for packs. Needs a lookup through shadow roots on every icon, and a cache per root. Isolated demos, but dictionaries still can't be per-subtree. 

<ui-root icons="lucide">

<!-- nearest root's packs -->
C. Split

Icons / emoji / lang page-wide, theme / size / tokens per subtree (they inherit anyway). In code the same as A: this is A, said out loud in the docs.

Q14 Root: nested roots, does an inner root override or merge? → D52

<ui-root theme="dark" icons="fa7-free">

           display="immediately">
    <ui-card>...</ui-card>
  </ui-root>
</ui-root>

Questions in that example: does the inner root stay dark? Does it wait for its own families or the outer one's? Does the outer display hide it?

A. Inner inherits, adds (recommended)

Theme / size / tokens inherit by CSS (inner overrides only what it sets). Page settings merge (see the scope question). Loading: the inner root reports to the OUTER one, which is ready only when every inner root is. The outer display hides everything under it; an inner display matters only once the outer is ready.

A root inside a root does nothing but warn. Simple, but a self-contained widget breaks the moment a page also has a root.

C. Independent

Each hides and loads its own subtree. The outer is ready when ITS descendants (not the inner root's) are. Can flash: the outer shows while the inner is still hidden.

Recommend A: matches how CSS inheritance already works, and gives one "everything is ready" answer for the page.

Q15 Root: when-ready timeout and error policy (a family that never loads) → D53

<ui-root display="when-ready"
         timeout="3s">
  <ui-card>...</ui-card>
  <ui-cardd>typo</ui-cardd>
</ui-root>

Two kinds of failure: a tag with NO family (ui-cardd: the roll-up has no entry, known at once) and a family whose import REJECTS or hangs. The docs site's loader today logs a rejection and carries on (Promise.allSettled in site/src/scripts/components.ts (gone since P20)).

A. Reveal after a timeout (recommended)

Unknown tags are ignored (one console.warn). A rejected import is logged and counts as settled. After timeout (default 5s) the root reveals anyway and fires a cancelable ui-error per failure. A broken family never blanks the page; its elements show their native fallback.

B. Stay hidden

No timeout. Strict: never shows half-built UI. But one offline chunk blanks the page, which the native fallback (docs/fallback.md) exists to avoid.

C. Reveal on first error

Wait with no timeout, but reveal the moment any import rejects. A hang (never settles) still blanks the page.

Q16 Root: server-side rendering and Declarative Shadow DOM → D54

  </ui-button>
</ui-root>

A. Hide only with JS (recommended)

Simple, but with JS off or slow the page is blank: server rendering gains nothing under a root.

Q17 Root: how does a skeleton size to content it has not seen? → D55

    <ui-description>
      3 lines of text
    </ui-description>

A. Default size per tag (recommended)

B. Mirror the children
