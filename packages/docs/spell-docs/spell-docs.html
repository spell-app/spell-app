How Spell Docs Work

Spell's docs are plain HTML pages that render with @spell-app/ui, open straight from disk, and come in a few kinds, each with a template. Planning sessions get their own kind: a live plan doc that /epic keeps current while the work happens.

  • Written for: anyone writing a doc, or running a planning session with Claude Code
  • The rules, for agents: AGENTS.md and plan-doc.md. The mechanics, distilled: spell-docs.md.
  • Every doc lives in packages/docs, one folder per topic, listed in the docs index.
  • A page is hand-written HTML using ui-* elements. No build step to read it: open the file.
  • Start every page from a template: durable doc, cheat sheet or plan.
  • /epic <name> runs a planning session in its own worktree and keeps a plan doc that shows phases, open questions, issues, caveats and decisions as they change.
  • The last phase of every plan turns the plan doc into durable docs.
kind for template lives at
durable doc design notes, research, references templates/durable.html <topic>/<topic>.html
cheat sheet an API reference: a filterable grid of cards templates/cheatsheet.html <topic>/<topic>.html
plan doc one planning session, kept live templates/epics/plan.html epics/<name>/<name>.html
  • A topic with one page and nothing beside it may sit at the top: <name>.html.
  • Claims backed by measurement keep their scripts in <topic>/experiments/.
  • When agents need a doc's rules, a distilled <topic>.md sits beside it.
  • Browsers refuse ES modules on file://, so a page loads ONE classic script, _assets/spell-ui.js: Solid, all of @spell-app/ui and the page runtime, bundled.
  • Icons are bundled too: UI's icon packs load over the network, which a file on disk can't do, so the ones the pages use are registered at start-up.
  • highlight.js, from a CDN, colors code; offline, code is plain monospace.
a page's skeleton · 21 lines 
<head>
  <title>Short Title</title>
  <meta name="description" content="One sentence:  shown in the docs index." />
  <link rel="stylesheet" href="../_assets/spell-doc.css" />
</head>
<body class="spell-doc-page">
  <div class="spell-doc">
    <main class="spell-doc-main">
      <h1>Short Title</h1>
      <ui-section id="1-summary" header="1. Summary" sticky collapsible dividing>
        <ui-icon slot="icon" name="lightbulb"></ui-icon>
        ...
        <ui-section id="a-part" header="1.1 A part" sticky collapsible dividing>
          ...
        </ui-section>
      </ui-section>
    </main>
  </div>
  <script src="../_assets/spell-ui.js"></script>
</body>
  • The contents sidebar, built from the page's sections when it loads, so it can never drift from them. A drawer on narrow screens.
  • Sticky section titles: every section is a <ui-section sticky collapsible dividing>, so each title sticks below its parent's, folds its section, and has a rule under it. Folds are remembered per page.
  • Scroll-follow: the current section is highlighted in the sidebar, and its panel opens.
  • Buttons to expand or collapse the sidebar, and to fold every code block.
  • On cheat sheets, a filter that shows only the cards matching every typed word.
Aside: why not generate the pages?

Pages used to be generated from plain HTML sources by a converter. Writing the ui-* markup directly removed a slow step and a second copy of every page; the one thing the converter did that hand-written pages need, the contents sidebar, moved into the runtime.

  1. Start from a template: yarn docs:new durable <topic>/<topic>.html --title "Title", then replace its placeholders.
  2. Headings are short labels; the claims go in bullets below them. Code is always folded and colored.
  3. Link every file you mention: doc-links.py does it for <code> paths.
  4. Check it: doc-links.py --check, then check-spell.js, and look at its screenshots.
  5. yarn docs:index, so the page shows up in the index.

AGENTS.md, "Writing a page" and "Finishing a page".

A plan doc is a planning session's live record: the plan, what's done, what's open. You read it in Chrome while Claude Code works; its tab reloads whenever the session moves to a new stage.

name /epic <name>. If a doc, folder or worktree of that name exists, reuse it or pick another name. worktree Work happens in worktree <name>; the plan doc is created and opened in Chrome. plan Plan mode: explore, ask, draft. Once approved, the plan doc is filled from the plan. phases One at a time. Each ends with a summary and a question: what next? doc review The last phase: the plan doc becomes durable docs; the plan doc stays as the record.
section what ids
Plan two-sentence summary; phases, each with a status icon P1 ...
Questions waiting on you; also asked in Claude Code Q1 ...
Overview the plan's substance: what becomes durable docs
Caveats, Issues, Todos limits we accept, problems found, later work C1, I1, T1 ...
Decisions what was decided and why, so it isn't argued twice D1 ...
Phases per phase: goal, files, how to verify P1 ...
Log one-liners of plan changes, with local timestamps
  • Phase status: not started, in progress, done.
  • Short ids are for chat: "fix I2", "start P3".
  • Items are never deleted: done ones stay, struck through.
  • While a phase is in progress, what changed is flagged UPDATE; the flags go when the phase is done.

The plan doc for this docs workspace, built with the same tooling.

Claude Code and its agents change a plan doc's structure only through this command, so ids, icons and flags stay consistent and parallel agents take turns.

command does
new <name> create the doc from the template; update the index
add-phase <name> "Short Name" append a phase
phase <name> <N> todo|active|done set a phase's status, and reload the doc's tab
add <name> <kind> "title" add a question, caveat, issue, todo or decision
close / reopen <name> <id> strike or unstrike an item
summary <name> what's open, and the next phase
check / open <name> verify the doc; show it in Chrome, reusing its tab
command (from the repo root) does
yarn docs:update rebuild the bundle from the latest @spell-app/ui, update the index, check every page in a browser
yarn docs:index rewrite the index's lists
yarn docs:new <template> <page> start a page from a template, with asset paths fixed for its depth
yarn docs:open [page] show a page (default: the index) in Chrome, reusing its tab
yarn plan-doc ... edit a plan doc (above)
  • Claude Code can't rename its session or tab: run /rename <name> yourself.
  • New worktrees branch from origin/main: work that isn't pushed isn't in them, unless worktree.baseRef is head.
  • A plan doc lives in its worktree: the main index lists it once the branch is merged.
  • An icon a page uses must be in the bundle's list; any other name draws nothing.
  • The formatter collapses double spaces in page text.
