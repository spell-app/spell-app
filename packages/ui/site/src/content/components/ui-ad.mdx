<Section title="Behaviour">
  `<ui-ad>` is only the slot:  it sizes a box to an IAB unit and lays out whatever you put in it.  Loading the ad
  itself is up to your ad network's script.  `unit` takes the unit's words (`medium rectangle`, `leaderboard`,
  `large mobile banner` ...), not `size`, which is `mini` ... `massive` on every component.  It has no events.

  <VocabularyTable family="ui-ad" />
</Section>

<Section title="Theming">
  Theme with the public `--ui-ad-*` tokens:  set one on the element, on any ancestor (a region, `:root`), or on the
  ad's box through `::part(ad)`.  They inherit into the shadow root, where the sheet reads each through a private
  alias, so nothing inside blocks them.  The unit sizes are fixed by the IAB, so they aren't tokens.

```css
:root {
  --ui-ad-margin: 2em 0;
  --ui-ad-test-background: var(--ui-surface-muted);
  --ui-ad-test-color: var(--ui-text-muted);
}
```

  <CssTokens family="ui-ad" />
</Section>

<Section title="Accessibility">
  - An ad is a plain block with no role, so several ads on a page don't create duplicate landmarks.  Where you want
    one, wrap the ad column in a named `<aside aria-label="Sponsored">`.
  - The `test` text is drawn by CSS and isn't reliably read aloud;  it's a layout placeholder, not content.
  - The ad's own content needs its own text alternative:  an `alt` on an image link, a `title` on an `<iframe>`.
  - If the element can't render, its native fallback keeps the same box and class words, so the unit keeps its
    size;  a bare `test` then says "Ad" in English rather than the translated text.
</Section>
