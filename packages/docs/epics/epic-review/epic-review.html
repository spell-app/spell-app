Q4 Defer and Exit: where each goes → D4

The item modal: up to 2 recommendations, then Defer, then Exit (4 is the cap; "Other" lets Owen type anything else). Where do Defer and Exit go?

A. Defer = next, Exit = section (recommended)
  • Defer: item untouched, NOT marked reviewed (it shows next time), go to the next picked item; after the last, back to the section list
  • Exit: drop the rest of the picked items, back to the section list
  • "back" there goes to Start
 B. Exit = Start

Same Defer; Exit jumps to the Start modal. Faster to switch section, but loses the section list just shown.

Deferred items: leave a trace? Recommend a data-deferred date, shown in the list as "(deferred 10-03)", still outstanding.

Q5 Act on answers during review, or at Finish → D5

When Owen picks "Fix it now" for an issue, does the review stop and fix code, or only record it?

A. Record now, act at Finish (recommended)
  • Each answer: written to the doc (decision, close, convert to todo, new phase ...)
  • Actionable ones collect in a list; "Finish Review" shows it, and offers "Start the fixes" (in the epic's worktree), "Add as a phase", or "Leave"
  • Keeps the review fast; fixes run together
 B. Fix inline

Fix each item as it's answered, then the next. Good for 1-line fixes; a long fix stalls the review, and fixes happen wherever the session is (maybe main).

Finish Review also: a log line ("Review: 7 items, 3 decisions, 2 deferred"), a reply summary, and for a doc on main, stage + ask before committing.
