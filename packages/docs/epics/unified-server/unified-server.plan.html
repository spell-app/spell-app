New leaf package packages/server ($/server, namespace SRV): one set of page-serving helpers replaces six hand-rolled copies in goals, the VS Code preview, the CLI, ui's tools and the app's Express API. On it, ONE per-checkout page server serves docs, plans, goals, Spell UI docs and finally the editor (spell serve) on one port, with live reload, a shared site header and an API that edits pages in place.

T3 Choice to review: a :name* route part takes the whole rest of the path

In the Library Core phase (P1), the new router (packages/server/src/Router.ts) was made to differ from Express 4 on purpose: it fixes Express's behaviour instead of copying it. You'd notice it in the app's project-file URLs.

  • A route like /projects/file/:projectId/:filePath* now puts the WHOLE rest of the path in filePath, slashes included.
  • Express 4 put only the first segment in filePath, and the rest in params[0].
  • With Express, a project file in a sub-folder answered 404 or EISDIR.
  • The app's QUIRK contract tests, which pinned Express's split, changed with it in the App Router phase (P6).
Request Express 4 Now
/projects/file/p1/src/main.spell filePath = src; the rest in params[0] filePath = src/main.spell

Net effect:

  • project files in sub-folders load
  • a route handler never reads params[0] for a :name* part
T4 Choice to review: page edits must send If-Match

In the Page Server phase (P2), edits through the page server were made to require the version of the page being edited, so nothing overwrites a file blindly.

  • A PUT or PATCH without an If-Match header answers 428.
  • The other option: allow blind writes.
  • Every caller already has the page's ETag, from the page it loaded: the edit UI, and editPage().
  • An ETag that's out of date (the file changed underneath) answers 409, and the caller reloads.
packages/server/src/page/PageEditor.ts · 1 line 
if (!expected) throw new SRV.HttpError(428, "If-Match required:  send the ETag the page was served with")

Net effect:

  • a tool that writes through the page server reads the page first, for its ETag
  • an edit made in VS Code or by an agent meanwhile is never silently overwritten: the edit gets a 409
T5 Choice to review: the live-reload script is a function turned into text

In the Page Server phase (P2), the script that every served page runs for live reload and edits (liveClient()) was written as a TypeScript function that the server sends as text, (fn)(), not as a separate .js file.

  • Why: the VS Code extension's bundle is CommonJS, which has no import.meta.url to find a .js file beside it by.
  • The cost: it needs a __name shim. tsx (its keepNames) wraps nested functions in __name(fn, "fn"), a helper that lives in the module, not in the function's text.
  • It MUST stay self-contained: no imports, no module helpers.
packages/server/src/liveClient.ts · liveClientScript() · 6 lines 
return [
  "// spell server:  live reload and page edits (packages/server/src/liveClient.ts)",
  "var __name = (fn) => fn;",
  `(${liveClient.toString()})()`,
  ""
].join("\n")

Net effect:

  • the extension and the page server serve the same script without finding a file on disk
  • anyone editing liveClient() must not import anything into it

T14 Choice to review: the app's API has no token, only an Origin check

In the Spell Serve phase (P7), the app's API joined the page server, but without the token the page server's own writes need.

  • Why: the editor calls /api from Vite's origin, through Vite's proxy, so the page server's token can't apply.
  • Instead, a write whose Origin isn't this machine is refused (403): that stops other sites posting into your projects (CSRF).
