D1 Agents: up to 5D2 Solid server render, not simulated DOM or browser prerender

Chosen after costing (1.2): biggest job, but no browser at build or request time, renders per request from a node server, and fixes ui's SSR for everyone.

D3 Replace each host with its rendered root

~40 of 55 families replace cleanly, output == their class-grammar examples (already CSS-tested). Keeping hosts would hide the page: native.css hides undefined ui-root / ui-popup / ui-modal. See 1.3.

D4 List-item families wrap in <li>

card in cards, feed event, list item, step: their host's role=listitem has no valid place on an <article> / <a> / <button> root, and ul > div is invalid. Costs CSS like .ui.cards > li > .card.

D5 Nested isolation: data-ui on roots + @scope

Flattener marks each component root data-ui="<noun>"; each sheet wrapped @scope ([data-ui="menu"]) to ([data-ui] > *). No new browser floor: anchor positioning already needs Firefox 147 / Safari 26, and packages/ui/docs/plan.md lists @scope as assume-present. Vue-style per-element attributes not needed. See 1.4.

D6 Page CSS in a layer before ui

@layer page, ui;: component wins conflicts, page fills gaps. Unlayered page CSS would beat every ui.* layer.

D7 spell CLI command, not a yarn script

spell static in packages/cli; yarn only wraps the CLI.

D8 Server code stays out of client bundles

Separate @spell-app/ui/server entry and fork server helper; client gets only isServer guards (dead code in the browser build). Budget under 1 kB min+gz, yarn measure before / after.

D9 Fork server module: hooks register, never run

@spell-app/solid-element/server's ServerElement: attach() gives a linkedom element the fork's bookkeeping, props() converts attributes as the element would, run() makes it current + ElementContext. So onConnect() / onFormReset() register instead of throwing: no guards needed in PartContext or FormElement.

D10 hostEffect(): host-writing effects apply at once on a server

Solid's server build runs an effect's compute only, never its apply, so host ARIA (internals.role = "listitem") was never set. UIElement.hostEffect(compute, apply) ~== createEffect in a browser, applies once on a server. Used in UIItem, UICard; the rest in P3.

D11 ServerRuntime, not UIRuntime, in node

UIRuntime's constructor registers the foundation with new CSSStyleSheet(). ServerRuntime installs the real browser, ids, i18n, vocabulary, icons and a no-op styles; any other service throws, naming itself.

D12 A role=list root holding <li>s becomes <ul>

<ui-cards>' root is <div role="list">; once its cards are <li>-wrapped (D4) the flattener re-tags it <ul>, attributes kept.

D13 Host states as data-state, author content as data-ui-slotted

The flattener writes every host state as data-state="a b" (:state(x) => [data-state~="x"]; in-* also as classes), and marks each slotted element data-ui-slotted. The scope limit is [data-ui-slotted]:not([data-ui]) > *, :scope [data-ui] > *: slotted author elements and other components' roots are in scope (as ::slotted() reached them), their insides aren't.

D14 List item wrappers: display: contents, child combinators step over them

<li data-ui-li> is display: contents (the card stays the flex child), the slotted marker goes on the item's root, and in the sheets of cards / list / feed / steps / items each A > B also matches A > [data-ui-li] > B (at most 3 per selector: 2^n variants).

D15 Host-only rules move to @layer ui.reset

A host rule (:host { --ui-color: initial }) and the root's own rule (.ui.red, in ui.tokens) were on different elements; now they share one, so the host rule moves to the first layer and every later layer still wins. Their display is dropped (the host box's).

D16 Page sheets lose their shadow-only selectors; reset.css is scoped to [data-ui]

The foundation's :host token defaults never match on a page; reset.css only ever applied inside shadow roots, so it's rewritten and scoped to every component.

D17 Static parity renders through a second, SSR-only Vite server in vitest's ssr posture

yarn test:visual --static serves /static/<family>/<example>.html from the visual dev server (tools/visual/StaticPages.ts), but renders through its OWN middleware-mode Vite server with mode: "test" + test.environment: "node". Why: @solidjs/vite-plugin compiles JSX with generate: "ssr" only in test mode or with its ssr option; the dev server's plugin compiles every module dom, even for ssrLoadModule, and Solid's server build then throws "Client-only API called on the server side". Its ssr option would change the element pages' compile too (hydratable). Plus ssr.noExternal: ["solid-js", "@solidjs/web"] (the plugin adds it outside test mode, vitest inlines them itself): external, node resolves solid-js's own imports without development and mixes builds ("Cannot set properties of undefined (setting 'server')"). P5's spell static will hit the same two.

D18 Selectors anchored with :where(:scope, *)

Fixes I3: inside @scope, a selector without :scope is read as a descendant of the root, so .ui.card never styled the card. StaticSelectors.anchor() adds :where(:scope, *) to the subject: no specificity, still bounded by the scope. (The agent's experiment, measured: card / segment / section heights then match.)

D19 Adopted sheets recorded per render: scope roots and layer order

Fixes I4: StaticRender.sheetUsage records each element's sheets() (a new public UIElement method). A sheet is scoped to every noun seen adopting it (items take ui-list.css), and sheets are emitted in an order keeping every adoption order (StaticStylesheet.ordered(), a topological sort): in the item's shadow root the list's sheet came AFTER the item's, so its layers won (--_ui-item-media: image vs 1).

D20 A <div> list item root becomes the <li>; only <article> / <a> / <button> roots are wrapped

Refines D4 / D14: a wrapper hides an item's siblings, so :first-child and .item + .item broke (every list item got the first item's padding). Wrapped roots remain (cards, link items): their position pseudo-classes are tested on the wrapper (StaticSelectors.hostPosition() / wrapperPosition()).

D24 Families allocate the ids their ARIA needs on the server (UI.ids)

Element reflection doesn't exist in a static render, so a family that relates two elements gives the target an id from UI.ids on the render's parsed copy (which the flattener moves to its root) and writes the idref: tab buttons aria-controls their pane (ui-tab-N), a dialog aria-labelledby its header shorthand or slotted heading (ui-modal-heading-N), a popup's target aria-describedby (tooltip) or aria-controls + aria-haspopup=dialog (click; no aria-expanded: a native invoker reports it). Exclusive accordions get a page-unique <details name>. NOTE: Ids.next() skips ids already in document, which node lacks: a hand-written ui-tab-3 could collide (P4's allocator).

D25 Server memos that read other elements' controllers are lazy

A server memo computes ONCE (createMemo in solid-js's server build), and StaticRender builds controllers in document order, so an eager memo in <ui-tabs> saw its panes without controllers (no tabs) and a pane saw its later siblings without them. { lazy: isServer } (UITabs.serverLazy, UITab.state): first computed at render time, unchanged in a browser.

D26 Host-is-the-box families hide their static root with their own CSS

D15 drops display from host-only rules, so :host(:not(:popover-open)) / :host(:state(inactive)) no longer hid a popup or an inactive shape side. Each family adds a rule that never changes the element: .ui.popup[popover]:not(:popover-open) { display: none } (inside the shadow root the HOST has popover) and :host(:state(inactive)) > .side { display: none } (the host is already hidden). The static popup root carries popover (auto for click popups, manual otherwise) for P4.

D27 Static <ui-form> merges the author's <form> into its root

Server render only (UIForm.mergedForm): when a <form> is the host's only element child, it is unwrapped and the root becomes <form class="ui … form"> with the author's attributes (class after ours). Why: Fomantic's own markup; the author's form was a slotted element, so the form sheet's @scope stopped at it (D13) and state messages inside (.ui.form .error.message) never matched -- ui-form/states 10% -> 4% (rest: ui-message's own spacing). A form AROUND <ui-form> stays, root a <div>.

D28 Form controls write their native submission attributes themselves, server only

Each form control's staticControl() (or staticRadio() / staticOption() / staticValues()) returns {} in a browser and, on a server: name, the starting value, checked / selected on the native control (input, textarea, checkbox, radio, select + options, rating radios, search input, calendar field), or hidden inputs where the control is no form control (dropdown: one per value; slider: two for a range; inline calendar). So a static form submits natively. Spread onto the control: the browser render is unchanged (an empty spread). The native control is marked data-ui-control for the flattener (see the todo).

D29 Static ui-table: the author table is its own @scope root; data mode renders inside the scroller

On the server UITable.decorateStatic() writes the author <table>'s mirrored classes (TableClassMirror.mirrored()), aria-sort and data-ui="table". Why the marker: ui-table.css is a PAGE sheet in the browser, reaching every cell, but statically the slotted table's insides fall outside the scroller's @scope (D13). As a second scope root the sheet reaches its cells; the host-only rules (container-type, token resets) then also land on the table, measured harmless (collapsing / fixed / scrolling tables identical). Data mode (rows / column-defs JSON attributes) renders its table inside the scroller, classes and aria-sort written, rows sorted. (Agent B)

D30 Static ui-root: a plain, never-hidden wrapper

UIRoot.serverRender(): a <div class="ui [size] root"> with data-state="ready [light|dark] [box]", styled inline as the browser styles the host (display: contents unless a box; else RootBox's width / height / --ui-scale, content in the named scrolling region). No loader, no skeletons, no hidden slot. RootBox checks lengths with a strict pattern on the server (no CSS.supports() in node). The ui-loader / ui-placeholder side-effect imports moved from LoaderMessage / PlaceholderSkeleton to the root's barrel: UIRoot.tsx threw on import in node (customElements). (Agent B)

D31 Host-margin groups: the root-zeroing rule skips static roots ([data-ui])

ui-items.css puts the group's outer margin on the HOST and zeroes the root's (:host(:state(items)) > .ui.items { margin: 0 }). Statically root == host, so that rule (components layer) beat the host margin (ui.reset): every items group lost its 1.5em. D32 Static dropdown: rows rendered, menu closed (an open one plain, not a popover)

On a server <ui-dropdown> renders its rows whatever open says (the options' text is in the page), drops its <ui-item>s (no default slot), and leaves the menu a closed popover. An open dropdown's menu has no popover: nothing can show a popover without JS, and the sheet shows a plain menu under an active root (Fomantic's static markup). Rich items still fill their rows' named slots. SlottedItems reads item attributes, never properties, on a server (linkedom has no :defined, and the items' hosts are built after the dropdown's), and imports itemVocabulary from its file, not the ui-item barrel (that calls customElements.define; the dropdown / select barrels still import it for the side effect).
