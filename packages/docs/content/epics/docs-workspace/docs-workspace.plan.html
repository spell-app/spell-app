Move every doc into a packages/docs workspace of hand-authored .html pages on @spell-app/ui, with templates and a docs index. Then add /plan-doc <name>: each planning session keeps a live plan doc like this one, built and kept current by yarn plan-doc.

  • <topic>/<topic>.html + <topic>/experiments/: one folder per doc
  • templates/: durable, cheat sheet, plans/plan.html + plans/plan-doc.md
  • plans/<name>/<name>.html: one per /plan-doc session
  • index.html: lists written by yarn docs:index
  • _assets/: one classic bundle (Solid + @spell-app/ui + runtime), page and plan CSS
  • Opens from file://: no server, so ONE classic script, no ES modules.
  • Icons bundled at build time, UI.icons.register()ed; packs dropped, since they can't load from disk.
  • Runtime builds the contents sidebar from the headings at load (D3).

Aside: why a script, not hand edits?

Ids, icons, UPDATE markers and the "updated" stamp must agree across the phase list, the phase sections and the items. Agents editing by hand drift; the script also locks the file so parallel agents take turns.

C1 Renaming the session from a skill

When this plan was written, a skill had no way to rename the Claude Code session or its VS Code tab. The /plan-doc skill had to ask you to type /rename yourself.

  • Claude can't run /rename: it's a command only you can type.
  • So a new planning session kept its first prompt as its title until you renamed it.
  • Looks done or obsolete: the /title skill now queues a title with spell dev session title <title>, and a UserPromptSubmit hook applies it on your next message; the prompt-gate.mjs hook also renames the session on /isolate <name> and /epic <name> (checked 2026-10-04).

Net effect:

  • you no longer need to type /rename after starting an epic
  • the new title shows only on your next message, not at once
C2 Unpushed work missing from a new plan worktree

Claude Code's own EnterWorktree made the new worktree's branch from origin/main, not your local main. Anything you'd committed but not pushed was missing from the plan's worktree, and you'd notice when a fix you'd just made wasn't there.

  • Looks done or obsolete: the WorktreeCreate hook, .claude/hooks/worktree.mjs, now makes every worktree from local main ("unpushed work included, not origin/main", its header says) (checked 2026-10-04).

Net effect:

  • a new epic's worktree starts from what's on your local main, pushed or not
C3 Checks lost when pages stopped being converted

The docs used to be generated by a converter, which checked its own output. Now the pages are hand-written .html, so that self-check is gone, and a broken page is caught only by the separate checkers.

  • Three checkers cover most of what the converter checked:
    • doc-links.py --check: every local link resolves (now doc-links.js)
    • check-spell.js: the page renders in a browser, with no console errors
    • plan-doc check: a plan doc's structure and links
  • Not checked: exactly which checks the old converter ran, so what "most" leaves out.

Net effect:

  • nothing changes: an accepted limit
  • run the three checkers after editing a page by hand
C4 Each plan-doc command takes about a second

Every yarn plan-doc command takes about one second, so a session that adds ten items one at a time waits about ten seconds.

  • Where the time goes:
    • starting yarn and node
    • running oxfmt on the doc after each edit
  • Example, measured 2026-10-04: yarn plan-doc check docs-workspace --here --no-browser took 1.05s wall-clock, and it doesn't even edit.

Net effect:

  • nothing changes: an accepted cost
C5 Two spaces after a period don't survive in pages

The house style puts two spaces after a period. In the text of an HTML page, oxfmt squeezes them to one, so a page's source never keeps them.

  • Example, run 2026-10-04: <p>One.  Two  three.</p> comes out of oxfmt as <p>One. Two three.</p>.
  • A browser shows one space either way, so only the source is affected.

Net effect:

  • nothing changes: page text uses single spaces
C6 Running epics missing from the main docs index

A plan doc lives in its epic's worktree until the branch merges. So the docs index on the main checkout didn't list a running epic until after the merge.

  • Looks done or obsolete: the main checkout's page server now serves every worktree under /worktrees/<w>/, and the docs index lists running epics first in its Epics section (Page Server, "Running epics") (checked 2026-10-04).

Net effect:

  • a running epic shows in the main docs index while its worktree is still open

T2 A docs server with live reload

When this plan was written, a page shown in Chrome was refreshed by an AppleScript reload after each edit. The idea: consider a docs dev server that reloads the page by itself instead.

  • Looks done or obsolete: the page server (yarn server) now pushes changes to open pages (LiveReload + liveClient.ts in packages/server), and a plan doc updates in place. AppleScript is still used, but only to open or reuse the Chrome tab (pages.js) (checked 2026-10-04).
I1 An expand arrow on titles with nothing to open

Every ui-accordion title gets an expand arrow, even when its panel is empty. You'd notice it in a contents sidebar: a section with no sub-sections offers to open into nothing.

  • Cosmetic: nothing breaks.
  • Recorded as finding 17 in spell-ui-findings.md, with the repro: <ui-accordion><ui-title>Leaf</ui-title><ui-content></ui-content></ui-accordion>
  • No workaround yet; the old static sidebars had the same arrow.
  • Suggested fix there: hide the arrow and skip toggling when the content is empty, or a leaf attribute on ui-title.

Net effect:

  • once fixed in @spell-app/ui: a title with an empty panel shows no arrow
