Thingverse

Standard libraries of everyday ideas (people, bank accounts, invoices, calendars) that teach spell new words.

Status: draft · first pass, not yet talked through Updated: 2026-10-01 Notes for agents: thingverse.md

1. Summary
  • The idea (2017 talk): "concept libraries" like Bank Account that extend the language when you import them: a person's vocabulary, not a programmer's API.
  • Today: one library, @library/cards (cards, decks, piles, jokers). Imports work through compiled JavaScript that carries the phrases it declares.
  • Foundations first: dates and times, money, maps, saving data, and the type work in syntax.

2. Today
  • Library: packages/spell/projects/system/library/cards; used by Solitaire-import.
  • How imports work: compiled JavaScript with /*! SPELL: DECLARES {...} */ comments, so a project learns another's phrases without its source.
  • Known bug: importing a project also runs its top-level code.
  • The runtime lacks: date and time, money, map and record types; saving and loading; networking.
  • Old sketches (background only): products, prices and discounts; an invoice with "the current user", an address book and email; dates like "30 days from now"; a Registered aspect that teaches the person named Alice.

4. Ideas
  1. I1 A library is a vocabulary import people, and spell understands "the people whose birthday is this month"
  2. I2 Things you can name the Registered aspect: keyed collections, "the person named Alice"
  3. I3 Borrow from schema.org Person, Event, Invoice, Place are already well described
  4. I4 Plurals for free defining a person defines people, and phrases for both

5. Questions
  1. Q1 Which three things first? follows from audience/Q1details

    Suggestion (for the tinkerer): dates and times, money, and a "collection" (things you keep, with photos and notes).

  2. Q2 Where does data live? files in the project? a local database? the cloud?details

    Suggestion: a file per collection inside the project folder (JSON or SQLite), so it's yours, it's visible, and it moves with the project.

  3. Q3 How do libraries change over time? versions, and what happens to spells that use an old one
  4. Q4 Is "thingverse" the right name? Thingiverse (3D models) is one letter awaydetails

    Fine as our working name; risky as a public one. Alternatives: "spell library", "the commons", "words", "almanac".

6. Risks
  1. R1 The Thingiverse name clash confusing at best; a trademark question at worst
  2. R2 More phrases, more ambiguity every library adds words that can collide
  3. R3 Saving data is a big design formats, changes to a thing's shape, sync
