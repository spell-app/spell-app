<Section title="Owned parts">
  A generic part styles itself by its OWNER, not by a per-owner tag:  there is no `ui-card-header`.  The part finds its
  nearest owner and sets `:state(in-card)`, `:state(in-modal)` ... on itself, and `ui-parts.css` keys on that state.  So
  the same markup reads differently in each owner:

  <Example title="A header in a card" description="Inside a `<ui-card>`, the parts are the card's header, meta, description and extra.">
    <ui-card>
      <ui-content>
        <ui-header>Elliot Fu</ui-header>
        <ui-meta><span>Friend</span></ui-meta>
        <ui-description>Elliot is a film-maker from New York.</ui-description>
      </ui-content>
      <ui-extra>22 Friends</ui-extra>
    </ui-card>
  </Example>
  <Example title="One meta, four owners" description="The same `<ui-meta>` in a card, an item, a feed event and a comment:  each owner styles it its own way.">
    <ui-card>
      <ui-content>
        <ui-meta><span>Joined in 2013</span><a href="#friends">Friends</a></ui-meta>
      </ui-content>
    </ui-card>
    <ui-items>
      <ui-item>
        <ui-content>
          <ui-meta><span>Description</span><span>Stevie</span></ui-meta>
        </ui-content>
      </ui-item>
    </ui-items>
    <ui-feed>
      <ui-event>
        <ui-content>
          <ui-meta><a href="#like">4 Likes</a><a href="#reply">Reply</a></ui-meta>
        </ui-content>
      </ui-event>
    </ui-feed>
    <ui-comments>
      <ui-comment>
        <ui-content>
          <ui-author href="#matt">Matt</ui-author>
          <ui-meta><span>Today at 5:42PM</span></ui-meta>
        </ui-content>
      </ui-comment>
    </ui-comments>
  </Example>

  Outside any owner, `ui-content`, `ui-description` and the rest are unstyled blocks, and a standalone `ui-header` is
  Fomantic's `ui header`.  The owners are [card](../ui-card/), [items](../ui-items/), [feed](../ui-feed/),
  [comment](../ui-comment/), [statistic](../ui-statistic/), [step](../ui-step/), [message](../ui-message/), [modal](../ui-modal/),
  [popup](../ui-popup/) and [list](../ui-list/), with more as families land;  each part's `:state(in-*)`
  table below lists the owners it knows.
</Section>

<Section title="Behaviour">
  `ui-header` is the one part with its own attributes (`level`, `size`, `sub`, `icon`, `dividing`, `block` ...).  The
  others take few or none.  An owner's `ownsParts` list, in its own vocabulary, is what lets the part find it.

  <VocabularyTable family="ui-parts" />
</Section>

<Section title="Theming">
  A standalone header's tokens are public (`--ui-header-*`):  set one on the element, on any ancestor or `:root`,
  or through `::part(header)`.

  Inside an owner, a part's look comes from the OWNER's tokens (`--ui-card-header-color`,
  `--ui-modal-header-size` ...):  set them on the owner or above it, and every part inside follows.  Owners also
  hand their parts private layout switches (`--_ui-card-layout: horizontal`), so a part never needs to know its
  owner's markup;  never set those.

  <CssTokens family="ui-parts" prefixes={["--ui-header-"]} />
</Section>

<Section title="Accessibility">
  - A `ui-header` with `level` renders a real `<h1>` ... `<h6>`, so it belongs in the document outline.  Without
    `level` it is a `<div>` that only looks like a heading, so pick a level whenever it labels a section.
  -   - A slotted `<ui-icon>` is decorative unless given a `label`;  an image inside a header needs its own `alt`.
  - `sub` and `disabled` are visual.  `disabled` does not remove the header from the outline.
  - The other parts are neutral blocks with no role;  their meaning comes from the owner and from the semantic
    elements you put inside them.
  - A linked header with a `level` is `<a role="heading" aria-level>`, so it is both a link and a heading.
  - Without JavaScript the native fallback renders the same part elements (`<h1>` ... `<h6>` for a leveled header)
    around a slot, so the text and outline stay;  only the owner-context styling (`:state(in-card)`) is lost.
</Section>
