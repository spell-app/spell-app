<Section title="Behaviour">
  A sticky IS CSS `position: sticky` (Fomantic's `native` type):  no scroll listener, no script positioning,
  nothing to measure.  `offset` and `bottom-offset` become its `top` and `bottom`;  `pushing` also sticks it to the
  bottom edge.

  The host has no box of its own (`display: contents`), so the sticky sticks within its PARENT, and the end of that
  parent pushes it out.  Fomantic's `context` setting (any element) has no CSS equivalent:  put the sticky inside the
  element it belongs to, such as a [rail](../ui-rail/).

```html
<ui-rail position="right"><ui-sticky offset="60">Table of contents</ui-sticky></ui-rail>
```

  What the element adds is reporting.  It keeps `:state(stuck)` while stuck and `:state(bound)` while pushed out by
  the end of its parent, and fires `ui-stick` / `ui-unstick` (with `{ edge }`, `top` or `bottom`) as that changes.
  It watches with an `IntersectionObserver` on two 1px markers, against the nearest scroll container (else the
  viewport).

```css
ui-sticky:state(stuck)::part(sticky) {
  box-shadow: 0 2px 4px oklch(0 0 0 / 0.15);
}
```

```js
document.querySelector("ui-sticky").addEventListener("ui-stick", (event) => console.log("stuck to the", event.detail.edge))
```

<Section title="Theming">
  Theme with the public `--ui-sticky-*` tokens on the sticky or any ancestor;  `::part(sticky)` works too.  Style
  the box through `::part(sticky)`, and a stuck one through `:state(stuck)`.  The offsets come from the `offset` /
  `bottom-offset` attributes;  `--ui-sticky-offset` / `--ui-sticky-bottom-offset` are for class-grammar markup only.

```css
ui-sticky {
  --ui-sticky-z-index: 50;
}
```

<Section title="Accessibility">
  - A sticky changes nothing for assistive technology:  its content stays where it is in reading and Tab order.
  - Stuck content covers what scrolls under it, so while stuck the element RESERVES its room:  it sets its scroll
    container's `scroll-padding-top` (`-bottom` at the bottom edge) to the lowest stuck edge.  Focus moves,
    `scrollIntoView()` and Page Down / Space (Chromium, Firefox;  Safari pages the full viewport) then keep content
    out from under it.  A sticky column (taller than half the view, or narrower than half its width) reserves
    nothing.  Keep stuck content small all the same.
  - If the element can't render, its native fallback still sticks (it's CSS);  only `:state(stuck)` and the
    events are lost.
</Section>

<Section title="Framework usage">
  Nothing to bind:  put it in the template, and listen for `ui-stick` / `ui-unstick` if you need to know.

```jsx
// React 19
<ui-sticky offset={60} onui-stick={() => setStuck(true)} onui-unstick={() => setStuck(false)}>...</ui-sticky>
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-sticky offset="60" @ui-stick="stuck = true" @ui-unstick="stuck = false">...</ui-sticky>
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<ui-sticky offset="60" ref={(el) => el.addEventListener("ui-stick", () => setStuck(true))}>...</ui-sticky>
```

</Section>
