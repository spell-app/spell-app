Binding power

P2 / D21: the smaller design replaces the design doc's (OperatorExpression, {x:operand}, kept alternatives).

  • precedence keeps ONE job: which whole match wins a Choice. New bindingPower, on operator (suffix) rules only: how tightly they bind, read by the existing shunting-yard.
  • compound_expression becomes THE expression rule: a single_expression (today's simple_expression, D22), then suffixes, stopping at a bound. Parsed once per level, not twice.
  • Slots: a list prefix's last slot is {list:single_expression}; absolute value / round take {expression:arithmetic_expression}; statements and slots closed by a word keep {expression}.
  • Give-back in Sequence: a word that fails because the slot before swallowed it re-parses that slot shorter. Fixes remove the card of the pile. ~35 lines, the only core change.
  • The model: Parser Model.

A datatype on every match

  • Rule.getDatatype(match); scope lookups stashed in parse(), like scopeVar.
  • Spell words only (text, choice, list of cards), never JS ones.
  • TypeScope: item type, getMember() with super-type walk (moved from the LSP), real method records. Built-in types become real types with member tables.

Signatures, calls, members

  • Paren-free typed parameters: to add a card to a pile.
  • Call rules reject a confident type mismatch: put the chip on the pot picks Chip's.
  • Multi-word member names, resolved through the type they're read from.

Exclusive lists

  • a pile is an exclusive list of cards: adding a card to a pile removes it from its previous pile; the pile of a card comes for free. Pile.spell's to move goes away.

Q2 Paren-free signatures: `a|an <known type>` is a parameter, `the ...` is words? → D2

Today every bare word in a signature is a keyword; only parens make a parameter:

today 
to give a card to a pile     =>  export function give_a_card_to_a_pile() {}

Proposed rule:

  • parens still work, and are needed for untyped (message), defaults, (with …)

Q3 OK that operators change meaning: `x + y is empty`, `the absolute value of x + 1`? → D3
