Epic Review

/epic review [<name>] walks an epic's open items with Owen, one section and one item at a time, and records each answer in the plan doc as it's given. For whoever runs, changes or extends it.

Written for: Claude sessions running a review, and whoever changes the skill or plan-doc Status: built Plan doc: epics/epic-review; the rules: .claude/skills/epic/SKILL.md, section 7
  • Plan docs pile up open items: caveats, todos, issues, questions, judgement calls, things to test. Nothing recorded which ones Owen had already gone through.
  • A review picks a section, Owen ticks the items on a details page, then each comes up in chat: the item as clean bullets, then a modal to accept, explore, explain further, or defer.
  • Every answer lands in the plan doc at once, and the item is marked reviewed, so the next review starts where this one stopped.
  • Work an answer calls for goes on the epic's to-do list; the next review offers to start it in its own worktree.
  • The docs index shows every epic, running and merged, in one Epics list, each with its state and an Open | All filter.

Every modal is headed Epic Review: <name>, asks one plain question, and never shows a bare id: Owen comes to a review cold, with 5+ epics on the go.

  • A details page (yarn details new ... --from a spec that yarn plan-doc items <name> --section todos --spec <file> writes), titled "Choose todos to review", no site header.
  • Each card in two columns: the tick box, a (?) "Provide more details", and a state icon (orange circle: not reviewed; grey pause: deferred; green check: reviewed; blue list: to do); then the title and the item's whole text from the plan doc, its links rewritten to work from the page.
  • Select all / Select none (one button), and Open | All: Open hides the reviewed ones.
  • The answer names the ticked ids, and More details wanted on: the (?) ones: those skip the short version and start with the full explanation.
  • A details page: plain words, the real code, a table, the options side by side. Kept with the epic (epics/<name>/details/) when this checkout holds its live doc, else a scratch page.
  • Then a second modal: up to two options, recommended first, then Defer and Exit. Choices that don't fit a modal are answered on the page.
Mark Means Label, after the item's id
data-reviewed="2026-10-03" gone through with Owen; the outcome is in the log green "reviewed 10-03"
data-deferred put off; still not reviewed grey "deferred" (date on hover)
data-queued + data-work work a review decided on, not started yet; also reviewed blue "to do" (the work on hover)
  • REVIEWED also counts an item that's struck, decided, or linked from a decision's details, so a doc settled before the marks existed isn't all "not reviewed".
  • Kept current: every /epic session marks the items it talks through with Owen. Older docs: a one-off yarn plan-doc backfill finds items Owen named in past sessions (his messages, modal answers), a dry run unless --apply.
yarn plan-doc ... · review commands 
list [--json]                                every epic (main + worktrees):  status, not reviewed / items
items <name> [--section s] [--filter f] [--json]   where reviews stand, the to-do list, sections
items <name> --section s --spec <file>      the item picker, as a details page spec
review <name> <id> ["outcome"]             mark reviewed today;  the outcome goes in the log
defer <name> <id>                         put off;  still not reviewed
queue <name> <id> "work"  /  unqueue       on / off the to-do list
backfill <name> | --all [--apply]           one-off:  what past sessions show Owen went through
  • Every command but new edits the epic's LIVE doc: its own worktree's, else the main checkout's, else the first worktree that has it. Never the copy a worktree took of an epic merged before it was cut.
  • The prompt hook lets /epic review ... through untouched (review is a reserved epic name): a review runs from any window, and keeps the session's name.
  • One Epics section: yarn docs:index writes the merged epics' cards and a slot; the main checkout's page server (RunningEpics) fills the slot with the running ones, dropping a merged card of the same name.
  • Each card's title starts with its state: [3/6] in progress, a green check done, a blue thought bubble planning, a yellow pause stalled (phases left, no update for 3 days).
  • Open | All on its title, and on every plan doc's item sections: Open (the default) hides the done ones, with "12 hidden · show all" under them; remembered per page.
  • A details page to pick items, not ids typed in chat. Owen ticks; nothing to remember or type. The first design had him type "I4, I5" or filter words.
  • The item's whole text on the picker. One-line summaries were too dense to parse; long ones clamp at 150px with Show more.
  • Fast by default. The item as bullets and one modal; the full explanation only when Owen asks (Explain further, or the picker's (?)).
  • Work is never done mid-review. It goes on the to-do list, so a review stays quick; "Start work" opens it in its own worktree.
  • Every plan-doc command edits the live doc. From main, a review of a running epic would otherwise fail on decide or close, or edit a stale copy.
  • Modals hold four options. So the epic picker pages two at a time with More, the section picker shows three, Exit is typed in Other on the item modal.
  • A mockup first. The interaction was clicked through on canned data and reshaped six times before any real state existed.
  • Backfill is heuristic, and finds little: Owen rarely types item ids. The marks sessions add from now on matter more.
  • A review from a worktree session of an epic whose doc is on main edits main's file but can't commit it there: Finish Review says which checkout holds uncommitted marks.
  • A merged epic's "stalled" is judged when docs:index last ran; running ones on every load.
  • "Start work" ends the review's turn (the session moves to the new window); /epic review <name> picks it up again.
  • A details page replaces the plan doc in the side bar until the review reopens it.
