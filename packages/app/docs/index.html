The App's Components Every component the spell app is built from, by where it sits, and a page for each.

The spell app is its editor, its runners, and two web components any page can embed. All of it is drawn by the components below: Solid components on Spell UI's widgets, and the two web components on top.

Written for: anyone changing the spell app, or putting spell programs in a page Live where a component can be drawn alone (the web components, the runner's pieces); a picture of the editor otherwise The app's notes: AGENTS.md

The two tags a page can embed, with no editor app around them:

  • <spell-app>: runs a spell project
  • <spell-editor>: edits one, and runs it in the <spell-app>s beside it

Every editor page is a box of panes, with menus along their tops:

  • SpellPage: a whole page's box
  • SplitPanel: panes side by side, or one above the other
  • AppRoot: the running program, under its toolbar
  • AppContainer: the box the program draws in
  • Chrome: the menus and toolbars around the panes

What the panes show, besides the code:

  • ThingExplorer: the things a running program has made
  • TypeExplorer: the scopes a project parses in
  • ScopeDetailsPane: the details of the scope picked there
  • Markdown: a docstring, drawn
  • TreeViewer: the spell tree of the line the cursor is on
  • ConsoleViewer: what programs print, in the editor
  • ConsoleLines: the lines every console draws

The code editors, all Monaco, loaded the first time one shows:

  • InputEditor: the spell source of the open file
  • OutputEditor: its compiled javascript
  • MonacoEditor: a Monaco editor, which the others are
  • FileEditor: one on a spell file, kept in step with it

Picking a project or a file, and doing something with it:

  • FileDropdown: the open project's files
  • ProjectDropdown: every project
  • Actions: the editor's actions, as menu items or buttons
  • Chooser: a dialog to choose from a list

Telling people what happened:

  • Notice: something worked
  • ErrorNotice: something didn't
  • ErrorBoundary: a part of the page broke, and the rest goes on

What every runner draws around a program: a <spell-app>, VS Code's "Run Project", and the editor's own:

  • RunnerSplit: the program above, the debug pane below
  • RunnerPane: a pane with a toolbar of tabs
  • RunnerConsole: one program's console
  • SpellElement: a drawable thing, drawn as its own element

The pages live beside the web components' code, so a component's page changes in the same commit as the component:

  • Each page's props, attributes and "Used in" tables come from the code itself: yarn site:data in packages/app reads every documented component's banner and props, and where the app draws it.
  • The pictures are headless screenshots of the editor: yarn site:pictures, with the editor running.
  • The live examples need the app's element build: yarn build:element in packages/app.
  • A new page: add it to the set's hand-kept facts, pages.json5, run yarn site:data, then copy a page like it (Notice for a picture, <spell-app> for a live one) and link it here.
