C1 Answers need a page server started after the merge

A details page sends your answer to a route on the page server. The main checkout's server has that route only once this branch is merged and the server restarted; until then, Send fails there.

  • Why: the main server serves worktree pages too, but loads its route modules once, when it starts.
  • The route: scripts/detailsRoutes.ts, which writes <slug>.answer.json beside the page.
  • Until the merge and restart: test against the worktree's own page server.
  • What Send says on a server without the route: "This page server can't take answers yet: answer in chat."

Net effect:

  • restart the main checkout's page server once after this merges
C2 Reload a page before Send if the server restarted

A details page that was open while the page server restarted can't send until you reload it.

  • Why: every send carries the server's write token (x-server-token), and the token changes each time the server starts.
  • What you see, from _assets/details.js: "The page server restarted since this page loaded: reload the page, then Send again."
