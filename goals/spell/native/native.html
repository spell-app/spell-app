Native apps

Spell as an app you download and double-click: Mac first, then Windows.

Status: draft · first pass, not yet talked through Updated: 2026-10-01 Notes for agents: native.md

1. Summary
  • Nothing exists yet: no Electron or Tauri, no installer, no signing. Running spell needs Node, a clone and yarn start.
  • Good news: the compiler runs in the browser and the server only does file I/O, so a desktop shell mostly swaps the /api for local files.
  • The choice: Tauri (small, the system's web view) or Electron (large, the same Chromium everywhere, Node built in).
  • Target: a signed, notarized Mac app in December; Windows next.

2. Today
  • 2020 plan: "Install as local app via Electron" (packages/spell/thoughts/site-structure.md).
  • The server: express /api over packages/spell/src/node/project-utils.ts.
  • Projects: environment.ts puts them inside the source tree (packages/spell/projects).
  • Docker: removed on 2026-09-30.

5. Questions
  1. Q1 Tauri or Electron? size and memory, or Node in-processdetails
    • Tauri: ~10 MB, the system web view (WebKit on Mac), Rust for native bits.
    • Electron: ~150 MB, Chromium everywhere (matches what we test), and the cli and language server's Node code runs in-process.

    Suggestion: Electron for December: one browser engine to test, and the Node code we have just works. Revisit Tauri when size matters.

  2. Q2 Where do people's projects live? ~/Documents/Spell? iCloud Drive?details

    Suggestion: ~/Documents/Spell, with a "Show in Finder" button.
  3. Q3 Apple and Windows signing do you have an Apple Developer account? a Windows certificate?
  4. Q4 Everything works offline? except AIdetails

    Suggestion: yes. It's software you own (motivation/I3).

  5. Q5 Does the app include the cli and VS Code bits? e.g. "Install the spell command" from a menu

6. Risks
  1. R1 Signing rabbit holes notarization, entitlements, certificates: start early
  2. R2 Two storage worlds drift apart browser storage and files behaving differently
  3. R3 Download size Monaco, the parser and the runtime, on top of the shell
