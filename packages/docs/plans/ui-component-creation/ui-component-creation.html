3.3 Icon packs
  • Icons are SVG files in packs: a folder of SVGs + a generated pack.js index (file, size, aliases). Built-in: fa7-free (default), fa7-brands, fomantic.
  • UI.icons (runtime, page-wide): use(), reset(), resolve(), get(), peek(), register(); <ui-icon-set src> from HTML. Design: packages/ui/docs/icons.md.
  • Contract: get() never rejects -- a missing icon draws nothing. Broken today (I1), fixed in P2.
  • Single-file (IIFE) pages: packages/docs/scripts/bundle-spell-ui.js calls reset() + register() for the icons it bundles, so nothing is fetched.

5. Issues
  1. I1 UI.icons.get() can reject, though documented never todetails

    BuiltInPacks.url() throws Invalid URL when BuiltInPacks.base is empty (IIFE bundle), inside IconPacks.add(), reached from ready, so get() rejects. IconGlyph.load() is fire-and-forget: every icon becomes an unhandled page error. Fix in P2.

  2. I2 yarn test:hmr broken since the move: $/ui alias not resolved from ?inline sheetsdetails

    Vite 8's resolve.tsconfigPaths only resolves aliases for TS / JS importers; solidElementHot() injects $/ui/elements/HotDefinitions into the .css?inline modules. Fixed: vite.config.ts injects it by file path. 8/8 pass.

  3. I3 yarn site:build broken since the move: Astro's prerender gets express's cookie 0.7.1details

    Astro 7 inlines its runtime into site/dist/.prerender/ and leaves cookie external, which then resolves to the root's hoisted 0.7.1. Fixed: environments.prerender.resolve.noExternal bundles it. 60 pages. Not caught by CI: CI doesn't run the site build (T6).

  4. I4 Integration: ui-button read UI.browser during render (SSR threw; a button rendered before UI.load() would too)details

    From the invoker work. Fixed: UIButton.invokers() reads UI.browser only when !isServer && loaded(). Accordion has the same pattern: in SUSPECTED-BUGS.md.

  5. I5 Integration: the layout agent rewrote 2 list tests to a nested shadow root that doesn't exist, then reported them as old failuresdetails

    Restored the original selectors; 84/84 list tests pass.
  6. I6 Integration: yarn test:hmr case 5 anchored on render()'s first line, which the invoker work changeddetails

    tools/hmr.e2e.ts now anchors on the signature alone; 8/8.

  7. I7 Browsers: WebKit drops style-query results on ::before/::after after a dynamic changedetails

    In WebKit (Playwright 26), a @container style(--x: v) rule that changes a PSEUDO-ELEMENT's style is not re-evaluated when the container's custom property changes AFTER first style (set at creation: fine). Probe: nav with inline --l set later; getComputedStyle(span, '::before').content stays stale, while the span's own style updates. Touching the pseudo's originating element (style.setProperty) refreshes it. Affects breadcrumb (divider-icon loads async, so a real Safari bug) and feed (ordered / basic circles). Tests left failing: breadcrumb x2, feed x1. Options: a per-element nudge after a token change, or move the pseudo rules off style queries.

  8. I8 Browsers: WebKit finds no container inside a shadow root above a slot (form)details

    WebKit's container lookup walks shadow-including DOM ancestors, not the flat tree through slots, so a size container that is an element INSIDE a shadow root (ui-form's .ui.form, display: contents host) is invisible to slotted descendants' own shadow trees. Container NAMES are also tree-scoped in WebKit (a name set by :host is not visible from a sibling shadow tree): fixed for grid and items by unnamed queries. ui-form needs its container on a real box host: test 'stacks rows on a narrow form' left failing.

  9. I9 doc-links.py linked <code>/</code> (an operator in a table) to the filesystem root, and linked paths outside the repodetails

    Found re-linking every page. Fixed: code spans with no letter or digit, and paths outside the repo, stay text.

Presentation (U+FE0F) now comes from emojibase's type, not hand-written ranges.

  21. D21 Tokens: inverted group hands a flag to slotted membersdetails

    <ui-segments inverted> flags each slotted host with --_ui-segments-inverted; the member root style-queries its parent. UISegment now writes the inline --ui-inverted only when inverted (an inline 0 beat the sheet). Static twin: .ui.inverted.segments > .ui.segment.

  22. D22 Tokens: lone feed event / comment declare their own aliasesdetails

    Aliases now also declared on :host(:not(:state(in-feed))) / :host(:not(:state(in-comments))); members in a list keep the list's (inverted writes some).

  23. D23 Tokens: tooltip shown-state selector covers visible and delegated focusdetails

    native.css scale rules now share one shown set: hover, focus-visible, data-variation=visible, and :focus-within for non-native hosts (a ui-button host is never :focus-visible itself).

  24. D24 Decision: modal closable=false restores Fomantic closable:falsedetails

    closable="false" = no close icon AND dismissal none, unless closedby is set (wins). closable absent keeps today's behaviour. Fomantic: closable (Escape / dimmer) and closeIcon (icon) are separate settings; the vocabulary says which each maps to.

  25. D25 Decision: ui-button invoker commands (commandfor / command)details

    Forwarded to the inner button (commandForElement resolved from the host root node). UI.browser.supports.invokers; without it a JS fallback (Invoker) runs built-ins and dispatches command. --toggle added to modal / flyout. Popup, dropdown and toast do not yet answer command events (todo).

  26. D26 Decision: label colour matches Fomanticdetails

    Fomantic: a plain .ui.label inside .ui.red.segment (or any coloured owner) is NOT coloured; only its own colour, or its .ui.red.labels group's, paints it. Before: an un-coloured <ui-label> inherited --ui-color from any coloured ancestor. Now: :host in label.css drops the inherited --ui-color* tokens and takes back its group's, handed down as --_labels-color* by the .ui.labels root (statistic's pattern). Class-grammar (light DOM) labels have no host, so a plain .ui.label there still inherits a coloured ancestor's colour. Kept open for Owen (T5).

  27. D27 Decision: popup hoverable, sidebar width, container tokensdetails

    hoverable (default true) on ui-popup; hoverable=false closes as the pointer leaves the target. Sidebar width takes Fomantic words and columns like flyout (word class now after the noun). Container --ui-container-scrolling-height-tablet / -computer / -widescreen (named after the breakpoints the sheet uses, --ui-widescreen, not large-screen / large-monitor).

  28. D28 Layout: card links carry no underlinedetails

    A card's header link and its meta / extra links have text-decoration: none (colour and hover only), as in Fomantic (site.less a { text-decoration: none }). Owen's standing preference. Site-wide links stay underlined (typography.css); only in-card parts opt out (parts.css).

  29. D29 Layout: table stacks by VIEWPORT by defaultdetails

    Fomantic's ui table stacks below 768px of the VIEWPORT (tablet stackable: 992px). The element used the host's own width, so every docs example (~655px column) showed the stacked layout. Now both hosted and static tables use the viewport (@media); an element opts in to its own width with --ui-table-stack-by: container (host, ancestor or page). Open choice for Owen: a vocabulary attribute instead of a token. Removed the docs page's site-note.

  30. D30 Layout: dropdown menu popover is position: fixeddetails

    The .menu[popover] was position: absolute; webkit measured its position-area against the origin screenful of the page, so any dropdown below the first viewport height opened upwards despite room. fixed (the popover default) makes chromium, firefox and webkit agree (probe: dropdown at y=1100, scrolled into view, opens down in all three). A dropdown opened while its anchor is OFF-screen opens upwards in all three (viewport has no room below).

  31. D31 Layout: Items group margin lives on the hostdetails

    A size container (container-type: inline-size) is its own formatting context, so the .ui.items root's outer margin inside the host never collapsed with the heading above (+21px per Items example). The margin (and its first / last-child zeroing) moved to :host(:state(items)). Same cause for grid (celled margin) and possibly cards: DEFERRED (see the next entry).

  32. D32 Browsers: test files run one at a time under UI_TEST_ALLdetails

    Files of one browser share ONE page focus (parallel iframes): with firefox / webkit, Tab / Escape / focus() tests of other files steal it. fileParallelism: !UI_TEST_ALL in vitest.config.ts: the plain single-chromium run keeps its parallelism. Also: commands.emulateReducedMotion (Playwright) replaces the Chromium-only cdp().

  33. D33 Browsers: grid / items container queries are unnameddetails

    WebKit scopes container NAMES to the tree, so a slotted column's shadow tree can't see a host's name. The containers keep their names for page CSS. Checked by the visual run.

  34. D34 Invokers: a press on an element's own invoker button doesn't count as leaving itdetails

    Found by the docs page's live example: after --show, a REAL click on a --toggle button blurred the dropdown (closing it) and the command reopened it. UI.overlays.pressedInvokerOf(); the dropdown's blur skips it. Failing-first test with userEvent.click; the agent's tests used .click(), which moves no focus. Popup checked the same way: fine. The shared step is a class, ToggleCommands.action() (Owen's class-first rule).

  35. D35 Emoji: CLDR wins the 19 clashing names (Q9)details

    Owen, 2026-10-01: he likes CLDR's pictures better. Fomantic's stay reachable by another name (dog_face, memo).

  36. D36 plan-doc open: the tab is named <name> and found by the doc's path in packages/docs; never takes focusdetails

    Owen, 2026-10-01. Any checkout (a worktree) reuses the tab; the page sets window.name; links to a plan doc use target="<name>" (doc-links.py). Fallbacks (Chrome not running, AppleScript refused) may still raise Chrome.
