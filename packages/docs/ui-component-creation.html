  • "Stacking" is Fomantic's word for what a layout does when it's too narrow: things that sit SIDE BY SIDE are put ONE UNDER ANOTHER, so nothing gets squeezed.
    • a table: each row becomes a block, and each cell goes on its own line
    • a form: fields in a row (first name | last name) go one per line
    • a grid: columns become full-width rows
  • Tables: Fomantic stacks when the WINDOW is narrower than 768px (a phone). We had changed that to the table's OWN width, so every table in the docs site's 655px example column showed the phone layout. Fixed: by window again.
  • Kept as an opt-in: a table can stack by its own width instead, for a table in a narrow sidebar on a wide screen. The question was how to spell that opt-in.
  • Decided (Owen, D48) and built (P21): both. The attribute for one table; the token for a whole region, from a stylesheet; the attribute wins.
Attribute (chosen)

<ui-table stack-by="container">

Discoverable, validated by the vocabulary, translatable. container or viewport (the default).

Token (kept, underneath)

--ui-table-stack-by: container

Set on a wrapper or the page: every table inside follows, unless it has the attribute.
  • How: the attribute adds a private class to the inner table (stack-by-container), whose rules undo the token's way and stack the attribute's. Not a host state: in WebKit, a state rule left a LATER table's media queries stale.

  • Some decorations were drawn by a ::before rule that only applied while a setting (a CSS custom property) had a certain value: a @container style(...) rule.
  • When the setting changes AFTER the first paint, Chromium and Firefox redraw the decoration; WebKit (Safari) updates the element but NOT its ::before, so the decoration stayed as it was.
  • Two places hit it:
    • breadcrumb divider-icon="chevron right": the setting flips to "icon" only once the SVG has loaded, which is always after first paint. In Safari the divider stayed EMPTY.
    • feed ordered: numbers in circles beside each event. Turning ordered (or basic) on after first paint left Safari without numbers.
ui-breadcrumb.css · the rule WebKit didn't re-check (before P21) 
@container style(--_ui-breadcrumb-divider-layout: icon) {
  :host > .divider:empty::before {
    content: "";
    mask: var(--ui-breadcrumb-divider-icon) center / contain no-repeat;
  }
}
 A: nudge (not taken)

Keep the rule; after changing the setting, write any inline style on the element, which makes WebKit recompute everything about it, ::before included. 

// LAYOUT:  the divider-layout token
host.style.setProperty(LAYOUT, "icon")
// WebKit: re-check ::before too
divider.style.setProperty(
  "--_nudge", String(++nudges))

Small; but a workaround every future style-query decoration must remember.

 B: no style query on the ::before (chosen)

The element marks itself instead, and the rule matches the mark: a class or custom state, which every browser re-checks. 

/* element:  a custom state */
:host(:state(icon-divider))
  > .divider:empty::before { … }
/* class grammar:  a class */
.ui.breadcrumb
  .divider.icon:empty::before { … }

Same as Fomantic's own markup (<i class="right chevron icon divider">); feed would use the owner-context state it already has (:state(in-feed)).

  • Decided (Owen, D49) and built (P21): B, in a simpler form than sketched. The style query stays, but it matches only the REAL divider element, which sets private values; the ::before reads them through var(), which every engine re-checks.
  • Feed's connecting line, numbers and basic circles work the same way. No WebKit failures left.

  • A new HTML feature (Chrome 135, 2025): a button controls another element by NAMING it, with no JavaScript. commandfor is the target's id; command is what to do.
  • The browser fires a command event on the target. Built-in commands work on native elements (show-modal on a <dialog>, toggle-popover on a popover); custom elements get custom commands, which start with --.
  • Ours: --show, --close, --toggle, each run as if the user did it (the cancelable ui-open / ui-close first).
  • <ui-button commandfor command> passes both to its inner <button>; in browsers without the feature it sends the same event itself (UI.browser.supports.invokers).
  • Who answers: <ui-modal>, <ui-flyout>, <ui-sidebar>, <ui-dimmer>, <ui-popup> and <ui-dropdown> all three; <ui-toast> --close only (a closed toast is gone for good, so there's nothing to show again).
  • A command button sits OUTSIDE the overlay it controls, so a click on it no longer counts as a click outside (that closed the overlay first, then the command reopened it).

  • One element around a page or app. Each ui-* tag inside loads its component the first time it appears; nothing else is downloaded. The page shows once everything inside is ready.
  • It also sets icon packs, emoji names, theme and size for everything inside, and can be a scrolling box or a full-page app shell.

Attribute Does
display while loading: skeleton (default: grey placeholders), when-ready (nothing, space kept), immediately (as things arrive)
loading a spinner with this message while loading (bare: "Loading…")
timeout longest wait before showing anyway: 5s (default), 500ms
icons icon packs for the subtree: built-in ids or pack.js URLs, comma-separated, later wins; added over the outer root's (or the page's)
emoji emoji names for the subtree: cldr (default) or fomantic
assets folder the built-in icon packs load from
theme, size light / dark; mini ... massive
width, height a CSS length or window: the root becomes a box that scrolls its own content (see aria-label)
fixed fills the viewport and stays there: a full-page app shell (scrolls the same way)
aria-label a box's content scrolls in an inner region, part="scroller", a tab stop named by this (else "Content"); name each one when a page has several
  • Events: ui-ready ({ failed }, what didn't load); ui-error per tag that didn't load (no such component, import failed, not ready in time), cancelable to skip the console warning.
  • <ui-icon-set> and <ui-emoji-set> are gone: a page without a root calls UI.icons.use() / EmojiData.use().
  • Loading: which component defines a tag comes from a generated catalog (yarn gen:root after adding a tag), never from guessing at its name. Each component is imported once per page, whatever the number of roots; content added later loads too.
  • Ready: every component imported, then every element inside ready; a nested root counts once it is. Then the content shows, and is never hidden again.
  • Skeletons: each tag's vocabulary describes its placeholder (37 do; parts and wrappers say null). The root draws real <ui-placeholder>s in its own shadow DOM; the page's DOM is never touched.
  • Settings: a nested root inherits what it doesn't set and adds its own icon packs; an icon or emoji finds its nearest root, even from inside another component's shadow DOM.
  • Without JavaScript (a crawler, a server-rendered page) nothing is hidden: the hiding rule applies only under @media (scripting: enabled).
  • The loading look is swappable in code: UIRoot.Loading (a <ui-loader>), UIRoot.Skeleton (<ui-placeholder>s).
  • Skeleton sizes were judged by eye from Fomantic's defaults: expect some shift on reveal. Placeholders stack in page order, so a grid of cards shows as one column until ready (inline ones, like buttons, sit side by side).
  • With display="immediately", theme, size and box apply once the runtime loads, and an icon may draw from the page's packs for a moment first. The hidden modes don't show either.
  • Without a box (width / height / fixed), a theme sets colours but paints no background.
  • Language stays page-wide: no lang attribute yet.
