Vite+

How the repo's build, test, lint and format tools run on Vite+ 1.0, and what to watch for when changing them.

Written for: anyone touching configs, scripts or tool versions Status: built on branch vite-plus Checked 2026-10-02: every package's checks run before and after, on the same machine (see Measured)
  • vite-plus 1.0.0 (command vp, MIT) replaces vite, vitest, oxlint, oxfmt and tsgolint in every package.json; their versions move together.
  • Same engines underneath: dev, build and test are no faster. The gain is vp run: root scripts run packages in parallel (yarn ts 6.0s to 3.1s) and carry on past a failing one.
  • Its pins trail the standalone tools by a week or two (vitest 5.0.1, oxlint 1.85, oxfmt 0.70): cost us 4 rewrapped files and no new lint warnings.
  • Node 24.11+.
  • vp run --cache replayed "TSC PASSED" for a package with a type error: its file tracking can't see TS 7's native tsc. A cached task needs explicit inputs (Limits).
  • One yarn catalog: in .yarnrc.yml: vite is npm:@voidzero-dev/vite-plus-core@1.0.0 (Vite 8.3.1 repackaged), vitest and @vitest/* 5.0.1, vite-plus 1.0.0. Packages say "catalog:".
  • Bump all of them together, to what vp toolchain lists; never one tool on its own.
  • packages/vscode is its own yarn project and stays on plain vite.

  • vite.lint.ts at the repo root holds them (was .oxlintrc.json, .oxlintrc.react.json, .oxfmtrc.json): lintBase, reactLint, packageLint(), rootLint(), fmtConfig.
  • Every vite.config.ts spreads them into its lint / fmt blocks: vp lint / vp fmt read the nearest one.
  • The editor (oxc.disableNestedConfig) and vp check read the ROOT block only, so rootLint() carries React's rules as overrides for app, cli, core, lsp, parser, spell and util.

 * `parser`'s Vite+ config:  only the `lint` / `fmt` blocks (`vp lint`, `vp fmt`), from the repo root's `vite.lint.ts`.
 * - Tests:  `vitest.config.ts` beside this.

export default defineConfig({
  fmt: fmtConfig,
  lint: packageLint({ react: true })
})
  • In a package or the root: yarn vp lint, yarn vp fmt [--check], yarn vp test, yarn vp check. yarn oxfmt / yarn oxlint no longer work in a package; yarn vitest does.
  • Tests import from vite-plus/test (/browser, /browser-playwright), configs from vite-plus: lint rule vite-plus/prefer-vite-plus-imports.
  • Root ts, test:packages, review: vp run --fail-if-no-match -F '@spell-app/*' <task>, 4 at a time; review one at a time (--concurrency-limit 1).
  • vp run -r includes the root package: its all-in-one test runs too.
  • A filter matching nothing exits 0: hence --fail-if-no-match.
  • Flags go BEFORE the task name; after it, they're handed to the task.

  • Vite+'s pinned versions across the board, not newer standalone ones: one set to bump, nothing to drift.
  • Node 24 LTS, not the minimum 22.18: one bump covers the next pins.
  • Settings folded into vite.config.ts, through ONE module: vp migrate left each package's lint.extends pointing at deleted files, and dropped every comment saying why a rule is set.
  • No options.typeCheck: yarn ts already runs tsc; a second type check reports every error twice.
  • Imports rewritten to vite-plus/test in their own commit: 380 lines, nothing else.
  • Root scripts on vp run: parallel, and they run every package instead of stopping at the first failure.
  • No git hooks, no cached tasks, no root check script yet (see Limits).
  • No caching. Input auto-tracking misses TS 7's native tsc, so vp run --cache replays a stale pass. To cache: a run.tasks entry with explicit cache.input globs, including the packages its tsc reads through $/ aliases.
  • vp check fails today on 63 files already unformatted on main (56 in docs).
  • The Oxc editor extension must read fmt from the root vite.config.ts; if saves add semicolons, it isn't.
  • Fixed: a fresh install's first app browser test run used to fail (cold vite deps cache), also on main. The tests import spellRuntime.ts by URL, so it is now listed in optimizeDeps.entries (packages/app/vitest.config.ts).
  • cli's process-spawning tests can time out at 5s when everything runs at once; they pass alone.
  • Vite+ also manages Node and the package manager; we keep corepack yarn 4.18 and don't use that.
