<Section title="Behaviour">
  A label with `href` renders a link;  without one it is a plain `<span>`-like box.  `removable` adds a delete
  button that fires `ui-remove` (see the events table).  `<ui-labels>` shares size, colour, basic, tag and circular
  with every label inside it.

  Colour follows Fomantic:  a plain label stays grey inside a coloured owner (a `ui-red` wrapper, a red segment);
  only its own `color`, or its `<ui-labels color>` group's, paints it.

</Section>

<Section title="Theming">
  Theme with the public `--ui-label-*` tokens:  set one on the element, on any ancestor (a `<ui-labels>` group,
  `:root`), or on the label's box through `::part(label)`.  They inherit into the shadow root, where the sheet reads
  each through a private alias, so nothing inside blocks them.  Positioned labels (`corner`, `ribbon`, `attached`,
  `floating`) read `--ui-label-owner-edge` and `--ui-label-owner-radius` from their owner, so set those on the
  element that holds them (components like `<ui-segment>` and `<ui-input>` set them for you).

```css
ui-labels.tags {
  --ui-label-radius: 0;
}
```

</Section>

<Section title="Accessibility">
  - A label with `href` is a real link:  focusable, with Enter to follow.  Without `href` it is inert text.
  - An icon-only label (`icon` with no text) needs an `aria-label`.
  - `removable` adds a delete button with its own accessible name;  it is a separate tab stop.
  - A `prompt` label under a field should carry `role="alert"` and be tied to the field with `aria-describedby`, as the
    example does;  it is only a look, so it does not link itself to the input.
  - Colour is never the only signal:  a label's text carries its meaning.
  - Without JavaScript the native fallback renders the same `ui label` element around a slot, so text, links and
    colours stay;  the `removable` delete button (and `ui-remove`), the `icon` glyph and the `image` shorthand are dropped.
</Section>
