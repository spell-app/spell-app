Q7 Rulex: how to say "space required" (and adjacency beyond Symbols)? → D17

Markdown needs "space required": - item is a list item, -item is text; # Title a heading, #Title text. With D13, symbol runs (**, ]() no longer allow spaces, but nothing can REQUIRE one.

Whitespace is already kept: with today's WhitespacePolicy.LEADING_ONLY, each token carries the spaces after it in token.whitespace. So a new policy wouldn't help by itself: the gap is that rulex has no way to SAY it.

A. \s marker (recommended)

Regex's \s: "whitespace here". Checks the previous token's whitespace; consumes nothing. 

\-\s{text}
\#{1,6}\s{text}

No new policy. Spell untouched (no syntax uses it). Small: one zero-width rule.

B. New WhitespacePolicy

Keep inline whitespace as tokens; rulex's \s matches one; a Sequence skips whitespace the syntax doesn't mention.

Same syntax as A, but every rule class must step over whitespace tokens: much bigger change to parser.

C. Write it as it looks

Syntax spacing is significant: no space in the syntax = none allowed; a space = allowed; \s = required. 

![{alt}]({url})   adjacent
- \s{text}

Most natural for markdown; changes spell wherever a syntax has no space but input does (e.g. {a}'s).

What C changes in spell (packages/docs/rulex/experiments/adjacency-impact.mts): 11 of 135 syntaxes have parts written touching. Each keeps today's behaviour by adding a space to the syntax.

Syntaxes Touching Input that would stop matching Want it?
6: isn't, can't, won't, doesn't have (expressions.ts:210-234), doesn't start with, doesn't end with (lists.ts:295, 337) isn|'|t isn ' t yes: that's not the word
4 lists: [{item}(,|and)] shapes (lists.ts:40, 74; methods.ts:745; properties.ts:317) {item}|, red , green (space BEFORE a comma) probably fine; [{item} ,] keeps it
method signature ({method_keyword}|\({method_arg}\))+ (methods.ts:842) \(|{method_arg}|\) to move ( a card ) your call; \( {method_arg} \) keeps it

For comparison, the decided Symbols fix (D13) changes ONE spell syntax: (operator:(<|>) =?) (math.ts:45) stops matching > =. Under C it would keep matching it, because that syntax has a space.

The 4 list commas and the method-signature parens get a space added in their syntax, so they keep matching as today; that diff is in the P2 review gate. (<|>) =? keeps matching > =.

Q8 Rulex: interval quantifier syntax? → D18

Markdown needs counts: a heading is 1-6 #s; a thematic break 3 or more. Repeat already has minCount / maxCount: rulex just can't set them.

meaning regex A. braces (recommended) B. plus-number
exactly 7 x{7} x{7} x+7
1 to 6 x{1,6} \#{1,6} \#+1-6
3 or more x{3,} \-{3,} \-+3-
  • A: exactly regex. { is also a subrule, but a subrule name starts with a letter, so { + digit is unambiguous. Cost: rulex's repeatFlag grows a second form.
  • B: Owen's first idea. Quirk: the tokenizer reads -6 as a negative number and 1..6 as 1, .6; parseable, but the parser fights the tokenizer.

T1 LSP checks in docstrings: broken #heading links, unknown `identifiers` I1 Rulex silently drops the rest of a syntax it can't read

rulex.compile() (via P.Rule.compileSyntax()) never checks that every token was consumed. It throws only when NOTHING matched; otherwise the rule is quietly truncated.

syntax compiles to
a -- b Keyword("a")
a // b Keyword("a")
a "b c" d Keyword("a")
a \-- b Sequence[Keyword("a") Symbol("\")]

Evidence: packages/docs/rulex/experiments/rulex-probe.mts. Simplest fix: throw when match.length < tokens.length. Parser change: review gate (D7).

I2 Whitespace is invisible to literal rules: ** matches * *

Confirms the suspected bug (SUSPECTED-BUGS.md, parser). Rule from \*\*{word}\*\*:

input matches?
**hello** yes
* *hello* * yes (wrong for markdown)
[ hello ] ( world ) vs link rule yes (wrong for markdown)

Markdown needs both "no space here" (**x**, ]() and "space required here" (# heading, - item). Rulex has no way to say either. How to fix is a P4 question, after Owen reviews the rulex doc.

I3 toRulexSyntax() round trip loses escapes

\[{text}\]\({url}\) compiles fine, but prints back as \[ {text} ]( {url} \): Symbols joins its literals without escaping, so ( would re-read as a choice. Same for \*\*{text}\*\*, which prints back as ** {text} ** (re-reads as repeat flags). Matters wherever rules are written back out as syntax (spell's SPELL: DECLARES comments). Evidence: packages/docs/rulex/experiments/rulex-probe.mts.

I4 Rulex: 1.1.1 in a syntax crashes the compile (TypeError) UPDATE

1.1.1 tokenizes as Number(1.1) Number(0.1); compiling throws Cannot read properties of undefined (reading 'length'). Evidence: rulex/experiments/rulex-probe.mts. Goes away with digits-only numbers (D20).
