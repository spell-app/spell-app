<Section title="Behaviour">
  Attributes carry primitives and are reflected;  the rich `options` array is a JS property (frameworks find it with
  `"options" in element`), and first paint never needs it -- slotted `<ui-item>`s or the `value` / `text` attributes
  carry what server rendering must show.  Options set through the property are added after the slotted items.

  A native `<button commandfor="id" command="--toggle">` (or `--show` / `--close`) opens and closes the menu with no
  script, as a user action (the cancelable `ui-open` / `ui-close` first), and focuses the dropdown so the arrow keys
  work.  A disabled or read-only dropdown ignores commands.

  <Example title="Invoker commands" description="Two native buttons drive one dropdown.">
    <button type="button" class="ui button" commandfor="dropdown-invoker" command="--show">Open the menu</button>
    <button type="button" class="ui button" commandfor="dropdown-invoker" command="--close">Close it</button>
    <ui-dropdown id="dropdown-invoker" selection placeholder="Pick one">
      <ui-item value="a">Alpha</ui-item>
      <ui-item value="b">Beta</ui-item>
    </ui-dropdown>
  </Example>

  <Example
    title="Rich data"
    description="Set `options` from script and listen for `ui-change`.  `detail.value` is a string, or an array with `multiple`."

<Section title="Theming">
  Theme with the public `--ui-dropdown-*` tokens:  set one on the element or on any ancestor (`:root` included).
  They inherit into the shadow root, where the sheet reads each through a private alias, so nothing inside blocks
  them.  Variations build on them:  `floating` and `pointing` swap in their own `--ui-dropdown-floating-*` /
  `--ui-dropdown-pointing-*` values.  Style the pieces with `::part()`:  `trigger`, `text`, `icon`, `menu`, `item`,
  `label`, `search` and `clear`.

```css
ui-dropdown::part(menu) {
  max-height: 20em;
}
ui-dropdown {
  --ui-dropdown-arrow-size: 0.8em;
}
```

<Section title="Accessibility">
  The trigger is an ARIA 1.2 combobox with a listbox popup (the WAI-ARIA authoring practices pattern).

  - `role="combobox"` with `aria-expanded`, `aria-controls`, `aria-haspopup="listbox"` and `aria-activedescendant`
    pointing at the highlighted row.  Focus stays on the trigger while you move through the list.
  - The menu is `role="listbox"` (`aria-multiselectable` for `multiple`);  rows are `role="option"` with
    `aria-selected` and `aria-disabled`.  Headers and dividers are presentational.
  - `aria-label` on the host names the combobox, otherwise the placeholder does.  `loading`, `readonly`, `required`
    and validation set `aria-busy`, `aria-readonly`, `aria-required` and `aria-invalid`.
  - The clear button and each `multiple` label's delete button get translated names (`Clear`, `Remove {value}`).
  - Escape and outside clicks close the menu;  leaving the dropdown with Tab closes it too.

  | Key                        | Action                                                                    |
  | -------------------------- | ------------------------------------------------------------------------- |
  | Arrow Down / Arrow Up      | Open the menu, then move the highlight                                    |
  | Home / End                 | Highlight the first / last enabled option (open)                          |
  | Page Down / Page Up        | Move the highlight several rows (open)                                    |
  | Enter                      | Choose the highlighted option (or the addition);  opens a `search` dropdown |
  | Space                      | Choose the highlighted option (not in `search`, where it types a space)   |
  | Escape                     | Close the menu                                                            |
  | Tab                        | Close the menu and move on                                                |
  | Backspace                  | `multiple` + `search` with an empty query:  remove the last label          |
  | Any character (no `search`) | Type-ahead:  open and highlight the next matching option                  |

  Without JavaScript the native fallback is a real `<select>` (`multiple` when `multiple`), built from the same
  `<ui-item>`s or `options`.  It keeps the value, the form submission, `ui-change`, and the browser's own keyboard
  pattern;  it drops search, additions, clearable, option icons and images, and the open / close events.
</Section>

<Section title="Framework usage">
  Set `options` as a property, not an attribute, and listen for `ui-change`.

```jsx
// React 19
<ui-dropdown selection options={options} value="x" onui-change={(e) => setValue(e.detail.value)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-dropdown selection :options="options" value="x" @ui-change="(e) => (value = e.detail.value)" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref;  `prop:` for the rich data
<ui-dropdown
  selection
  prop:options={options}
  value="x"
  ref={(el) => el.addEventListener("ui-change", (e) => setValue(e.detail.value))}
/>
```

</Section>
