Every `ui-*` element renders SEMANTIC shadow markup that carries Fomantic's class grammar:
`<ui-button size="small" color="primary" basic>` renders `<button class="ui small primary basic button">` inside
its shadow root. `ClassBuilder` does it, driven by each component's vocabulary file.

The examples on this page are that shadow markup written out by hand, so you can see the classes; they are
styled by the page's native look until the components land.

## Why keep the grammar

- Shadow markup keeps Fomantic's classes on semantic elements: `<button class="ui small primary button">`.
- The CSS is then a mechanical port of Fomantic's `.less`, and the override language for the app stylesheet and
  `::part` is the vocabulary people already know.
- Fomantic matches multi-word phrases with substring selectors (`[class*="four wide"]`), so words come out in a
  fixed order. Attributes are therefore enumerated per kind, never free text.
- Class words are ALWAYS canonical English. Translated attribute names and values map back to canonical before
  they reach `ClassBuilder`.

## Shape

```
ui  <size>  <color>  <keyOnly...>  <valueAndKey / keyOrValueAndKey...>  <multiple...>  <width...>  <textAlign>  <verticalAlign>  <noun>  <extra>
```

- `ui` always, unless the vocabulary says `ui: false` (context-only parts such as `column`).
- Size, then colour: value only.
- Key-only words ALPHABETICAL by attribute name, so output doesn't depend on vocabulary order.
- Value-and-key words in vocabulary order; then multiple, width, text and vertical alignment.
- The noun (`button`, `card`, `column`), then any extra classes (a state like `active`).

## Widths

The attribute is `width`, NEVER `wide`. It accepts:

| Form       | Example                 | Columns (of 16) | Class                              |
| ---------- | ----------------------- | --------------- | ---------------------------------- |
| number     | `width="4"`             | 4               | `four wide`                        |
| word       | `width="four"`          | 4               | `four wide`                        |
| fraction   | `width="1/4"`, `"3/4"`  | 4, 12           | `four wide`, `twelve wide`         |
| percentage | `width="25%"`, `"100%"` | 4, 16           | `four wide`, `sixteen wide`        |
| equal      | `columns="equal"`       | --              | `equal width` (only where allowed) |

- Inexact values (`1/3`, `33%` => 5.33) snap to the nearest column, with a dev-time warning.
- Out of range (`0`, `17`, `2/1`) emits nothing, with a dev-time warning.

  <div class="four wide column">width="1/4"</div>
</Example>

## Booleans

- absent => false
- `""`, `"true"`, `"yes"`, or the attribute's own name (`disabled="disabled"`) => true
- `"false"`, `"no"`, `"0"` => false: Vue sends `open="false"` when it can't find a property
- any other present value => true (HTML presence semantics)
- reflection: true => `""`, false => attribute removed; NEVER `"false"`

## `medium`

`medium` is a real size meaning "default". It is accepted, validated and reflected like any other size, but emits
NO class, so `size="medium"` and no `size` render identically, and CSS never needs a `.medium` rule.

## Value sets

Enumerated values are validated against shared sets:

- `hues`: `primary secondary red orange yellow olive green teal blue violet purple pink brown grey black`
  (extensible)
- `sizes`: `mini tiny small medium large big huge massive`
- `positions`: `top left`, `top center`, `top right`, `bottom left`, `bottom center`, `bottom right`,
  `left center`, `right center`
- `alignments`: `left center right justified`; `verticalAlignments`: `top middle bottom`
- `floats`: `left right`; `devices`: `mobile tablet computer`, `large screen`, `widescreen`
- `widths`: `1` to `16` (plus words, fractions, percentages)

Unknown values are dropped with a dev-time "did you mean" warning.
