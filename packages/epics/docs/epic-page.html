<epic-page> The <epic-page> element: a whole plan doc, one epic's page.

<epic-page> is a whole plan doc: one epic's page.

  • Its attributes hold the epic's data (name, title, branch, dates); its children are the Overview and the sections.
  • It draws everything above them: the breadcrumbs, the sticky page header, the meta lines, and the review buttons.

Written for: anyone reading or writing a plan doc's markup, or changing this element.
Status: built in epic-page/.
Its vocabulary (attributes, slots, parts, children): EpicPage.en.ts.
The component: EpicPage.tsx.

As markup only, not drawn live: the note below says why.

An <epic-page> takes over the page around it: its header sticks under the site header, and its sections join the page's rail. So it shows only as markup here; to see one drawn, open this epic's own plan doc.

  • <ui-root> loads the epics pack, the script that defines every <epic-*> tag, from its <ui-components source>.
  • The file's <title> reads Epic: <title>; the page's title holds the title alone.
  • None of the header is written in the file: the element draws it from the attributes and the phases below.

None: it's the page. A plan doc's file holds exactly one, in main.spell-doc-main, inside <ui-root>.

The Overview first, then the sections, each kind once at most, with its fixed id. A report (kind="report") is the one section that isn't numbered: it sits right after the Overview.

In THIS order, always: the tool puts each child where it belongs, and the check refuses another order.

title

branch text Its git branch; absent for a future epic.
worktree text Its worktree's folder, absolute; absent for a future epic, or once the worktree is gone.

updated text: date The day a command last changed it.
future boolean: there or not A FUTURE epic (/epic future): an idea written down, not planned yet; its open questions are on details/analysis.html.
bedtime text A /bedtime run is on, and what it runs (P3-P6): items it changes are recent.
recent-since text: time Items decided, reviewed or closed since then are recent (green): the commit time of HEAD~2 in the doc's checkout. Absent without git history.
repo text The repo's web address (https://github.com/spell-app/spell-app): <epic-commit> links are made from it. Absent: commits show without links.
reviewing boolean: there or not PAGE state, never in a doc: the page is being reviewed -- served by the page server with a token, its review inbox answering -- so items and Overview parts show their review controls, and the header Send and Review Now. Set by them (P9, ReviewState); the old runtime's body.plan-reviewing.

Pieces of what it draws, which a page's CSS can style from outside with ::part(name).

Part What it is
base The page.
crumbs In the h1, before the epic's name: Docs / Epics /, the docs' eyebrow. None narrow, nor while the doc still holds its old ui-breadcrumb.spell-crumbs before the page.
header The sticky page header: the h1, then the tools and labels at its right.
heading The h1: the crumbs, then the epic's name in their type, twice their size and bold; a click on the name copies /epic resume <name>.
actions While the page is reviewed: Send (the paper plane: grey, blue with unsent marks, outlined once sent) and Review Now (the wand: blue while there's anything for Claude to work through).
send The Send button: every unsent mark to Claude.
review-now The Review Now button: every mark sent, each revisit asked now.
git The git toggle: shows or hides every commit (only when the doc has some).
status The state mark (in progress, errors or paused), then the bedtime and step labels.
state The epic's state, an icon in its colour: in progress (blue), errors (red: every phase done, items need you), paused (grey: phases left, untouched for days); why on hover. None for a future epic or a done one: the step label says so.
review-line Under the header: To review this doc, type /epic review <name>, copied on click; while the page is reviewed with nobody listening, it says no session is reviewing.
meta The meta lines: branch, worktree, dates, durable doc.
notice A future epic's notice: not planned yet.
hung A doc still planning (no phases, not future): the folded Plan hung? aside, with the prompt to copy.

Custom states: CSS can match them with epic-page:state(name).

State When
:state(future) A future epic.
:state(commits) Every commit shows (the git toggle is on).
  • Edge to edge: it breaks out of the docs' page padding, so the section bands reach across the window. Everything inside insets itself.
  • The step label, at the header's right, follows the phases (the colour scheme):
    • the phase under way: OUTLINED blue (Claude is on it), a link to it
    • every phase done: DONE, SOLID green
    • otherwise the next phase, grey; FUTURE, grey, for a future epic; nothing without phases
  • The bedtime label (bedtime set): violet, Claude's voice, with a bed icon.
  • The state mark, by the same rule as the Epics list ($/server/site/EpicState, Owen 2026-10-10): in progress (blue: phases left, touched in the last 3 days or a session listening), errors (red: every phase done, items need you), paused (grey: phases left, untouched for 3 days or more). Its tooltip says why. None for a future epic or a done one: FUTURE and DONE say it.
  • Send and Review Now, only while the page is reviewed: blue (do it now), by the fill rule.
    • Send (paper plane): a grey outline with nothing to send; DASHED blue with marks not sent yet; OUTLINED blue once sent
    • Review Now (wand): outlined blue while Claude has anything to work through
  • The review line: a click copies the command. While the page is reviewed with no Claude session listening, it says so in solid orange (a warning).
  • The git toggle: a bare icon, only when the doc lists commits. It shows or hides every commit, remembered per page.
  • Agents running: a panel before the blocks, while any agent of the epic runs, with a note box per agent.
  • Folding: the page itself doesn't fold. Its blocks do, and on a plan doc they all start folded.
  • The shared look: it declares the pack's CSS tokens (--epic-*: colours, bands, the inset, the chips), and every element inside inherits them.
  • spell dev plan-doc new <name> [--title ...] [--prompt ...] [--future]: copies the tool's template (plan.html) and fills epic, title, branch, worktree, started and updated. With --future: future, and no branch or worktree.
  • new run on a future epic's doc, or adding its first phase, plans it: future goes.
  • Every command that edits the doc stamps updated and refreshes recent-since.
  • spell dev plan-doc bedtime <name> start "P3-P6" sets bedtime; bedtime <name> done removes it.
  • spell dev plan-doc commit and spell dev plan-doc commits <name> --backfill list commits, linked through repo.
  • spell dev plan-doc convert wrote it for every doc made before the switch (from the old ui-* markup).
  • reviewing is never written: the page sets it on itself while it's being reviewed.
  • The rules for the doc's data: PLAN-DOC.md, "The page".
