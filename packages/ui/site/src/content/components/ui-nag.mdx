<Section title="Behaviour">
  A nag shows its slot with a close icon (`closable`, on by default).  A `<span class="title">` inside is set off in
  the title colour.  `fixed` pins it to the top (or `bottom`) of the viewport, `overlay` puts it over the top of its
  container, and plain it pushes the content down.

  Remembering is opt-in.  With a `key`, closing the nag stores `value` (default `dismiss`) under that key in
  `storage`:  `local` (`localStorage`), `session` (`sessionStorage`) or `cookie` (Fomantic's default, with `path`,
  `domain`, `secure` and `samesite`), for `expires` days (30 by default;  `0` never expires).  A nag whose dismissal
  is stored is hidden before it paints, unless it `persist`s.  Blocked storage (a private window, a strict browser)
  just doesn't remember.

  `display-time` hides it after that many milliseconds, without storing anything.  `ui-close` is cancelable, with
  `detail.reason`:  `close` (the icon), `timeout` or `dismiss` (`host.close()`);  `ui-hide` follows once it has gone.
  The host also has `show()`, `clear()` (forget the dismissal) and `dismissed`.

```js
const nag = document.querySelector("ui-nag[key=cookies]")
nag.addEventListener("ui-close", (event) => {
  if (!consentSaved) event.preventDefault() // keep it up, store nothing
})
if (nag.dismissed) loadAnalytics()
```

<Section title="Theming">
Theme with the public `--ui-nag-*` tokens:  set one on the element, on any ancestor (`:root` for every nag), or
  on the box through `::part(nag)`.  `inverted` reads the `--ui-nag-inverted-*` tokens
  instead.  Style the close icon with `::part(close)`.

```css
ui-nag {
  --ui-nag-padding: 1em 2em;
}
ui-nag::part(close) {
  opacity: 1;
}
```

<Section title="Accessibility">
  - A nag has no role of its own:  it's content, read in page order.  If it must be announced when it appears, give
    it `role="status"` (or a `role="region"` with an `aria-label`, for a banner) yourself.
  - The close icon is a real button named "Close" (translated).  With `closable="false"`, make sure something else
    closes it.
  - A `fixed` nag covers the page's edge:  leave room for it (padding on the body), so it never hides content.
  - If the element can't render, its native fallback still shows the nag with a working close button (which hides
    it and fires `ui-hide`).  Remembering, `display-time` and the vetoes are lost.
</Section>

<Section title="Framework usage">
  A nag manages itself:  put it in the template with a `key`, and listen for `ui-hide` if you track it.

```jsx
// React 19
<ui-nag key="cookies" storage="local" onui-hide={() => setConsent(true)}>We use cookies.</ui-nag>
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-nag key="cookies" storage="local" @ui-hide="consent = true">We use cookies.</ui-nag>
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<ui-nag key="cookies" storage="local" ref={(el) => el.addEventListener("ui-hide", () => setConsent(true))}>We use cookies.</ui-nag>
```

</Section>
