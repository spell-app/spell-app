<Section title="Behaviour">
  Container widths are the same at each device size and are calculated in CSS, from tokens, so they can be changed
  without touching the markup.  The host is a block;  the look lives on the `container` part inside.

  <VocabularyTable family="container" />
</Section>

<Section title="Theming">
  Theme with the public `--ui-container-*` tokens:  set one on the element, on any ancestor (a region, `:root`), or on
  the inner box through `::part(container)`.  They inherit into the shadow root, where the sheet reads each through a
  private alias, so nothing inside blocks them.  The fixed widths are one token per breakpoint
  (`--ui-container-width-tablet`, `-computer`, `-large-monitor`).

```css
/* every container on the page */
:root {
  --ui-container-width-large-monitor: 1200px;
}
/* one article */
article {
  --ui-container-text-width: 640px;
}
```

  <CssTokens family="container" />
</Section>

<Section title="Accessibility">
  - A container is a layout box with no role of its own.  Use a landmark inside it (`<main>`, `<nav>`, `<article>`) or
    put `role` / `aria-label` on the host when the region needs a name.
  - A `scrolling` container is a keyboard stop (`tabindex="0"`) so its overflow can be scrolled without a mouse;  give it an `aria-label` when it needs a name.
  - Without JavaScript the native fallback renders the same `ui container` element around a slot;  nothing is dropped.
</Section>
