Precedence And Types

How spell's grammar binds operators and knows what every expression is -- and what that bought: paren-free signatures, typed calls, multi-word members, built-in member tables and exclusive lists.

Written for: Owen, and any agent about to change the parser's rules Status: built 2026-10-04 by epic precedence-and-types, P1-P8, on branch precedence-and-types: not merged yet. Was the 2026-09-30 design; rewritten as built in P9. Checked by: every "today" below is the probe ledger's output, grammar.probes.test.ts in packages/spell, 2026-10-04; every "before" was produced by running the parser on 2026-09-30, see Sources and experiments. Beside it: Parser Model (every change modelled before code, with "Built" notes); PARSING.md (the mechanics, kept current).
  • The parser couldn't say what an expression is (its type) or how tightly it binds (its precedence), so every rule guessed from shape. It now knows both.
  • Binding (P3): an operator's precedence is how tightly it binds; a prefix's last slot is an operand, which stops before any operator. All 9 precedence probes the design targeted now compile as they should, and every row in 2 does.
    • Each nesting level is parsed once, not twice: the Solitaire project parses in 55ms, was 110ms (medians of 3).
  • Types (P4-P5): every match carries a datatype in spell's words. So signatures take a card without parens, and a call whose argument is the wrong type falls to the next rule.
  • Members (P6-P7): the short rank of a card resolves through the card's type; five built-in types (thing, list, app, text, date) have member tables, so the length of means one thing for text, another for a list.
  • Exclusive lists (P8): a pile is an exclusive list of cards -- adding a card to a pile takes it out of its last one, and the pile of a card reads it.
  • Not built: the TypeScript check, now an epic of its own; emitting Solid JSX, cut.

Kept for the record: the mechanism P3 replaced, and why it went wrong.

  • expression was a group of 42 rules, tried in module order. Rules added while parsing go first.
  • The only "term, then operators" rule was compound_expression: {lhs:simple_expression} {rhsChain:expression_suffix}+, precedence 12, one of the 42. It ran a shunting-yard over the suffixes' precedences when it built its AST.
  • simple_expression was not a narrower tier: "every expression rule except the left-recursive ones", so it still held every prefix rule ending in {expression}.
  • Choice.parse() parses every alternative, then keeps one. Sequence.parse() took each child's single match.
  • Normal parsing has no memo. compound_expression re-parsed the alternatives the outer expression choice parsed anyway, at every nesting level: 2depth.

  • The words were swapped at review (D26): precedence is what every programmer already means by it.
  • compound_expression is THE expression rule: {lhs:operand} {rhsChain:expression_suffix}* -- an operand, then each suffix binding tighter than its bound (0: all of them).
  • No suffix: it returns the operand's own match, so match.is(known_variable) still works on {thing:expression}.
  • An operand is every other rule aliased expression: SpellParser.getNamesForRule() registers them under operand (D29; was simple_expression). It nests: the first card of the deck holds the deck.
    • An operand whose syntax STARTS with an expression throws at registration: it would recurse forever. Something after an expression is an expression_suffix instead, e.g. list_membership_test.
  • Three slot kinds:
    • {x:expression}: everything. Statements, and slots closed by a word, like a paren (the position of {x} in).
    • {x:operand}: a prefix's LAST slot (the first card of {list:operand}), and every suffix's right side. Stops before any operator.
    • {x:arithmetic_expression}: + - * / only, bound Precedence.takesSum. For absolute value and round.
  • The suffixes' right sides are operands, so the chain is flat; getAST() groups it by precedence. A postfix now pops like an infix.
  • Each level is parsed once: the double parse is gone.

class compound_expression extends SpellExpression<"lhs|rhsChain"> {
  static ruleName = "expression"
  @proto static alias: string | string[] = []
  /** Suffixes must bind tighter than this to be ours:  0 takes them all, see `arithmetic_expression`. */
  declare bound: number
  @proto static bound = 0

  parse(scope: P.Scope, tokens: P.Token[]): P.Match | undefined {
    const [operand, chain] = this.rules as [P.Rule, P.Repeat]
    const lhs = operand.parse(scope, tokens)
    if (!lhs) return undefined

    const suffixes: P.Match[] = []
    let rest = tokens.slice(lhs.length)
    while (rest.length) {
      const suffix = chain.rule.parse(scope, rest)
      if (!suffix || precedenceOf(suffix) <= this.bound) break
      suffixes.push(suffix)
      rest = rest.slice(suffix.length)
    }
    if (!suffixes.length) {
      lhs.matchGroup = this.name
      return lhs
    }
    // the same shape `Sequence` would make of our syntax:  `lhs`, then a `Repeat` match as `rhsChain`
    // ...
  }
}

Binding power fixed shape. The type problems needed the parser to know what an expression is: built in P4, used by P5-P8. The mechanics: PARSING.md "Datatypes".

  • The rule the codebase already followed for scopeVar: look it up WHILE PARSING, stash it in match.data, never touch scope from getAST() or getDatatype().
  • match.datatype memoizes rule.getDatatype(match). Default: the rule's @proto static datatype; about 20 rules override it, reading only match.data and child matches.
  • Unknown is undefined, and fits everything. Nothing stops parsing for want of a type.
  • First datatype wins: a record's type is set when it's declared, never widened -- except a getter's property and a method's returns, set once the body has parsed.
  • literals, from their rule; [1, 2, 3] is a list of numbers
  • a known variable, from its scope record
  • a new card => Card; a new list of cards => list of cards
  • the X of Y and its X, from the member found on Y's type -- a built-in's from its table entry
  • a method call, from its record's returns, inferred from the method's returns (P5)
  • comparisons, aliases, and / or / not: choice
  • arithmetic: - * / are number; + is number only when both sides are, text when either is, else unknown (J12)
  • list rules: the item type, the list's type, or number
  • a whole compound_expression: getAST()'s shunting-yard again, over each suffix's getResultDatatype()

/** Emitted text, plus which AST node wrote each range of it. */
type Emitted = { text: string; spans: EmittedSpan[] }
type EmittedSpan = { start: number; end: number; node: P.ASTNode }

class ASTInfixExpression extends ASTExpression {
  // today:  a string, and where it came from is lost
  compile(): string {
    return `${this.lhs.compile()} ${this.operator} ${this.rhs.compile()}`
  }

  // proposed:  the same one-liner;  the tag asks each node for its own `emit()`, shifts its spans
  // by where it landed, and adds one span for `this`
  emit(): Emitted {
    return P.emit(this)`${this.lhs} ${this.operator} ${this.rhs}`
  }
}

/** Innermost node whose output covers `offset`:  its `match` is a range in a spell file. */
function nodeAt(emitted: Emitted, offset: number): P.ASTNode | undefined {
  let found: EmittedSpan | undefined
  for (const span of emitted.spans) {
    if (span.start > offset || span.end <= offset) continue
    if (!found || span.end - span.start <= found.end - found.start) found = span
  }
  return found?.node
}

type TypeScriptService = {
  /** Replace the files it knows:  the emitted `.ts`, `@spell/core`'s types, imported projects' types. */
  setFiles(files: Record<string, string>): void
  /** Type errors, as offsets into the emitted files. */
  semanticDiagnostics(): Promise<TypeScriptDiagnostic[]>
  /** Type of the expression at `offset`, in TypeScript's words, e.g. `"Card | undefined"`. */
  typeAt(file: string, offset: number): Promise<string | undefined>
  /** Plain JS:  types stripped, nothing else changed. */
  lower(files: Record<string, string>): Promise<Record<string, string>>
}

/** Editor only:  runs after the spell compile, before anything is saved or run. */
async function checkAndLower(project: SP.SpellProject, service: TypeScriptService): Promise<CheckedOutput> {
  const emitted = project.emitTypeScript() // one `.ts` per spell file, each with its node => output-range spans
  service.setFiles({
    ...emitted.files,
    "/spell-core.d.ts": SPELL_CORE_TYPES, // generated from `packages/core/src/` when the editor is built
    ...project.importedTypes() // an imported project's `<Project>.compiled.ts`, saved beside its `.js`
  })

  const problems: SpellProblem[] = []
  for (const diagnostic of await service.semanticDiagnostics()) {
    const node = emitted.nodeAt(diagnostic.file, diagnostic.start) // innermost AST node that wrote that range
    if (node) problems.push({ match: node.match, message: inSpellWords(diagnostic, node) }) // a SPELL range
  }

  // what every runner loads:  plain ES modules which import only `@spell/...`
  const javascript = await service.lower(emitted.files)
  return { problems, javascript }
}
