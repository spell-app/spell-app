Server-render pages of ui-* elements in node (Solid 2 renderToString) into plain light-DOM HTML plus one stylesheet: no shadow DOM, no JS, interactive parts present but hidden, dialogs, click popups and accordions opening natively. For crawlers and no-JS readers: each host is replaced by its rendered root, and CSS stays isolated with @scope.

How hard would it be to get spell/ui components to have a "render statically, no shadow dom" for SEO pages?

Interactive functionality (tooltips, dropdowns, modals) would render, but hidden.

Ideeally we'd have very minimal functionality. e.g. a button that shows a modal would open the modal with CSS somehow.

What the server render must fix

  • today's probe (packages/ui/test/ssr.ssr.test.tsx) passes only because its stub host has no children, parent or internals
  • fork (packages/solid-element): no server path; customElements, attachInternals, attachShadow, insert all browser-only; hooks throw without an element in context
  • unguarded hooks: PartContext onConnect (34 tags), FormElement onFormReset (8 families)
  • SlotContent uses Element / Node globals: crashes on any host with children
  • UI runtime won't construct in node (new CSSStyleSheet()); ~25 families call text(), UI.ids, UI.i18n or UI.browser while rendering
  • isServer short-circuits that EMPTY output today: accordion panels, tab buttons, card slotted parts, table rows
  • icons: async packs + DOMParser; on the server, empty boxes

Each host gives way to its rendered root, light children spliced in where the slot was (D3). Most hosts are already display: contents, so the box that lays out doesn't change.

Aside: why not keep the tags

native.css hides undefined ui-root (visibility: hidden whenever scripting is on, as for Googlebot) and ui-popup / ui-modal. Never-registered kept tags would hide the page.

Without shadow DOM, CSS leaks two ways:

Component into nested component (D5)

  • .ui.menu .item would reach a nested dropdown's rows; leaky selectors: menu 44, list 34, dropdown 34, form 22, message 21, breadcrumb 14, comment 9
  • fix: data-ui="<noun>" on each root, each sheet wrapped in @scope from its root down to, not into, other components
Scoped sheet · 3 lines 
@scope ([data-ui="menu"]) to ([data-ui] > *) {
  /* ui-menu.css, rules unchanged */
}

Page into component (D6)

  • unlayered page CSS beats every ui.* layer: page a { color } would recolor a menu's <a class="item">
  • fix: @layer page, ui;: component wins conflicts, page fills gaps

Rest of the rewrite

  • ~376 :host and 132 ::slotted rules already have class-grammar twins: drop the shadow half
  • ~224 :host + 20 ::slotted without twins: rewrite (box rules drop; position rules use the real DOM)
  • :state(in-card) -> .in-card (parts' documented static form)
  • token resets on host / <slot> -> root / .ui.X > * in an early layer, so colors and scale don't leak into nested components
  • [hidden] { display: none }: component display rules beat the browser's
  • inherited properties already cross shadow boundaries: no change; app ::part() / :state() CSS doesn't apply (C3)

D1 Agents: up to 5D2 Solid server render, not simulated DOM or browser prerender

Chosen after costing (1.2): biggest job, but no browser at build or request time, renders per request from a node server, and fixes ui's SSR for everyone.

D3 Replace each host with its rendered root

~40 of 55 families replace cleanly, output == their class-grammar examples (already CSS-tested). Keeping hosts would hide the page: native.css hides undefined ui-root / ui-popup / ui-modal. See 1.3.

D4 List-item families wrap in <li>

card in cards, feed event, list item, step: their host's role=listitem has no valid place on an <article> / <a> / <button> root, and ul > div is invalid. Costs CSS like .ui.cards > li > .card.

D5 Nested isolation: data-ui on roots + @scope

Flattener marks each component root data-ui="<noun>"; each sheet wrapped @scope ([data-ui="menu"]) to ([data-ui] > *). No new browser floor: anchor positioning already needs Firefox 147 / Safari 26, and packages/ui/docs/plan.md lists @scope as assume-present. Vue-style per-element attributes not needed. See 1.4.

D6 Page CSS in a layer before ui

@layer page, ui;: component wins conflicts, page fills gaps. Unlayered page CSS would beat every ui.* layer.

D7 spell CLI command, not a yarn script

spell static in packages/cli; yarn only wraps the CLI.

D8 Server code stays out of client bundles

Separate @spell-app/ui/server entry and fork server helper; client gets only isServer guards (dead code in the browser build). Budget under 1 kB min+gz, yarn measure before / after.

D9 Fork server module: hooks register, never run

@spell-app/solid-element/server's ServerElement: attach() gives a linkedom element the fork's bookkeeping, props() converts attributes as the element would, run() makes it current + ElementContext. So onConnect() / onFormReset() register instead of throwing: no guards needed in PartContext or FormElement.

D10 hostEffect(): host-writing effects apply at once on a server

Solid's server build runs an effect's compute only, never its apply, so host ARIA (internals.role = "listitem") was never set. UIElement.hostEffect(compute, apply) ~== createEffect in a browser, applies once on a server. Used in UIItem, UICard; the rest in P3.

D11 ServerRuntime, not UIRuntime, in node

UIRuntime's constructor registers the foundation with new CSSStyleSheet(). ServerRuntime installs the real browser, ids, i18n, vocabulary, icons and a no-op styles; any other service throws, naming itself.

D12 A role=list root holding <li>s becomes <ul>

<ui-cards>' root is <div role="list">; once its cards are <li>-wrapped (D4) the flattener re-tags it <ul>, attributes kept.

D13 Host states as data-state, author content as data-ui-slotted

The flattener writes every host state as data-state="a b" (:state(x) => [data-state~="x"]; in-* also as classes), and marks each slotted element data-ui-slotted. The scope limit is [data-ui-slotted]:not([data-ui]) > *, :scope [data-ui] > *: slotted author elements and other components' roots are in scope (as ::slotted() reached them), their insides aren't.

D14 List item wrappers: display: contents, child combinators step over them

<li data-ui-li> is display: contents (the card stays the flex child), the slotted marker goes on the item's root, and in the sheets of cards / list / feed / steps / items each A > B also matches A > [data-ui-li] > B (at most 3 per selector: 2^n variants).

D15 Host-only rules move to @layer ui.reset

A host rule (:host { --ui-color: initial }) and the root's own rule (.ui.red, in ui.tokens) were on different elements; now they share one, so the host rule moves to the first layer and every later layer still wins. Their display is dropped (the host box's).

D16 Page sheets lose their shadow-only selectors; reset.css is scoped to [data-ui]

The foundation's :host token defaults never match on a page; reset.css only ever applied inside shadow roots, so it's rewritten and scoped to every component.

D17 Static parity renders through a second, SSR-only Vite server in vitest's ssr posture

yarn test:visual --static serves /static/<family>/<example>.html from the visual dev server (tools/visual/StaticPages.ts), but renders through its OWN middleware-mode Vite server with mode: "test" + test.environment: "node". Why: @solidjs/vite-plugin compiles JSX with generate: "ssr" only in test mode or with its ssr option; the dev server's plugin compiles every module dom, even for ssrLoadModule, and Solid's server build then throws "Client-only API called on the server side". Its ssr option would change the element pages' compile too (hydratable). Plus ssr.noExternal: ["solid-js", "@solidjs/web"] (the plugin adds it outside test mode, vitest inlines them itself): external, node resolves solid-js's own imports without development and mixes builds ("Cannot set properties of undefined (setting 'server')"). P5's spell static will hit the same two.

D18 Selectors anchored with :where(:scope, *)

Fixes I3: inside @scope, a selector without :scope is read as a descendant of the root, so .ui.card never styled the card. StaticSelectors.anchor() adds :where(:scope, *) to the subject: no specificity, still bounded by the scope. (The agent's experiment, measured: card / segment / section heights then match.)

D19 Adopted sheets recorded per render: scope roots and layer order

Fixes I4: StaticRender.sheetUsage records each element's sheets() (a new public UIElement method). A sheet is scoped to every noun seen adopting it (items take ui-list.css), and sheets are emitted in an order keeping every adoption order (StaticStylesheet.ordered(), a topological sort): in the item's shadow root the list's sheet came AFTER the item's, so its layers won (--_ui-item-media: image vs 1).

D20 A <div> list item root becomes the <li>; only <article> / <a> / <button> roots are wrapped

Refines D4 / D14: a wrapper hides an item's siblings, so :first-child and .item + .item broke (every list item got the first item's padding). Wrapped roots remain (cards, link items): their position pseudo-classes are tested on the wrapper (StaticSelectors.hostPosition() / wrapperPosition()).

Older WebKit dropped the list-item role of a display: contents element; current browsers keep it. The role=list on the <ul> stays either way.

I1 Section's inline style loses the ; between declarations

UISection.tsx style={{ [STICK_TOP_PROPERTY]: ..., [DEPTH_PROPERTY]: ... }} server-renders as --_ui-section-top:0px--_ui-section-depth:0. Computed keys in Solid's SSR compile; ssrStyle() itself joins with ;. Fix in P3; logged in SUSPECTED-BUGS.md.

I2 UIRuntime's docstring says it constructs outside a browser; it doesn't

"Constructs outside a browser too (SSR)" in UIRuntime.ts: registerFoundation() calls new CSSStyleSheet(). Worked around by ServerRuntime (D11); fix the comment or make Styles lazy.

I3 Static stylesheet: rules miss every component ROOT (@scope's implicit descendant prefix)

Inside @scope (root) to (limit), a selector with no :scope / & is read as :where(:scope) <selector>, so .ui.card, .ui.cards, .ui.segment, .ui.list never match the root they are written for (checked in Chromium). Only the :scope:is(...) rules from :host(...) reach it. Seen in yarn test:visual --static: a standalone card is 992px wide with no border, ul.ui.cards keeps its UA 24px padding and stacks its cards, so ui-card/types is 2971px tall statically vs 1286px as elements.

Tried in the browser only (tools/results/fix.mts, nothing in src/): appending :where(:scope, *) to every scoped selector (before any ::pseudo) keeps specificity, still excludes elements outside the scope and past the limit, and brings static heights to the element ones exactly: card/types 1286 = 1286, segment/types 1165 = 1165, section/types 1532 = 1532, button/variations 1131 = 1131. Belongs in StaticSelectors.rewrite().

I4 Static stylesheet: list items don't get their owner's sheet (ui-list.css holds the item rules)

UIItem adopts its OWNER's sheets in its shadow root (ui-list.css holds the item rules, e.g. the image shorthand's avatar size at ui-list.css:449, :host(:state(in-list)) > .item > img.avatar.image). StaticStylesheet scopes ui-list.css to [data-ui="list"] only, and the limit [data-ui-slotted] > * stops at the slotted item root, so nothing inside an item gets list rules. Result: every <img class="ui avatar image"> renders at full width; ui-list/variations is 55575px tall statically vs 2736px as elements (98.7% different), ui-list/content 3791 vs 978px. Still off after the I3 fix (20872px). Needs a way to say "this family's roots also take the owner's sheets", e.g. scope ui-list.css to [data-ui="list"], [data-ui="item"][data-state~="in-list"]; the same holds for <ui-items> once it is server-ready (UIItem adopts whichever owner's sheets).

I5 Every element with an icon threw in node: RootSettings.parentOf used instanceof ShadowRoot

IconGlyph peeks its packs through RootSettings.nearest(), whose parentOf() ended in root instanceof ShadowRoot: ReferenceError: ShadowRoot is not defined in node once the climb reaches the document. 13 of 35 static pages failed (every button, section and list example with an icon). Fixed in packages/ui/src/elements/RootSettings.ts with the nodeType test OwnerContext.parentOf() already uses. Still instanceof ShadowRoot / Document, not hit by today's examples: ui-button/Invoker.ts:19 (a button's command target), ui-menu/UIMenu.tsx:194, runtime/Focus.ts:73.

I6 Stacked / piled segments lose their paper edges and gain 16px gaps

ui-segment/groups (3%): the stacked and piled effects are pseudo-elements on the HOST box, which no longer exists; the groups also get gaps the elements don't have. Per-family rule work, P3.

I7 card/groups and segment/variations differ by ~3%: not yet looked at

From tools/results/visual/static-parity.md after the P2 fixes; every other pair of the P1 families is within 1%, apart from those using icons (empty until P3) and families not yet server-ready.
