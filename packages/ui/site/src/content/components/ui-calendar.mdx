<Section title="Behaviour">
  A calendar is a field whose icon is a real button opening the picker, a popover dialog anchored to the field by
  CSS (no script measures anything).  With `inline` the picker sits in the page instead.  The picker has Fomantic's
  views:  years (a decade), months, days (always six weeks), hours and minutes (5-minute steps), as far as `type`
  goes.  Choosing a coarser cell opens the next view;  the finest sets the value.  The title button goes back up.
  `disable-minute`, `disable-month` and `disable-year` skip a view.

  Values are ISO strings, the shapes of the native date inputs:  `2026-09-30` (`date`), `14:30` (`time`),
  `2026-09-30T14:30` (`datetime`), `2026-09` (`month`) and `2026` (`year`).  `min`, `max` and `initial-date` (where
  the picker starts while there's no value) take the same shapes.  The `value` attribute is the starting (and reset)
  value;  the `value` property is the live one.  It's a form control:  `name` submits the ISO value, `required`
  validates, a form reset restores the attribute.

  Typing works too.  The field reads ISO, the locale's own numeric order (`9/30/2026`, `30.9.2026`), month names or
  their first three letters, and times with or without the locale's `am` / `pm`.  Text it can't read, or a value out
  of range, reverts when the field is left or Enter is pressed.

  `ui-change` (`{ value }`) fires when the user chooses, types or clears a value;  `ui-open` / `ui-close` around the
  popup.  All three are cancelable.  Days that can't be chosen are the `disabledDates` and `disabledDaysOfWeek`
  PROPERTIES, plus other months' days unless `select-adjacent-days`.

```js
const due = document.querySelector("ui-calendar[name=due]")
due.disabledDates = ["2026-12-25", "2026-12-26"]
due.disabledDaysOfWeek = [0, 6] // no weekends
due.addEventListener("ui-change", (event) => {
  if (event.detail.value < today) event.preventDefault() // keep the old value
})
```

  Dates are computed with `Temporal`:  the browser's own where it has one, else a polyfill loaded on demand, only
  by pages that show a calendar.

<Section title="Theming">
  Theme with the public `--ui-calendar-*` tokens:  set one on the element, on any ancestor (`:root` for every
  calendar), or on the box through `::part(calendar)` or `::part(popup)`.
  Style the pieces with `::part()`:  `input` and `control` (the field), `trigger` (the icon button), `popup`,
  `header` with `previous`, `title` and `next`, `grid`, `cell` and `today`.  `color` remaps the shared `--ui-color`,
  so a theme's hues work here too.

```css
ui-calendar {
  --ui-calendar-cell-padding: 0.75em;
}
ui-calendar::part(cell) {
  border-radius: 50%;
}
```

<Section title="Accessibility">
  The picker follows the WAI-ARIA APG date picker dialog.  The grid is a `role="grid"` named by its title (a time
  grid by "Hours" / "Minutes");  each cell carries the whole date as its name, with `aria-selected`, `aria-disabled`
  and `aria-current="date"` on today.  Weekday heads spell out the day (`<th abbr>`).

  - Name the field with a `<label for>`, `aria-label`, or at least a `placeholder`;  an inline calendar needs
    `aria-label`.
  - Disabled days stay focusable (APG), so the keyboard never skips a week;  they just can't be chosen.
  - All the texts (Today, Previous month ...) are translatable.

  | Key                          | Action                                                         |
  | ---------------------------- | -------------------------------------------------------------- |
  | Arrow Down (field or button) | Open the picker, focus in the grid                              |
  | Arrow keys                   | Move by a day (a cell);  Up / Down by a week (a row)            |
  | Home / End                   | First / last day of the week (cell of the page in other views)  |
  | Page Up / Page Down          | Previous / next month (a year, or a decade, in the coarser views) |
  | Shift + Page Up / Page Down  | Previous / next year, in the day view                            |
  | Enter / Space                | Choose the focused cell                                          |
  | Escape                       | Close the picker;  focus goes back to the field                 |

  - A click in the field opens the picker and leaves focus there for typing;  focus leaving the element closes it.
  - If the element can't render, its native fallback is the browser's own `<input type="date">` (or `time`,
    `datetime-local`, `month`, a number for a `year`) holding the same ISO value, so it still works and submits.
    Fomantic's picker, ranges, disabled days and the locale's formats are lost.
</Section>

<Section title="Framework usage">
  Bind `value` (an ISO string) and listen for `ui-change`;  set `disabledDates` as a property.

```jsx
// React 19
<ui-calendar type="date" name="due" value={due} disabledDates={holidays} onui-change={(e) => setDue(e.detail.value)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-calendar type="date" name="due" :value="due" :disabledDates="holidays" @ui-change="(e) => (due = e.detail.value)" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref;  `prop:` for the property
<ui-calendar type="date" name="due" value={due()} prop:disabledDates={holidays} ref={(el) => el.addEventListener("ui-change", (e) => setDue(e.detail.value))} />
```

</Section>
