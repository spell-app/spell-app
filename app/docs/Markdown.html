Markdown Markdown text, such as a docstring, drawn as HTML.

How the app shows a docstring: the comment above a declaration, written as markdown, drawn as headings, bold, lists and links. Today it's the docstring at the top of the Type Explorer's details.

Written for: anyone changing the runners' debug pane, or reading its code Live: a real <spell-viewer>, its debug pane on the Type Explorer

Solitaire's Type Explorer. In its tree, open Card.spell under Solitaire and click Card: the line in bold under the breadcrumbs, "definition of a Card ...", IS this component, drawing Card's docstring (a ## comment, so a heading).

Live, from the app's element build, which this set's pages load: /element/spell.pack.js. The app package builds it with yarn build:element.

The ScopeDetailsPane draws a scope's docstring with it, when it's not being edited:

ScopeDetailsPane.tsx · a docstring · 3 lines
  • It draws GitHub-flavoured markdown as plain HTML tags, with Spell's own markdown package, written on its parser.
  • That package, and the parser under it, load the first time a Markdown is drawn: a runner's page carries no parser otherwise. Until then it shows the text as written.
  • A link clicked in it goes to onOpen, not the page: a link to a spell file, say, for the editor to open.
  • Raw HTML in the text is drawn as it is, but for <script> and the like: only give it text the app made.
