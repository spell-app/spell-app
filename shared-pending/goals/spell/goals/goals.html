Goals

What we're aiming for in three months, next year and someday — and what "shippable" means.

Status: draft · first pass, not yet talked through Updated: 2026-10-01 Notes for agents: goals.md

1. Summary
  • By December 31: spell is a shippable project: a website, docs, a downloadable app, and a language that holds up for small real programs.
  • Today: everything runs from a git checkout. Nothing is packaged, hosted, or published to npm.
  • A draft arc: October solid ground, November first spell in five minutes, December public preview (see the contents page).
  • The hard part: choosing what waits until 2027.

2. Today
  • A big September: TypeScript, the language server, the VS Code extension, Monaco, the explorers, @spell-app/ui (53 component families), the monorepo, and this docs system.
  • Waiting to merge: worktree-ui-component-creation (ui release prep) and worktree-cli-additions (ten new spell commands).
  • Paused:
    • the move from React to Solid (/Users/owen/www/spell-app/outstanding/solid-migration.md): needs a call on Solid rc.11 or rc.13
    • precedence and types (packages/docs/content/precedence/precedence.html): designed, nothing built, 14 decisions waiting on you
  • Unreviewed: much of the recent code says "not yet reviewed by a person".
  • Nothing ships yet: no npm packages, no website, no installer, no docs for people writing spells.

5. Questions
  1. Q1 What does "shippable" mean to you? public launch, or friends first?details

    Options: a quiet preview for friends; a public preview (website, "early" label); a 1.0.

    Suggestion: a public preview with an honest "early" label. It's enough pressure to finish things, and it doesn't promise that spells written now keep working.

  2. Q2 Who does December serve? settled in audiencedetails

    See audience/Q1.
  3. Q3 Merge order for the work in flight ui, cli, then Solid?details

    Suggestion: review and merge ui first (it's closest to done, and four WebKit failures wait on you), then cli, then decide on Solid.

  4. Q4 React to Solid: before or after the preview? touches the app, the runtime and how spells drawdetails

    Context: spells draw with React and SUI.* tags today. The Solid plan moves them to plain <ui-*> tags, so any UI tutorial written before it gets rewritten.

    Options:

    • before: ship on Solid and @spell-app/ui; the docs are written once
    • after: ship on React; migrate in 2027

    Suggestion: before, but only the parts a December spell touches (the runtime's drawing and the app shell), and only if October shows it can be done in about four weeks.

  5. Q5 How much time, and how many agents? hours a week; how many agents at oncedetails

    The plan should fit the real capacity. AGENTS.md mentions a five-agent cap.
  6. Q6 What waits until 2027? Windows, AI, translation, drag-and-drop, Python...details

    Suggestion: for December, leave out Windows, translation, drag-and-drop and Python. Keep a small AI experiment only if it helps the "first spell" story.
