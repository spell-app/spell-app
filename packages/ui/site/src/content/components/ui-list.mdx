<Section title="Behaviour">
  A list's children are the one generic [`<ui-item>`](../ui-item/):  the list tells each item how to render, so there is no
  `ui-list-item`.  An item with `href` is a link;  in a `selection` list every item is a button;  otherwise an item is a
  plain block that can hold anything.  A `<ui-list>` inside an item is its sub list, with the outer list's look.

  `ui-select` fires when a link or button item of the list is activated (click, Enter or Space);  `detail.value` is the
  item's `value`, else its text, and `detail.item` is the `<ui-item>`.  The list never moves `selected` itself, so the
  page decides what is chosen:

```js
const list = document.querySelector("ui-list[selection]")
list.addEventListener("ui-select", (event) => {
  for (const item of list.querySelectorAll(":scope > ui-item")) {
    item.toggleAttribute("selected", item === event.detail.item)
  }
})
```

</Section>

<Section title="Theming">
  Theme with the public `--ui-list-*` tokens:  set one on the element, on any ancestor (a region, `:root`), or on the
  list's box through `::part(list)`.  The items (and a nested list's items, through the `--ui-list-child-*` tokens)
  read them from the list, so set them there or above, not on an item.  A variation (`relaxed`, `celled` ...) swaps
  its own values in over yours.  Style an item's box with `ui-item::part(item)`.

```css
ui-list {
  --ui-list-item-border-color: var(--ui-primary);
  --ui-list-item-padding-block: 0.5em;
}
```

<Section title="Accessibility">
  - The shadow root holds a real `<ul>` (`<ol>` when `ordered`) with an explicit `role="list"`, since Safari drops list
    semantics from unstyled lists.  Each `<ui-item>` is a `listitem`.
  - Items with `href` are real links;  the `selected` one gets `aria-current="page"`.  In a `selection` list the items
    are `<button>`s and the selected one gets `aria-current="true"`.
  - `disabled` removes a link's `href` (and sets `aria-disabled`), or disables a button.
  - An item holding only an icon or image needs a name:  put `aria-label` on the `<ui-item>`.  The `image` shorthand is
    decorative (`alt=""`).
  - Every link or button item is its own Tab stop;  a list has no arrow-key navigation.

  | Key           | Action                                                      |
  | ------------- | ----------------------------------------------------------- |
  | Tab           | Move to the next link or button item                        |
  | Enter         | Follow a link item, or activate a button item (`ui-select`) |
  | Space         | Activate a button item (`ui-select`)                        |

  If the element can't render, its native fallback keeps the same `<ul>` / `<ol>` with the same class words, so the
  items keep their layout, numbering and links.  It drops `ui-select`, and a sub list is only recognised when it sits
  directly inside a `<ui-item>` or `<ui-list>`.
</Section>

<Section title="Framework usage">
  Define the elements first, then listen for `ui-select` with your framework's custom-event syntax.

```jsx
// React 19
<ui-list selection onui-select={(e) => setChoice(e.detail.value)}>...</ui-list>
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-list selection @ui-select="(e) => (choice = e.detail.value)">...</ui-list>
```

```jsx
// Solid 2:  no `on:` namespace, so listen from a ref
<ui-list selection ref={(el) => el.addEventListener("ui-select", (e) => setChoice(e.detail.value))}>...</ui-list>
```

</Section>
