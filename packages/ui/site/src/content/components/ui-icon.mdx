  (Font Awesome's dashed `circle-check` works too).  Brands and Fomantic's own names come in packs a page or a `<ui-root>` adds.  Browse and copy names in the [icon browser](../../icons/), which replaces Fomantic's long list of
  icon sets.

<Section title="Behaviour">
  `name` is the only thing an icon needs:  one name per icon, words separated by spaces (dashes work too).  A trailing
  `outline` names the regular icon;  `lucide:bell` asks one pack.

  Icons also work as the `icon` attribute of other components (`<ui-button icon="download">`), where they share this
  name resolution.  Icons have no events.

  **Icon packs.**  A pack is a folder of SVG files plus a `pack.js` index;  the page's packs are shared by every
  component.  Font Awesome 7 Free is the default.  Add more for a subtree with `<ui-root icons>`, a comma-separated
  list of built-in ids or `pack.js` URLs (the last pack wins a name;  a nested root adds to its outer root's packs):

  ```html
  <ui-root icons="fa7-brands">...</ui-root>                                  <!-- every brand logo -->
  <ui-root icons="fomantic">...</ui-root>                                    <!-- Fomantic's names -->
  <ui-root icons="fa7-free, /icons/lucide/pack.js">...</ui-root>             <!-- your own pack, after the default -->
  <ui-root icons="fomantic" assets="/assets/ui/">...</ui-root>               <!-- built-ins load from /assets/ui/icon-packs/ -->
  ```

  A page without a root adds them from JS:  `UI.icons.use("fa7-brands")`, with `{ prefix, base, only }` options.

  Turn any folder of SVGs into a pack with `yarn icons:pack <folder> --id <id>`;  see `docs/icons.md`.

</Section>

<Section title="Theming">
  Theme with the public `--ui-icon-*` tokens:  set one on the element, on any ancestor (a `<ui-icons>` group,
  `:root`), or on the box through `::part(icon)`.  They inherit into the shadow root, where the sheet reads each
  through a private alias, so nothing inside blocks them.  Size tokens (`--ui-icon-size-huge` ...) rescale a whole
  step;  `circular` and `bordered` replace the width and height.  The glyph itself takes `currentColor`, so `color`
  on the icon or its parent works too.

```css
:root {
  --ui-icon-distance: 0.5em;
}
.toolbar {
  --ui-icon-size-large: 1.25;
}
```

<Section title="Accessibility">
  - An icon is decorative by default:  `aria-hidden="true"` on the host, so screen readers skip it.
  - Give a meaningful icon a `label`:  the host becomes `role="img"` with that `aria-label`.
  - An icon that is the only content of a control (`<ui-button icon="cloud">`) needs the name on the control, not the icon.
  - `link` is only the look:  wrap the icon in a real `<a>` or `<button>` for interaction.
  - Without JavaScript the native fallback keeps the box (size, colour, ring), the `role` and the `label`, but not the glyph:  the SVG needs the icon data.
</Section>
