<Section title="Behaviour">
  Visibility is Fomantic's callbacks on an `IntersectionObserver`:  no scroll listener, nothing measured while the page
  scrolls.  The checks happen at crossings (the element entering or leaving, an edge crossing the screen's top or
  bottom), so `continuous` means "at each crossing", not "at every scrolled pixel".  `offset` moves the screen's top
  down, under a fixed menu.

  The element fires the checks as events, each with the calculations as `detail` (`topPassed`, `bottomVisible`,
  `percentagePassed`, `direction` ...), and keeps `:state(visible)` while any of it is on screen.  By default each
  event fires at most once (`once`, Fomantic's default);  `once="false"` fires it each time its condition turns true.

  | Event               | Fomantic's callback | When                                   |
  | ------------------- | ------------------- | -------------------------------------- |
  | `ui-visible`        | `onOnScreen`        | some of it came on screen              |
  | `ui-hidden`         | `onOffScreen`       | none of it is on screen                |
  | `ui-top-visible`    | `onTopVisible`      | its top came on screen                 |
  | `ui-bottom-visible` | `onBottomVisible`   | its bottom came on screen              |
  | `ui-top-passed`     | `onTopPassed`       | its top passed the screen's top        |
  | `ui-bottom-passed`  | `onBottomPassed`    | its bottom passed the screen's top     |
  | `ui-passing`        | `onPassing`         | it spans the screen's top              |

  `UI.observeVisibility(element, options)` runs the same checks on any element, without wrapping it.  It takes
  Fomantic's names, including the `...Reverse` callbacks (the condition turned false again) and `onUpdate` (every
  check), plus `once`, `continuous`, `offset` and `context` (a scroll container to measure against).  It returns
  the function that stops watching.

  `type="image"` is Fomantic's lazy image loading:  each `<img data-src>` (and `data-srcset`) inside gets its
  source once it's on screen, preloaded, then fades in;  `ui-load` fires per image.  For images alone, the browser's
  own `loading="lazy"` needs no script at all;  `type="image"` adds the fade and the event.

</Section>

<Section title="Theming">
  A visibility draws nothing:  it's a plain block around its content.  Style it through `::part(visibility)`, and the
  images' fade with `transition` and `duration`.

<Section title="Accessibility">
  - Visibility changes nothing for assistive technology:  it watches, and its content reads as usual.
  - Don't hide content until it's scrolled to:  keyboard and screen reader users move through a page without
    scrolling it the way a mouse does.  Load more, or animate, but keep the content reachable.
  - Lazy images keep their `alt` and their `width` / `height`, so the layout doesn't jump when they load.
  - If the element can't render, its native fallback gives every `<img data-src>` its source at once, with
    `loading="lazy"`, so the browser still defers them and no image stays empty.  The events are lost.
</Section>

<Section title="Framework usage">
  Listen for the events you need;  in a component, `UI.observeVisibility()` in a mount hook, and call what it
  returns on unmount.

```jsx
// React 19
<ui-visibility once="false" onui-bottom-visible={loadMore}>...</ui-visibility>
useEffect(() => UI.observeVisibility(ref.current, { onTopPassed: showBackToTop, once: false }), [])
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-visibility once="false" @ui-bottom-visible="loadMore">...</ui-visibility>
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<ui-visibility once="false" ref={(el) => el.addEventListener("ui-bottom-visible", loadMore)}>...</ui-visibility>
```

</Section>
