<Section title="Behaviour">
  The element is a real `<select>` in Fomantic's look, so the keyboard, type-ahead, the phone's picker wheel or sheet,
  and screen-reader support are all the browser's.  It is a form control:  `name` and `value` submit with the form
  (`multiple` sends one entry per value), `required` validates, and a form reset puts back the starting `value`.
  Options come from slotted `<ui-item>`s, then the `options` property (the same shape as a dropdown's).  `ui-change`
  fires when the user picks, with `{ value }`.

```js
const select = document.querySelector("ui-select")
select.options = [{ value: "xl", text: "Extra large" }]
select.addEventListener("ui-change", (event) => console.log(event.detail.value))
```

  ### Select or dropdown?

  | Use `<ui-select>` when | Use [`<ui-dropdown>`](../ui-dropdown/) when |
  | --- | --- |
  | a form field picks from a fixed list | the user types to filter (`search`), adds values or clears them |
  | the platform picker matters:  phones' wheels and sheets, native type-ahead, a no-script fallback | chosen values show as labels (`multiple`), or the menu holds rich content |
  | icons and flags in options are nice to have, not essential | it isn't a form field:  an action menu, `inline`, `button`, `pointing` |

<Section title="Theming">
  Theme with the public `--ui-select-*` tokens:  set one on the element, on any ancestor (a form, `:root`), or on the
  select's box through `::part(select)`.  They inherit into the shadow root, where the sheet reads each through a
  private alias, so nothing inside blocks them.  Style the rest with `::part()`:  `button`, `option`, `placeholder`
  and `group`.

```css
ui-select {
  --ui-select-radius: 0;
}
ui-select::part(option) {
  padding-block: 0.75em;
}
```

<Section title="Accessibility">
  - The shadow root holds one native `<select>`:  its role, keyboard and announcements are the browser's.
  - Name it with `aria-label` on the host, or a `<label for>` pointing at the host.  The `placeholder` alone is not a
    name.
  - While nothing is chosen, an empty first option shows the placeholder, so the browser never quietly picks the
    first real option;  `required` makes that empty option unselectable.
  - `state="error"` is only a look;  `aria-invalid` follows the select's own validation (`required`).
  - If the element can't render, its native fallback is the same `<select>` with the same options and value, so it
    still works and submits;  option icons and images are dropped, and a `<label for>` on the host no longer names
    it (use `aria-label`).
</Section>

<Section title="Framework usage">
  Set `options` as a property, not an attribute, and listen for `ui-change`.

```jsx
// React 19
<ui-select name="size" options={sizes} value={size} onui-change={(e) => setSize(e.detail.value)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-select name="size" :options="sizes" :value="size" @ui-change="(e) => (size = e.detail.value)" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref;  `prop:` for the property
<ui-select name="size" prop:options={sizes} value={size()} ref={(el) => el.addEventListener("ui-change", (e) => setSize(e.detail.value))} />
```

</Section>
