3.3 Icon packs
  • Icons are SVG files in packs: a folder of SVGs + a generated pack.js index (file, size, aliases). Built-in: fa7-free (default), fa7-brands, fomantic.
  • UI.icons (runtime, page-wide): use(), reset(), resolve(), get(), peek(), register(); <ui-icon-set src> from HTML. Design: packages/ui/docs/icons.md.
  • Contract: get() never rejects -- a missing icon draws nothing. Broken today (I1), fixed in P2.
  • Single-file (IIFE) pages: packages/docs/scripts/bundle-spell-ui.js calls reset() + register() for the icons it bundles, so nothing is fetched.

5. Issues
  1. I1 UI.icons.get() can reject, though documented never todetails

    BuiltInPacks.url() throws Invalid URL when BuiltInPacks.base is empty (IIFE bundle), inside IconPacks.add(), reached from ready, so get() rejects. IconGlyph.load() is fire-and-forget: every icon becomes an unhandled page error. Fix in P2.

  2. I2 yarn test:hmr broken since the move: $/ui alias not resolved from ?inline sheetsdetails

    Vite 8's resolve.tsconfigPaths only resolves aliases for TS / JS importers; solidElementHot() injects $/ui/elements/HotDefinitions into the .css?inline modules. Fixed: vite.config.ts injects it by file path. 8/8 pass.

  3. I3 yarn site:build broken since the move: Astro's prerender gets express's cookie 0.7.1details

    Astro 7 inlines its runtime into site/dist/.prerender/ and leaves cookie external, which then resolves to the root's hoisted 0.7.1. Fixed: environments.prerender.resolve.noExternal bundles it. 60 pages. Not caught by CI: CI doesn't run the site build (T6).
