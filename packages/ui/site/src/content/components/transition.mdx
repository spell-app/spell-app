<Section title="Behaviour">
  `visible` drives the element:  absent means hidden, and each change animates `animation` in or out.  The first
  paint never animates.  `animation` takes Fomantic's names, spaces and all (`fade up`, `horizontal flip`,
  `browse right`);  `duration` takes milliseconds (`300`) or a CSS time (`0.3s`).

  There is no attribute for "shake now", so the host has methods, each resolving once its animation has run:
  `show()`, `hide()`, `toggle()` and `transition(name?)` (Fomantic's `$(el).transition(name)`:  `animate` is the Web
  Animations API's).  `show()` / `hide()` / `toggle()` write `visible`, so it reflects.  Invoker commands do the same
  with no script:  `--show`, `--close`, `--toggle` and `--transition`.

  Animations queue, as Fomantic's did:  each waits for the one before, and the same animation twice in a row is
  dropped (`allow-repeats` keeps it).  With `interrupt`, a new animation stops the running one instead.
  `ui-show` / `ui-hide` fire once an in / out animation has finished (`{ visible, animation }`);  `ui-complete`
  after every animation.

```js
const notice = document.querySelector("#notice")
await notice.hide() // resolves once animated out
await notice.transition("shake") // attention:  in place
notice.addEventListener("ui-show", (event) => console.log(event.detail.animation))
```

  Under reduced motion the end state comes at once, and the events fire all the same.  To animate an element
  without wrapping it, the runtime's `UI.transitions` plays the same catalogue on any element.

</Section>

<Section title="Theming">
  A transition draws nothing of its own:  the animations are the foundation's `animations.css` catalogue, shared by
  every component.  Style the animated box through `::part(transition)`.

```css
ui-transition::part(transition) {
  border-radius: 0.5em;
}
```

<Section title="Accessibility">
  - Hidden content is out of the page and the accessibility tree, as `hidden` would make it:  nothing inside can take
    focus or be read.
  - Showing or hiding content doesn't announce anything by itself;  if the change matters, say so in a live region
    or move focus to it.
  - Under `prefers-reduced-motion` the element jumps straight to its end state, with the same events.
  - Drive transitions from real buttons (`commandfor`), so keyboard and screen reader users can reach them.
  - If the element can't render, its native fallback still follows `visible` at once, with no animation, and still
    fires `ui-show` / `ui-hide` and `ui-complete`.
</Section>

<Section title="Framework usage">
  Bind `visible`, and call the methods through a ref for attention animations.

```jsx
// React 19
<ui-transition animation="fade up" visible={shown} ref={box} onui-hide={() => setGone(true)}>...</ui-transition>
// later:  box.current.transition("shake")
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-transition ref="box" animation="fade up" :visible="shown" @ui-hide="gone = true">...</ui-transition>
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<ui-transition animation="fade up" visible={shown()} ref={(el) => el.addEventListener("ui-hide", () => setGone(true))}>
  ...
</ui-transition>
```

</Section>
