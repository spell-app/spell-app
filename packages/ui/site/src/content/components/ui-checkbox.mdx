<Section title="Behaviour">
  Both elements are real form controls.  While chosen, a checkbox submits `name=value` with its form (`value` defaults
  to `on`, as natively);  unchosen, it submits nothing.  A radio group submits the chosen radio's `value`.
  `form.reset()` restores the starting state, a disabled `<fieldset>` disables them, and `required` asks for a choice
  (on a radio, any member makes the whole group required).

  `selected` is the chosen state, as an attribute and a property.  `checked` is an alias:  the `checked` attribute in
  markup selects the box, and `el.checked` reads and writes `el.selected`.

  Radios group by `name` within their form, or the whole page when there is none, even though each `<ui-radio>`
  keeps its input in its own shadow root.  Choosing one unchooses the others without firing events on them.

  `ui-change` fires when the user chooses or unchooses (for a radio, only on the newly chosen one), BEFORE the state
  changes;  a handler that sets `selected` back vetoes the change.

```js
const terms = document.querySelector("ui-checkbox[name=terms]")
terms.addEventListener("ui-change", (event) => {
  if (!event.detail.selected && !confirm("Really opt out?")) terms.selected = true
})
document.querySelector("ui-radio[value=day]").checked = true // same as .selected = true
```

<Section title="Theming">
  Theme with the public `--ui-checkbox-*` tokens:  set one on the element, on any ancestor (a form, `:root`), or on
  the root box through `::part(checkbox)`.  They inherit into the shadow root, where the sheet reads each through a
  private alias, so nothing inside blocks them;  radios, sliders and toggles read the same set.  `inverted` swaps in
  its own `--ui-checkbox-inverted-*` colours.  Style the other pieces with `::part()`:  `control` and `label`.

```css
ui-checkbox,
ui-radio {
  --ui-checkbox-toggle-lane-on: var(--ui-positive);
  --ui-checkbox-radius: 0;
}
```

<Section title="Accessibility">
  - The shadow root holds a real `<input type="checkbox">` (or `radio`) tied to a `<label>`, so clicking the label,
    Space, and the checked state come from the browser.  `delegatesFocus` keeps the host out of the tab order and
    draws the focus ring on the box.
  - Toggles and sliders are `role="switch"` (on / off);  an `indeterminate` checkbox reports `aria-checked="mixed"`;
    `readonly` sets `aria-readonly` and cancels clicks.
  - The accessible name is the label text.  A `fitted` box has none, so give it an `aria-label` or a `<label for>`
    pointing at the host.
  - Wrap a radio group in `role="radiogroup"` with a name (`aria-label` or `aria-labelledby`), as the examples do.
  - Only the chosen radio of a group (else the first enabled one) is a tab stop, as with native radios.
  - A box that fails `required` after the user has interacted gets `aria-invalid="true"`.

  | Key                       | Action                                                                  |
  | ------------------------- | ----------------------------------------------------------------------- |
  | Space                     | Toggle the checkbox;  choose the focused radio                          |
  | Arrow Down / Arrow Right  | Radio:  choose the next enabled radio of the group and focus it (wraps) |
  | Arrow Up / Arrow Left     | Radio:  choose the previous enabled radio of the group (wraps)          |
  | Tab                       | Move into or out of a radio group, through its one tab stop             |

  Without JavaScript the native fallback keeps the same markup with a plain native input:  it still submits, validates
  `required` and fires `ui-change`.  It drops grouping radios across elements (each fallback radio stands alone, with
  no arrow keys), vetoing `ui-change`, the invalid state, reset to the starting state, and naming a `fitted` box
  through `<label for>` (only `aria-label` works).
</Section>

<Section title="Framework usage">
  Bind `selected` as a property to control the box, and listen for `ui-change`.

```jsx
// React 19
<ui-checkbox name="news" selected={on} onui-change={(e) => setOn(e.detail.selected)}>Newsletter</ui-checkbox>
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-checkbox name="news" :selected="on" @ui-change="(e) => (on = e.detail.selected)">Newsletter</ui-checkbox>
```

```jsx
// Solid 2:  no `on:` namespace, so listen from a ref callback
<ui-checkbox
  name="news"
  prop:selected={on()}
  ref={(el) => el.addEventListener("ui-change", (e) => setOn(e.detail.selected))}
>
  Newsletter
</ui-checkbox>
```

</Section>
