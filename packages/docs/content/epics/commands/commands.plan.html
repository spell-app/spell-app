Q3 One naming scheme: noun then verb?
D3 · Noun then verb: spell dev server start = yarn server:start; spell-language verbs stay bare; skills keep short names

Today yarn mixes docs:new (noun:verb) with start:server (verb:noun), colons with dashes (plan-doc, install-extension). The CLI is spell <noun> <verb> for tools (spell plan-doc add) but bare verbs for spell itself (spell compile).

Operation CLI yarn skill

new doc page spell docs new docs:new —

compile spell spell compile (none) —
  • Recommended: noun then verb everywhere (CLI words = yarn noun:verb, dashes inside a word); spell-language verbs stay bare, since spell IS the noun.

C1 The commands page needs the page server

The commands page draws its tables only when the page server serves it. Opened straight from disk, it shows a notice where the tables would be.

  • Why: it fetches its data, commands.json, and a file:// page can't.
  • Your choice, in the decision on how to store the data (D4): a plain JSON file, over a JS data file or tables written into the HTML.
  • Open it with yarn docs:open dev/commands/commands.html, which uses the server.

Net effect:

  • nothing changes: an accepted limit of the JSON choice
C2 Which checkout spell dev works on

The spell command on your path runs from one checkout, but you often use it inside a worktree. Its dev commands must work on the files where you are, not on the checkout spell came from.

  • yarn cli:install links spell to one checkout, normally the main one.
  • So every spell dev command must find the nearest checkout from the current folder, as spell plan-doc and spell goals do.
  • Looks done or obsolete: findCheckout() (findCheckout.ts) does exactly this, and its docstring says every spell dev command uses it (checked 2026-10-04).

Net effect:

  • spell dev ... in a worktree reads and edits that worktree's files
C3 The CLI takes about half a second to start

Every spell command spends about half a second starting up, because it compiles its TypeScript source on the fly with tsx.

  • Fine for a person typing a command.
  • It adds up in a skill that calls spell many times in one run.
  • Example, measured 2026-10-04: node packages/cli/bin/spell.mjs --version took 0.57s, three runs in a row.
  • The fix on the roadmap: a single-file bundle (todo T2 of the cli-additions epic).

Net effect:

  • nothing changes until the bundle exists
C4 The filter leaves the contents sidebar alone

On the commands page, typing in the filter hides rows, and families with no rows left. The contents column on the right still lists every family.

  • Example: filter on worktree, and the page shows only the worktree rows, but the contents still lists every family, most of them now empty on the page.
  • Why: the page runtime's own filter (wireFilter()) only knows cheat-sheet cards; the commands page has its own, in _assets/commands.js.
