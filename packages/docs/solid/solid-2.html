Spell on Solid 2

What spell needs to know about Solid 2 that the Solid docs don't tell you.

  • Written for whoever ports spell's runtime, editor and web components from React
  • Also for anyone reasoning about spell reactivity afterwards

Solid 2.0.0-rc.13 (current, 2026-09-30), researched on rc.11 -- which @spell-app/ui still pins.

  • Every experiment behaves the same on rc.11 and rc.13; see rc.11 vs rc.13
  • Researched 2026-09-30
  • Measurements: Node 22, M-series Mac; one warm run in the early tables, a median of 9 where a table says so
  • Quick reference: Solid 2 Cheat Sheet

The four newest posts on the Solid blog build one idea: the reactive graph always knows. Here it is compressed, with what each part means for us.

A component is a setup function that runs a single time.

  • No re-render and no diff
  • Each dynamic JSX expression compiles to its own tiny tracking scope
  • Props arrive as lazy getters, so "passing isn't reading"
  • When a signal changes, only expressions that read it re-run and patch their text node or attribute
  • Today a spell draw() is re-run by React whenever any property it read changed, and React diffs the result
  • Solid does neither
  • If we re-ran draw() ourselves we'd rebuild DOM from scratch, and a focused input would lose focus on each keystroke
  • So compiled output must hand Solid functions for everything that can change (class: () => ..., children: [() => ...])
  • Without a JSX compiler, as in @solidjs/h hyperscript, nothing else makes an expression reactive
  • Parser already knows which expressions are literals, so emitting those thunks is cheap

Solid 2 batches every write.

  • A write is staged and committed with all its neighbours on the next microtask, or when you call flush()
  • Until then every read returns the last committed value, even a read on the very next line
  • That is the price of the headline guarantee: "at no point does the UI disagree with itself"
  • There is no batch(), because everything is a batch

A memo may return a Promise.

  • Everything downstream just waits
  • <Loading> covers only the first load
  • Once a value has shown, a new write that feeds async work is held:
    • old content stays on screen until the new answer lands
    • every other write in the same batch is held with it
  • That's what replaced transitions
  • isPending(x) asks "is something on the way?"; latest(x) asks "what is it?"
  • Both are questions you can ask anywhere, not state you must keep

action(function* () { ...; yield api.save(); refresh(src) }) holds a transaction open across awaits.

  • Optimistic writes (createOptimistic, createOptimisticStore) are a layer over the confirmed value
  • Layer is dropped when the action settles, pass or fail, so there's no rollback code
  • Errors are just another status of part of the graph: <Errored> heals by itself when the data underneath recovers

Two more measured facts shape the options.

  • An unowned, non-lazy memo recomputes on every flush that touches its inputs, forever, even with no readers
  • A lazy memo tears itself down whenever it has no subscribers, so from untracked spell code it recomputes on every read and memoizes nothing

Each was prototyped on a Card with stored suit and rank, and derived color and label, plus a Todos with an "incomplete count" over 1000 tasks.

  1. N — record + notifiers. Values live in a plain per-instance record. A lazily-made Solid signal per property is bumped on write, only so Solid knows what changed. Derived values stay plain getters.
  2. F — Solid-native, flush per write. One signal per property. Every spell write is flush(() => set(v)). Derived values are createMemos, one per instance.
  3. X — "spell cells": record + a small synchronous reactive core, bridged into Solid.
    • Values live in the record
    • Our own ~100-line core tracks dependencies synchronously and memoizes derived values
    • enableExternalSource makes every Solid computation that reads spell state re-run when it changes
  4. Something Solid provides. Nothing fits: latest doesn't see synchronous writes, lazy memos read committed values, and there's no mutable store any more. The only built-in route to fresh reads is flush(), which is F.

Two things stand out.

  • First, memoizing a cheap derivation costs more than recomputing it: X reads label about 2× slower than a plain getter
  • Second, memoizing an aggregate wins big: 6× faster
  • So "memoize every derived value" is the wrong rule
    • "Memoize what's worth it" is the right one
    • The parser can decide that (below)
  • The absolute numbers are small either way
  • Nothing here will be spell's bottleneck; the choice is about correctness
  • Only candidate that:
    • is exact with no exceptions
    • memoizes derived values
    • lets draw() write freely
  • Also replaces the mutable store Solid 2 removed, which the editor needs anyway
  • Keep derived values as plain getters unless the parser marks them worth memoizing

F is the runner-up if we ever want zero reactive code of our own.

  • It has a real correctness hole, though (a spell set read back stale when entangled with async), plus per-object disposal
  • N is the fallback if enableExternalSource ever misbehaves
    • It's X without memoization
    • The two share the record, so switching is local to ~/util

The parts

record A Map per instance, the only truth. Read and written synchronously. Keys stay in creation order. cell Per property, made lazily the first time something tracking reads it, plus one keys cell per instance. Holds a version and its subscribers. derived A memo in our core: cached value, state (clean / check / dirty), and the version of each source it read. Its version bumps only when its value really changes. schema Per class: declared props (type, default) from the parser, and the types observed for undeclared props. bridge One enableExternalSource adapter. A node per Solid computation calls Solid's trigger() only on a real change.

A write, step by step

  1. Construct. new Card({ suit: "hearts" }):
    • Each prop goes through setProp, so types are checked, then create() runs
    • No cells exist yet, so it's just Map writes
    • Unset props read their default from the schema; a default isn't a key until it's set
  2. Spell reads. getProp("suit") returns the record's value.
    • If something is collecting (a derived value or a Solid computation), it also links that collector to the suit cell and records the cell's version
    • At top level nothing is collecting, so it costs nothing
  3. Spell writes. setProp("suit", "clubs") returns at once if the value is ===.
    • Otherwise it writes the record, bumps the cell's version and marks its direct readers dirty
    • A dirty derived value marks its readers check: maybe changed, not known yet
    • Nothing is recomputed, and the next line already reads "clubs"
  4. Derived reads. card.color:
    • clean: the cache
    • check: refresh its derived sources first; if none of their versions moved, it's clean again with no recompute
    • dirty: recompute, and bump its own version only if the result differs (!==)
    It's current on the very next line after a write. Pull-based, so glitch-free.
  5. Drawing. A thunk like class: () => this.color runs inside a Solid render effect. The bridge makes that effect's node the collector, so reading color links it.
  6. UI update, only on differences.
    • a bridge node read a cell that changed (dirty): it triggers Solid at once
    • it only read derived values (check): it's re-validated in a microtask, and triggers only if one of them really changed
    • Solid re-runs just that thunk, reading the fresh record
    • its DOM binding writes only if the text or attribute differs
      • insert returns early on === and assignProp on value === prev (rc.11 and rc.13 source)
      • Input value / checked are the exception: always re-applied
    Measured, with color red for both hearts and diamonds:
    • after hearts → diamonds, a reader of a memoized color did not re-run
    • a reader of a plain getter re-ran, and its binding skipped the DOM write
    • after → clubs both re-ran
    The DOM lags spell by one microtask, as React's batched render did.
  7. flush for spell.
    • Derived checks wait for a microtask, so Solid's flush() alone can miss them
    • Tests and imperative code call spellCore.flush(), which runs pending checks and then Solid's queue
  8. Lists. One items cell per List, changed by every mutating method. <For> keeps rows by item identity, so Things are keyed naturally.
  9. Editor store. createStore(defaults) becomes a deep Proxy on the same cells, so editor.foo = x keeps working everywhere, with no draft setters. This is where a Proxy belongs; see Accessors or a Proxy?

The prototype

The prototype, in TypeScript (core, types, strategy A): docs/solid/experiments/spell-cells.ts 
////////////////
// ## Core:  cells, derived values, the Solid bridge
//    Push-pull with an equality cutoff:  a write marks direct readers DIRTY and everything further down CHECK;
//    a CHECK reader re-validates by pulling its derived sources, and only re-runs if one REALLY changed.
////////////////

const CLEAN = 0
const CHECK = 1
const DIRTY = 2
type State = typeof CLEAN | typeof CHECK | typeof DIRTY

/** Anything a computation can read:  a cell or a derived value.  `version` bumps on every REAL change. */
type Source = { subs: Set<Observer>; version: number }

/** Anything that reads sources:  a derived value, or a Solid computation (via the bridge). */
type Observer = { srcs: Map<Source, number>; mark(state: State): void }

let collector: Observer | null = null

/** Subscribe the current collector to `src`, remembering the version it saw. */
function link(src: Source) {
  if (!collector) return
  src.subs.add(collector)
  collector.srcs.set(src, src.version)
}

function unlinkAll(observer: Observer) {
  for (const src of observer.srcs.keys()) src.subs.delete(observer)
  observer.srcs.clear()
}

/** Run `fn` with `observer` collecting what it reads. */
function track<T>(observer: Observer, fn: () => T): T {
  unlinkAll(observer)
  const outer = collector
  collector = observer
  try {
    return fn()
  } finally {
    collector = outer
  }
}

/** Did any source change since `observer` read it?  Refreshes derived sources first (the "pull"). */
function sourcesChanged(observer: Observer): boolean {
  for (const [src, seen] of observer.srcs) {
    if (src instanceof Derived) src.refresh()
    if (src.version !== seen) return true
  }
  return false
}

class Cell implements Source {
  subs = new Set<Observer>()
  version = 0

  /** Call ONLY for a real change -- `setProp` already skips `===` writes. */
  changed() {
    this.version++
    for (const sub of [...this.subs]) sub.mark(DIRTY)
  }
}

class Derived<T> implements Source, Observer {
  subs = new Set<Observer>()
  srcs = new Map<Source, number>()
  version = 0
  state: State = DIRTY
  value!: T

  constructor(
    private fn: (this: unknown) => T,
    private self: unknown
  ) {}

  mark(state: State) {
    if (this.state >= state) return
    const wasClean = this.state === CLEAN
    this.state = state
    if (wasClean) for (const sub of [...this.subs]) sub.mark(CHECK)
  }

  /** Bring `value` up to date;  bump `version` only if the new value differs. */
  refresh() {
    if (this.state === CHECK) this.state = sourcesChanged(this) ? DIRTY : CLEAN
    if (this.state !== DIRTY) return
    const next = track(this, () => this.fn.call(this.self))
    this.state = CLEAN
    if (this.version === 0 || next !== this.value) {
      this.value = next
      this.version++
    }
  }

  get(): T {
    this.refresh()
    link(this)
    return this.value
  }
}

/** One per Solid computation that reads spell state. */
class BridgeNode implements Observer {
  srcs = new Map<Source, number>()

  constructor(private trigger: () => void) {}

  mark(state: State) {
    if (state === DIRTY) this.trigger() // a cell it read directly changed:  a real change
    else scheduleCheck(this) // only derived values it read MAY have changed
  }

  check() {
    if (sourcesChanged(this)) this.trigger()
  }
}

const pendingChecks = new Set<BridgeNode>()
let checkScheduled = false

function scheduleCheck(node: BridgeNode) {
  pendingChecks.add(node)
  if (checkScheduled) return
  checkScheduled = true
  queueMicrotask(runChecks)
}

function runChecks() {
  checkScheduled = false
  const nodes = [...pendingChecks]
  pendingChecks.clear()
  for (const node of nodes) node.check()
}

/** Spell's `flush()`:  settle pending derived checks, THEN Solid's queue.  Tests and imperative code call this. */
function flushAll() {
  runChecks()
  flush()
}

enableExternalSource({
  factory(fn: (prev: unknown) => unknown, trigger: () => void) {
    const node = new BridgeNode(trigger)
    return {
      track: (prev: unknown) => track(node, () => fn(prev)),
      dispose() {
        unlinkAll(node)
        pendingChecks.delete(node)
      }
    }
  },
  untrack<T>(fn: () => T): T {
    const outer = collector
    collector = null
    try {
      return fn()
    } finally {
      collector = outer
    }
  }
})

// ## Property types

/** Spell's name for a value's type:  `number`, `text`, `yes/no`, `list`, a Thing class name, ... */
function spellTypeOf(value: unknown): string {
  if (value === null || value === undefined) return "nothing"
  switch (typeof value) {
    case "number":
      return "number"
    case "string":
      return "text"
    case "boolean":
      return "yes/no"
    case "function":
      return "action"
  }
  if (Array.isArray(value)) return "list"
  return (value as object).constructor?.name ?? "object"
}

type PropInfo = { type?: string; default?: unknown }

/** Per-class schema:  declared props (from the parser) + types observed for undeclared ones. */
class Schema {
  observed = new Map<string, Set<string>>()
  typeWarnings = 0

  constructor(
    public declared: Record<string, PropInfo>,
    public parent?: Schema
  ) {}

  /** NOTE:  own keys only -- `{}["constructor"]` is inherited, and a proxy asks about EVERY key. */
  info(name: string): PropInfo | undefined {
    return Object.hasOwn(this.declared, name) ? this.declared[name] : this.parent?.info(name)
  }

  /** Check `value` against the declared type, else widen the observed type set.  Warn, never throw. */
  checkType(name: string, value: unknown) {
    if (value === undefined) return
    const type = spellTypeOf(value)
    const declared = this.info(name)?.type
    if (declared) {
      if (declared !== type) this.typeWarnings++
      return
    }
    let seen = this.observed.get(name)
    if (!seen) this.observed.set(name, (seen = new Set()))
    if (seen.size && !seen.has(type)) this.typeWarnings++
    seen.add(type)
  }

  typeOf(name: string): string {
    return this.info(name)?.type ?? ([...(this.observed.get(name) ?? [])].join(" | ") || "unknown")
  }
}

// ## Strategy A:  accessors on the prototype, record in a `Map`

const RECORD = Symbol("record")
const CELLS = Symbol("cells")
const KEYS = Symbol("keys")
const DERIVED = Symbol("derived")

class ThingA {
  static schema = new Schema({});
  [RECORD] = new Map<string, unknown>();
  [CELLS]: Map<string, Cell> | null = null;
  [KEYS]: Cell | null = null;
  [DERIVED]: Map<string, Derived<unknown>> | null = null

  constructor(props: Record<string, unknown> = {}) {
    for (const key in props) this.setProp(key, props[key])
  }

  getProp<T>(name: string): T {
    if (collector) link(cellFor(this, name))
    const record = this[RECORD]
    if (record.has(name)) return record.get(name) as T
    return (this.constructor as typeof ThingA).schema.info(name)?.default as T
  }

  setProp(name: string, value: unknown) {
    const record = this[RECORD]
    if (value === undefined) return this.deleteProp(name)
    const added = !record.has(name)
    if (!added && record.get(name) === value) return
    ;(this.constructor as typeof ThingA).schema.checkType(name, value)
    record.set(name, value)
    notifyProp(this, name, added)
  }

  deleteProp(name: string) {
    if (!this[RECORD].delete(name)) return
    notifyProp(this, name, true)
  }

  /** Own keys in creation order.  Tracks the key SET only:  an overwrite doesn't re-run a reader. */
  keys(): string[] {
    if (collector) link((this[KEYS] ??= new Cell()))
    return [...this[RECORD].keys()]
  }

  derive<T>(name: string, fn: (this: this) => T): T {
    const derived = (this[DERIVED] ??= new Map())
    let d = derived.get(name)
    if (!d) derived.set(name, (d = new Derived(fn, this)))
    return d.get() as T
  }
}

function cellFor(thing: ThingA, name: string): Cell {
  const cells = (thing[CELLS] ??= new Map())
  let cell = cells.get(name)
  if (!cell) cells.set(name, (cell = new Cell()))
  return cell
}

function notifyProp(thing: ThingA, name: string, keysChanged: boolean) {
  thing[CELLS]?.get(name)?.changed()
  if (keysChanged) thing[KEYS]?.changed()
}

let colorRuns = 0

class CardA extends ThingA {
  static schema = new Schema({ suit: { type: "text", default: "hearts" }, rank: { type: "number", default: 1 } })

  get suit(): string {
    return this.getProp("suit")
  }
  set suit(value: string) {

  }
}

What the parser decides

A derived property compiles to one of two forms:

TypeScript · 17 lines 
class Card extends Thing {
  // plain:  one comparison -- recomputing is cheaper than caching
  get color() {
    return this.suit === "hearts" || this.suit === "diamonds" ? "red" : "black"
  }
}

class Todos extends Thing {
  // memoized:  pure (reads only cells) AND worth it (iterates a list)
  get incomplete() {
    return this.derive("incomplete", function () {
      let count = 0
      for (const task of this.tasks) if (!task.done) count++
      return count
    })
  }
}
  • Pure means it reads only spell state that goes through cells:
    • properties of this and of other Things
    • List items
    • literals and pure core helpers
    • Reading a top-level let, the clock, randomness or spellCore.RUNTIME makes it impure
    • An impure memo would go stale forever, so impure means plain
  • Worth it means it iterates (for each, list operations) or calls other derived values or methods. A single comparison or concatenation stays plain; the benchmark shows that's faster.
  • Memoizing also buys the equality cutoff above. A derived value read by a lot of UI, such as a game's "is over", can be worth memoizing for that alone.
  • All of this is static fact about the AST, known at compile time. It's the one place where "Solid-compatible output" means something: the output says what may be cached, without decorators.
  • Later, top-level spell lets could become cells too, which widens what counts as pure.

Semantics

  • keys() lists a Thing's own properties in the order they were first set.
    • An overwrite keeps the position
    • A delete (deleteProp, or setting undefined) takes the key out
    • Setting it again appends it at the end
  • The record must be a Map, not a plain object.
    • Objects hoist integer-like keys to the front, sorted: b, 10, a, 2 comes back as ["2", "10", "b", "a"]
    • A Map gives ["b", "10", "a", "2"]
    • And a Map was no slower: 15.5 ms vs 18.8 ms for 2M sets + 2M gets
  • keys() tracks a per-instance keys cell, changed only when the key set changes. So a Thing Explorer row list re-renders when a property appears or disappears, not on every value change.
  • Unset declared props with defaults aren't keys: they were never created on this instance. For display, list the schema's declared props in declaration order, then the rest of keys().

Where types come from

Each class's schema knows a type per property.

  • Declared types come from the parser:
    • an explicit specifier (as text, one of ...)
    • or the type of a default literal
  • Undeclared properties get their type observed, per class, on write
  • undefined / nothing never counts as a type

Policies

Policy Catches mistakes Cost Downside
Declared only for declared props nothing at runtime undeclared props show no type
Fixed on first write (type never changes) yes: any later mismatch one typeof + compare per write false alarms for legitimately mixed props, e.g. number or text answers. What to do with the value? Reject breaks programs; store-and-warn means the fixed type is a lie.
Widen on mismatch (a union) yes, as a dev warning same, plus a Set per undeclared prop per class after one bad write the type is permanently wider
Per instance per object a type per prop per instance memory for no real gain: a class's instances share their shape

Recommendation

  • For undeclared props: observe per class, widen on mismatch, and warn in dev
  • Never throw, since spell is forgiving
  • The schema answers typeOf(name) for the Thing Explorer and the language server
  • No speed payoff either way. With a Map record, V8's hidden classes don't apply, so a stable type buys tooling and bug-catching, not speed.
  • Thing-typed props must compare with instanceof, not by name, or a FaceCard in a Card prop warns. The prototype compares names; Phase 1 fixes it.
  • Types are per class, not per instance. A subclass's schema chains to its parent's.

What it would look like

Instead of an accessor pair per property, each Thing is a Proxy that routes properties to the record. Compiled output shrinks to a schema:

Two Proxies, measured

  • P, naive: wrapped at the end of the constructor, routing declared or recorded keys
  • P2, every prop through the Proxy:
    • the base constructor wraps FIRST: props, create() and registration all see the Proxy
    • subclass field initializers land in the defineProperty trap as defaults, applied only if the key is unset
    • prototype members (methods, getters) take a fast path, from a per-class key set cached on the instance
    • #private fields are banned in Thing subclasses; compiled spell never emits them
  • Both pass every correctness check: read-after-write, the Solid bridge, key order, types, the equality cutoff

const PROTO_KEYS = new WeakMap<object, Set<PropertyKey>>()

/** The instance's own cached copy of `protoKeys()`:  one property read per trap instead of a `WeakMap` lookup. */
const PROTO = Symbol("protoKeys")

/** Every key on the prototype chain below `Object.prototype`:  methods, getters, setters. */
function protoKeys(target: object): Set<PropertyKey> {
  const proto = Object.getPrototypeOf(target)
  let keys = PROTO_KEYS.get(proto)
  if (keys) return keys
  keys = new Set()
  for (let p = proto; p && p !== Object.prototype; p = Object.getPrototypeOf(p)) {
    for (const key of Reflect.ownKeys(p)) keys.add(key)
  }
  PROTO_KEYS.set(proto, keys)
  return keys
}

const P2_HANDLER: ProxyHandler<ThingA> = {
  get(target, key, receiver) {
    if (typeof key !== "string" || (target as any)[PROTO].has(key)) return Reflect.get(target, key, receiver)
    return target.getProp(key) // tracked even when unset, so a later first write notifies
  },
  set(target, key, value, receiver) {
    if (typeof key !== "string" || (target as any)[PROTO].has(key)) return Reflect.set(target, key, value, receiver)
    target.setProp(key, value)
    return true
  },
  defineProperty(target, key, descriptor) {
    if (typeof key !== "string" || !("value" in descriptor)) return Reflect.defineProperty(target, key, descriptor)
    if (!target[RECORD].has(key)) target.setProp(key, descriptor.value) // field initializer = default if unset
    return true
  },
  has(target, key) {
    return (typeof key === "string" && target[RECORD].has(key)) || Reflect.has(target, key)
  },
  deleteProperty(target, key) {
    if (typeof key === "string") target.deleteProp(key)
    return true
  },
  ownKeys(target) {
    return target.keys()
  },
  getOwnPropertyDescriptor(target, key) {
    if (typeof key === "string" && target[RECORD].has(key)) {
      return { value: target[RECORD].get(key), enumerable: true, configurable: true, writable: true }
    }
    return Reflect.getOwnPropertyDescriptor(target, key)
  }
}

class ThingP2 extends ThingA {
  static registry = new Set<object>()

  constructor(props: Record<string, unknown> = {}) {
    super()
    ;(this as any)[PROTO] = protoKeys(this)
    const self = new Proxy(this, P2_HANDLER)
    ThingP2.registry.add(self) // registration sees the proxy, not the raw target
    Object.assign(self, props) // through the `set` trap
    self.create() // `this` in create() is the proxy
    return self
  }

  create() {}
}

What the experiment found

  • Same behaviour as A: exact read-after-write, the Solid bridge, key order
  • Schema from decorator arguments, not initializers:
    • Symbol.metadata is collected at class definition: one line of polyfill
    • it inherits: FaceCard knows suit, rank and face, and warns on "thirteen" in a declared number

  • Plain fields and create():

What it does to the plan

  1. Compiled output is unchanged: accessor pairs plus the class schema. The verdict on emitting decorators stands.
  2. One mechanism, two spellings:
    • decorators and emitted code call the same ~/util helpers, so the Thing Explorer, keys() and types can't tell them apart
    • consider having the parser emit the helpers' plain-function form, e.g. static { defineProps(this, ...) } and thing(class Card ...): native JS, no transpile, and shorter than accessor pairs
  3. Hand-written classes move to @prop / @derived in Phase 1, dropping their hand-written getProp / setProp pairs
  4. The editor store becomes a decorated class: editor.x = y call sites don't change, since accessors intercept assignment. The deep Proxy shrinks to nested plain data.
  5. Phase 0b is resolved for hand-written classes by @thing.
    • open case: a compiled class extending a @thing class. new.target is the compiled class, so the wrapper won't call create(). The helper must guarantee exactly one call either way. Test it.
  6. Build:
    • the Symbol.metadata polyfill lives in ~/util, loaded before any decorated class, in every bundle and in spell-runtime.js
    • esbuild's decorator helpers cost about 1.2 kB per bundle
    • the decorator must start its line (@prop(...) accessor x does), or vite.decorators.ts won't see the file
  7. Types are said twice: the TS type on the accessor and the runtime type in the arguments. Infer the runtime type from default where possible, and have a test cross-check.
  8. AGENTS.md "Decorators" gains the rules: arguments not initializers; plain fields aren't spell state; @thing on hand-written Thing classes.

type PropOptions = PropInfo & { init?: () => unknown }
type Metadata = { props?: Record<string, PropOptions> }

/** `@prop({ type, default }) accessor name!: T` -- routes to the record through `getProp` / `setProp`. */
export function prop(options: PropOptions = {}) {
  return function <This extends ThingD, V>(
    _target: ClassAccessorDecoratorTarget<This, V>,
    context: ClassAccessorDecoratorContext<This, V>
  ): ClassAccessorDecoratorResult<This, V> {
    const name = String(context.name)
    const metadata = context.metadata as Metadata
    // NOTE:  own props object per class -- `metadata` inherits from the parent's through its prototype
    if (!Object.hasOwn(metadata, "props")) metadata.props = { ...metadata.props }
    metadata.props![name] = options
    return {
      get() {
        if (options.init && !this[RECORD].has(name)) this.setProp(name, options.init())
        return this.getProp(name)
      },
      set(value) {
        this.setProp(name, value)
      },
      init(value) {
        if (value !== undefined) log(`  warning:  @prop ${name} has an initializer -- use { default }`)
        return value
      }
    }
  }
}

/** `@derived get name()` -- memoized:  current on the next line, readers re-run only on a real change. */
export function derived<This extends ThingA, V>(
  getter: (this: This) => V,
  context: ClassGetterDecoratorContext<This, V>
) {
  const name = String(context.name)
  return function (this: This): V {
    return this.derive(name, getter as (this: ThingA) => V) as V
  }
}

/** `@thing` -- run `create()` once, after the MOST-derived class's field initializers. */
export function thing<C extends new (...args: any[]) => ThingD>(Base: C, _context: ClassDecoratorContext<C>) {
  const Wrapped = class extends Base {
    constructor(...args: any[]) {
      super(...args)
      if (new.target === Wrapped) this.create()
    }
  }
  Object.defineProperty(Wrapped, "name", { value: Base.name })
  return Wrapped
}

const SCHEMAS = new WeakMap<Function, Schema>()

/** Base for decorated Things:  its schema comes from `@prop` metadata, chained to the parent class's. */
class ThingD extends ThingA {
  static override get schema(): Schema {
    let schema = SCHEMAS.get(this)
    if (!schema) {
      const own = (this as unknown as Record<symbol, Metadata>)[Symbol.metadata]?.props ?? {}
      const parent = Object.getPrototypeOf(this)
      schema = new Schema(own, parent && parent !== ThingA ? parent.schema : undefined)
      SCHEMAS.set(this, schema)
    }
    return schema
  }
  static override set schema(_value) {}

  create() {}
}

enableExternalSource is global and chains

  • Registering ours wraps every Solid computation on the page, @spell-app/ui's included
  • That's one small object and two Set calls per computation run
  • Measure it on the @spell-app/ui demo page
  • Register it once, in the shared chunk, before anything renders

Check timing

  • Derived-only readers are re-validated in a microtask, which may come after Solid's own microtask flush
  • That costs a second, small flush pass, never a wrong value
  • Anything that needs the DOM settled now calls spellCore.flush(), never Solid's flush() directly

Equality is ===

  • A new array or object with the same contents counts as a change
  • Lists change through their items cell, so this only bites spell code that rebuilds values
  • That's fine: it errs toward updating

Errors in a derived value

must:

  • leave it dirty, which track's try/finally does
  • propagate to the reader
  • A throw that escapes into a Solid effect halts the scheduler (gotcha)
  • The bridge's track can't catch it for Solid, so spellCore.element() wraps thunks

Cycles

A derived value that reads itself needs a "computing" flag that throws a spell-level error. Today the equivalent is a stack overflow.

Collector hygiene

  • Code that must not subscribe, like the Thing Explorer reading values for display during its own compute, uses untrack
  • Solid's untrack reaches our core through the bridge's untrack hook

No async in cells

  • Spell values are synchronous
  • If a spell value ever comes from a fetch, it enters through a Solid async memo at the UI edge, never through a cell
  • That keeps spell immune to holds

Memory

  • Cells and derived values are created lazily and referenced only from their instance and their subscribers
  • Bridge nodes unlink on dispose, so there's nothing to leak
  • Verify with a heap snapshot after a run plus unmountApp()

bit usAn effect's apply function returns its cleanup

  • createRenderEffect(() => x(), v => list.push(v)) returns a number, which Solid then calls as a function
  • That throws and halts the whole page's reactivity (REACTIVITY_HALTED)
  • Always write v => { ... }
  • Our own effect helpers should wrap apply to make this impossible

One uncaught error halts every later update, page-wide

Afterwards "Update ignored: the reactive system was halted". A buggy spell program must never take down the editor around it:

  • thunks from compiled code run inside try/catch in spellCore.element(), reporting to the runner console
  • each app root sits in <Errored>
  • @spell-app/solid-element gives each element its own boundary already
  • resetErrorHalt() exists for recovery

Owned-scope writes throw in dev, even in a createRoot body

  • untrack doesn't exempt them; ownedWrite: true or runWithOwner(null, ...) does
  • Spell cells never write Solid state, so spell is unaffected
  • Our app code still has to follow the rule

Memo lifetimes

  • A non-lazy memo lives until its owner dies; unowned, it recomputes on every relevant flush forever
  • lazy: true tears down when unobserved and recomputes from scratch on the next read
  • In app code, create memos inside components, never at module scope

Holds are narrower than the docs say

  • A write feeding async work is held only when a render effect reads the async value with no <Loading> to catch it
  • Plain createEffect readers don't hold
  • Everything in the same batch is held too; later batches aren't

No mutable store

  • A direct write to a Solid store (s.a = 2) is silently ignored: no throw, no warning
  • Every editor.x = y would quietly stop working
  • Hence the spell-cells store

Stores wrap class instances

createStore({ card }) hands back a proxy, and === against the raw Thing fails. Never put Things in Solid stores; <For each={list.items}> over raw instances keeps identity.

Custom-element props are attributes by default

  • On a tag with a dash, options={list} becomes a stringified attribute
  • Rich data needs prop:options, and attr: / bool: are gone
  • spellCore.element() should route non-primitive values on ui-* tags to prop: automatically, so spell authors never learn this

Custom event names with a dash can't be written as onX in JSX

  • onUiChange listens for uichange
  • Solid lower-cases everything after on, so in hyperscript the key "onui-change" does work, but that's undocumented
  • Pick one spelling for spell JSX (e.g. onUiChange) and have element() map it to ui-change with an explicit addEventListener

Delegated events stop at each render root, and shadow roots work

  • In rc.11 and rc.13 the event walker follows parentNode then .host and retargets
  • The docs only say "needs integration testing", so test <spell-app> clicks explicitly
  • A custom element dispatching a delegated name (click, input...) must use bubbles: true, composed: true

Portal defaults to document.body

Inside a shadow root, pass mount, or content and styles escape. That's the same bug semantic-ui-react has today (CODE-DEBT.md).

  • className is class
