Chose to start the theme agents while P2 runs (separate files: src/styles/themes/, Styles.ts) over strict plan order, to fit the night. Commits still land per phase. (J1)

T2 Review: Fomantic themes load ON TOP of classic UPDATE

Fomantic themes are deltas on Fomantic's default look; ours is classic.css. Chose classic + theme over copying classic's tokens into each sheet (25 copies) or applying themes on our default look (wrong base sizes / palette). (J2)

T3 Review: Fomantic's classic theme named fomantic-classic UPDATE

Our classic.css is already Fomantic's DEFAULT look; chose fomantic-classic.css over renaming ours. (J3)

T4 Review: ui-docs-* read a generated components.json UPDATE

Chose a committed site/_data/components.json (from the vocabularies, yarn site:data) over importing vocabularies in the elements: ComponentDefinitions is ~325 KB of source and <ui-root>'s glob would drag it into docs' spell-ui.js. (J4)

T5 Review: theme overrides reach shadow roots via UI.styles shadow:true UPDATE

Fomantic .overrides are class-grammar CSS; ours render that grammar INSIDE shadow roots. Chose a new register(..., { shadow: true }) that adopts a sheet into every shadow root (like the app stylesheet) over tokens-only themes (would drop most overrides). (J5)
