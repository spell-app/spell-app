- Look at `packages/brand` and make the "Spell" theme based on our brand look. Don't worry about swoops. Also read this page `https://interfaces.dev/cheat-sheet` for things to do in our theme.
- Use the spell logo for favicon (on this and all other doc sites)

The chrome (nav panel, right sidebar, narrow top bar) is written ONCE, and stays on screen while you move between pages; only the page's content is swapped in, by <ui-include>. How the URLs work is Q1.

  • A small router: catches link clicks and <ui-docs-nav>'s cancelable ui-navigate, points the content include at the new page (select="main"), history.pushStates the real URL, sets the title, scrolls to the hash; back / forward via popstate.
  • The old content stays until the new one is ready, then swaps (a View Transition where supported): no blank flash between pages.
  • Gotcha: <ui-docs-example> reads its source from a snapshot taken once, at load (_src/snapshot.ts). Included pages need their own snapshot BEFORE they upgrade: the router takes it from the fetched HTML.
  • Live reload (page server) reloads just the content when only a page changed.

Q2 FOUC: how to hide the page until it's ready? → D2

FOUC ("flash of unstyled content"): raw <ui-*> markup paints before its element's code loads, then jumps into shape. Every page today asks for it: <ui-root display="immediately">. The 44px jump from the site header is fixed in every option (its space reserved in CSS).

A · ui-root when-ready (recommended)
  • <ui-root display="when-ready">: already built
  • CSS hides it before upgrade (native.css:510); then it waits for every element's ready, 5s cap, and shows all at once (120ms fade)
  • No JS: CSS hides only while scripting: enabled
 B · <ui-root hidden>
  • Your idea; needs a :host([hidden]) rule (ui-root.css has none) and code to drop hidden on ui-ready
  • Same result as A, by hand; a failed script leaves the page blank forever
 C · Skeleton
  • display="skeleton" (ui-root's default): grey placeholder shapes until ready
  • Feels like an app loading; noisy for mostly-static docs
 D · .ui-cloak
  • Class on each piece: opacity 0 for up to 2s by a CSS animation
  • Crude: a fixed timer, not "ready"
 D2 A: ui-root when-ready, header space reserved in CSS (Q2)

J1 Favicon: bytes embedded as TS strings, not files beside the server

Chose packages/server/src/site/favicon.ts (SVG + both PNGs as base64, GENERATED by yarn favicon in packages/server, scripts/favicon.ts) over an assets folder read at run time, because the VS Code extension bundles WebServer with esbuild: a file beside the source isn't there once installed. The site header's bundles tree-shake the PNG strings away (only the SVG is used there).

J2 Favicon: hat at the brand's 74%, not enlarged for 16px

Kept the hat at 74% of the icon's width (brand: about three-quarters, CSS 72%) rather than a bigger hat for small sizes. Tried 82%: at 16px on a 1x screen it gains about one pixel and still reads as a hat silhouette either way; at 16px on retina (32 device px) and above, 74% is crisp and the bigger hat crowds the corners. One SVG serves every size, so it's one number for all. Re-run with yarn favicon --hat 0.8 to change it.

J3 Favicon: apple-touch-icon has square corners

The 180px apple-touch-icon.png is the full aubergine square, NOT the rounded icon: iOS masks home-screen icons with its own corner shape, and transparent corners would show black. The 32px PNG and the SVG keep the brand's 22.5% corners.

J4 Favicon: every WebServer answers it, live or not; /favicon.ico after the static files

The /_server/favicon.* routes and /favicon.ico are on every SRV.WebServer (page server, spell serve, the app's API server, VS Code's doc preview, ui's StaticServer), not only live ones; the icon LINKS are injected only where live reload is (pages served by the page server). /favicon.ico answers with the 32px PNG (no redirect: one request), and sits AFTER the static folders, so a folder with its own favicon.ico wins, but BEFORE fallback, so an SPA's catch-all doesn't answer it with index.html. A page whose <head> links its own icon gets no injected links.

J5 Favicon: the app's copy lives in packages/app/static/favicon/

The app (vite) links /static/favicon/{favicon.svg,favicon-32.png,apple-touch-icon.png}, copies yarn favicon writes, over a public/ folder: vite bundles them into dist/assets/ (checked: hashed files, links rewritten), while a public/ folder would also be copied into every library build (dist-element/, dist-runner/). /editor redirects to vite's own port, so the page server never serves the app's page. /vite.svg never existed (the old link was dead).

J6 Spell theme sits on classic, restating what it replaces

Chose to apply spell like a Fomantic theme (classic underneath, as the lead's brief allowed) and list it apart in a new ThemeSheets.OWN, over a standalone theme on our own look. Cost: spell.css restates every classic token the brand replaces (type, size ladder, radii, ink, borders, shadows, palette, message colours, links, focus). Options: (a) on classic, OWN list (chosen); (b) a third apply() mode with no base; (c) make spell one of names.

J7 Spell theme body size 16px, not the brand's 15px

Kept --ui-font-size: 16px (ui's default, and the 16px body spell-doc.css sets) over the brand's 15px --text-base, so docs prose and widgets agree and reading stays comfortable. Options: 16px (chosen), 15px (brand density, widgets a notch smaller than docs prose).

J8 Focus ring: solid violet, 3px, 2px off the box

The brand's focus is a 3px halo of violet at 28% (about 1.5:1 on white), which fails WCAG's 3:1 for non-text contrast. Chose a solid 3px ring, violet-500 light (4.3:1) / lilac violet-300 dark, 2px off the box (ui's offset), via --ui-focus-width / --ui-focus-color. Options: brand halo as is; solid ring (chosen); halo at 55%.

J9 Info is lavender, ivory is the brown hue

ui has no accent slot, so Polished Ivory maps onto the brown hue (the brand's Theme Creator did the same). Info messages take lavender (the brand's aside tint), not ivory, because ivory and the amber warning tint are too close to tell apart. Secondary and grey are the brand's grey-blue at brand-700 (white on brand-600 is only 4.1:1). Options: info ivory (the docs1 TIP box); info lavender (chosen); info sky blue.

J10 Theme menu: Spell first, Default renamed Plain

With Spell the default, the old Default entry (our own unthemed look) would mislead, so its text is now Plain ("Spell UI, unthemed"), under a new first entry Spell ("The Spell brand"). Storage: no theme key means Spell; Plain is stored as default (DOCS_PLAIN_THEME); an unknown stored name falls back to Spell. Options: rename (chosen); keep "Default" pointing at Spell and drop the unthemed look from the menu.

J11 Pill labels, round checkboxes, mono eyebrows

Took the brand's shapes as far as tokens reach: --ui-label-radius pill (brand badges), --ui-checkbox-radius circle (the brand's to-do circle), --ui-progress-radius pill; a sub header and a statistic's label become the brand's mono eyebrow (uppercase, 0.14em tracking); a header's sub header the italic serif lede. Pointing and keyboard labels look fine as pills in the kitchen sink; P5 may revisit.

J12 New public event on <ui-include>: ui-insert, with the fragment before it goes in

Chose a generic event over router-only code because the router must keep each example's authored markup BEFORE it upgrades, and fix links, and only the include sees the fragment. Options: (a) ui-insert event (chosen, small, reusable); (b) router fetches and inserts itself, no ui-include (against the prompt); (c) examples always wrapped in <template> (touches every page).

J13 Page swaps go through a ui-include the router creates on the first swap, not one in the layout

An include with no source empties itself on connect, and giving it the current page's URL at load would fetch and re-render the page just shown. So the first page's main sits bare in .site-content; the first swap wraps it in <ui-include select="main#main" page-styles> with the new source set before it connects.

J14 Router makes every relative URL absolute in anything an include brings in (footer too)

ui-include rewrites a relative URL only when it would point elsewhere from the current page; after a pushState to another folder those left relative break (the footer's ../index.html). The router absolutizes on ui-insert. Examples' shown code keeps the authored URLs (ExampleSource.keep() restores the originals).

J15 "On this page" moved into the layout's right column already in P2 (planned for P4)

Doing it now kept later phases from editing all 66 pages again. The page says its toc title as <main data-toc-header>; the router points a fresh toc at each page. The column stays on the API tab (the page width doesn't jump).

J16 The page waits for the theme's sheet too, not just the layout and the elements

Otherwise the stored / default theme (Spell) restyled the page after first paint: a 0.03 layout shift. Now 0.0002, page shown at ~250ms locally.

J17 <spell-site-header docked>: a new attribute, two copies in the layout (right column, narrow top bar)

Docked: no fixed position, no crumbs (the page shows its title), no scheme button (the page's own control has it), no room kept (--spell-site-header-height 0).
