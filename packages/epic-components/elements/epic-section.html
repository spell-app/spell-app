<epic-section> The <epic-section> element: one section of an epic page (Phases, Questions ... Log), an Overview sub-section, or a report.

<epic-section> is one section of an epic page.

  • Its kind says what it holds: the phases, one kind of item (questions, todos ...), the log, an Overview sub-section's prose, or a run's report.
  • It draws the numbered title, the kind's icon, the fold, the count, and the state filter.

Written for: anyone reading or writing an epic page's markup, or changing this element.
Status: built in epic-section/.
Its vocabulary (attributes, slots, parts, children): EpicSection.en.ts.
The component: EpicSection.tsx.

What it takes depends on its kind:

Child Where How many What it is
prose slot="title" one at most A title with markup.
<epic-updated> slot="changes", only when its kind is phases any number An older doc's Plan changes (until 2026-10-11): a copy of each <epic-updated> of a phase still to do, its phase in of. Not drawn: each phase draws its own now, and the tool removes these on its next write.
prose only when its kind is overview-part or report any number An Overview sub-section's prose, or a report's.
<epic-status> slot="status", only when its kind is overview-part any number An Overview sub-section's status cards from Claude, oldest first (plan-doc status).
<epic-phase> only when its kind is phases any number The phases, in order.
<epic-item> only when its kind is questions or judgements or caveats or todos or issues or tests any number The items, their id's letter the section's (q in Questions).
<epic-event> only when its kind is log any number The log, oldest first.
<epic-cards> only when its kind is epics one at most A saga page's Epics: the cards of the epics serving the saga, drawn from the page server.

JS property: epicTitle 		text An Overview sub-section's title, WITHOUT its number (Structure, drawn as 1.1 Structure), or a report's (Overnight · 2026-10-04): required there (or a slot="title" child, for a title with markup). The page's sections draw their own.

Where its children show: a child goes in a slot by its slot attribute.

Slot What goes in it
(default) Its phases, items, log events or prose.
title A title with markup, in place of title.
changes An older doc's Plan changes copies in the Phases section (until 2026-10-11: <epic-updated slot="changes" of="3" at="...">). Not drawn: each phase draws its own Plan changes box now, and the epic tool removes these on its next write.
status An Overview sub-section's status cards from Claude (<epic-status slot="status">, P13): at the end of its body, above the note box.

Pieces of what it draws, which a page's CSS can style from outside with ::part(name).

Part What it is
base The element's box.
section The <ui-section> drawing the title bar and fold: its own parts through ::part() from inside.
body Around its children: sets --epic-stack for them.
note The Loads from parts/x.html ... line, when its part can't load.
tools At the title's end: the Phases section's Files / Verify toggles; an item section's state filter; an Overview sub-section's review buttons.
filter An item section's state filter: a grey filter chip (show all / only what needs you), then one round chip per state its items are in, filled while that state's items show.
hidden-note Under a filtered list: "3 hidden · show all".
empty An item section with no items: "None yet".
review-buttons The review buttons (P9): the note bubble, a pick's letter, Approve / Revisit / Make Todo, then Do Now. Only while the page is reviewed (served by the page server, its inbox answering).
note-box The note box: the note, then Revisit Later and Make Todo.
said A note marked and closed: You · revisit soon · sent 10:42, the note, Edit.

Custom states: CSS can match them with epic-section:state(name).

State When
:state(open) Unfolded.
:state(loaded) Its source part is in.
:state(error) Its source part couldn't be loaded.
:state(tools) Its title has tools: the Phases toggles, or a state filter (items in it).
Event Cancelable When
ui-open yes About to unfold: its title was clicked. Cancel to stay folded. After the fact for a link.
ui-close yes About to fold: its title was clicked. Cancel to stay open.
ui-load The source part arrived and is in its children (as <ui-section source>'s).
ui-error yes The source part couldn't be loaded; its note says so unless cancelled.
  • Its title: numbered by its place among the page's blocks (3. Questions); an Overview sub-section by its parent's (1.2 Why); a report not at all, so the sections after it keep their numbers. The kind's icon: phases layers, questions a file with a question mark, judgements a gavel, caveats a warning triangle, todos a checklist, issues a bug, tests a flask, log a clock turning back, a saga page's epics a map.
  • The count, on the title: open/all of its items or phases; open means any status but done, decided or canceled. None when it holds nothing. Counted again whenever an item comes, goes or changes.
  • The state filter (item sections): in the colour scheme, red needs Owen, blue Claude is working on it, yellow open, green decided or done, grey no longer relevant. A chip is FILLED while its items show. The grey chip flips between everything and only what needs Owen. A filtered list says 3 hidden · show all under it. Remembered per page.
  • Phases: its title holds the Files and Verify toggles (show or hide those fields in every phase, remembered per page). No box above the phases since 2026-10-11: each phase shows its own changes, in a Plan changes box atop its body (<epic-phase>).
  • An empty item section says "None yet".
  • An Overview sub-section sits on the row band; while the page is reviewed it has review buttons (Revisit, Make Todo, Do Now) and a note box, with Claude's status cards above the note box.
  • Folding: a click on the title folds it; on an epic page every section starts folded, and the page remembers what you opened. With source, its body loads from its part file the first time it opens. Opened from disk, it can't load, and says Loads from parts/x.html when opened (needs the page server).
  • spell dev plan-doc new: the template's sections, each kind once, in order, with its fixed id; and one Overview sub-section, o1.
  • Its children, by kind: spell dev plan-doc add-phase (phases), spell dev plan-doc add and spell dev plan-doc decide (items), spell dev plan-doc log and every command that logs (the log).
  • An older doc's Plan changes copies (slot="changes"): removed by the tool on its next write, which puts each phase's changes in that phase instead.
  • spell dev plan-doc status <name> o3 underway | done: Claude's status cards on an Overview sub-section.
  • spell dev plan-doc split / spell dev plan-doc join: move a body into a part file (source, part-ids) and back.
  • spell dev plan-doc overnight <name> remove: removes an older doc's Overnight report once read.
  • An Overview sub-section's prose: by hand, by the Claude session planning the epic.
