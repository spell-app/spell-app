Solid Migration

How the spell editor app is built on Solid 2 and @spell-app/ui now, and why -- and where React is still left.

Written for: anyone changing the app's UI, the runners, the web components, or spell state Status: built on branch solid-migration, 2026-10-02; compiled spell's own drawing still React (see Next) The record: plan doc Solid Migration (phases, every decision, the log). Solid itself: Spell on Solid 2 (the why, measured) and solid/solid-2.md (the rules for agents) Checked: against the code on branch solid-migration at P9 (3fa79578); numbers from the plan doc's log (see Sources)
  • The editor app, <spell-app>, <spell-editor> and the VS Code runner draw with Solid 2 (2.0.0-rc.13, every package, one copy at the repo root) on @spell-app/ui's <ui-*> elements. React 18, semantic-ui-react (for the app) and easy-state are gone from the app's own UI.
  • Spell state -- every Thing, SP.*, the editor store -- is spell cells , not Solid signals: spell must read its own writes at once, Solid 2 stages writes.
  • Solid follows cells through ONE bridge the host installs; React follows them through view().
  • One Solid per page, across our builds: element, editor and runner bundles import spell-solid.js / spell-ui.js, built once. The app's chunks hold no React (pinned by packages/app/src/build.test.ts).
  • Compiled spell programs STILL draw with React + semantic-ui-react, from spell-runtime.js: moving them is its own thread, "Core + JSX Emit" (Next).
  • Solid code: read solid/solid-2.md first -- Solid 2 is neither React nor Solid 1.
  • A React file must start with /** @jsxImportSource react */; everything else is Solid.
  • Never let Solid or $/ui reach spell-runtime.js, or React the app's chunks.

The parts, from the page down:

The app's UI Solid components in $/app/solid and $/app/pages, drawing <ui-*> elements. Spell cells The state under it all, in $/util: no Solid, no React. The bridges Solid (bridgeSolid(), tracked()) and React (view()) follow cells. Compiled spell Runs on its own spell-runtime.js, drawing with React into a spot the Solid UI hands it.

packages/app/src/solid/ ($/app/solid: 26 .tsx with packages/app/src/solid/modals/ and packages/app/src/solid/monaco/, ~4.8k lines, tests aside) holds the app's UI in Solid 2 on @spell-app/ui; its barrel packages/app/src/solid/index.ts lists it all.

  • Plumbing: loadUI.ts (defines every <ui-*>), cellsBridge.ts, tracked.ts, on.ts (a ref listening for a ui-* event), solid.types.ts (<ui-*> tags in Solid JSX).
  • Shared UI: chrome.tsx (menus, MoreMenu, dropdowns), Actions.tsx, ErrorBoundary.tsx (wraps Solid's <Errored>), ErrorNotice.tsx, Notice.tsx, Markdown.tsx.
  • The shell: SpellPage, SplitPanel, AppRoot / AppContainer (where a program draws), ProjectDropdown.
  • The panes: console (ConsoleLines, ConsoleViewer), match and AST viewers, type and thing explorers, the Monaco editors (LazyMonaco, InputEditor, OutputEditor), FileDropdown.
  • Kept out of the barrel: monaco/ (loads on first use, through LazyMonaco; never import it statically) and modals/ (editor.ts imports it with import(), so the editor never loads Solid up front).
  • Pages: packages/app/src/pages/ -- ProjectChooser, SpellEditor, SpellRunner, ProjectSettings, the router (below).
  • Entry: packages/app/src/index.tsx renders <Routes>, <Notice> and <ErrorNotice> into #app-root; dialogs need no root (each opens its own <ui-modal>).
  • packages/app/src/ui/ is now only what compiled spell draws with: the forms (F), SUIPassThroughs.ts, the Monaco plumbing (packages/app/src/ui/monaco/, React-free) and types.

Conventions

  • Menus: <ui-menu> of <ui-item link>; hosts are display: contents, so page CSS styles ::part(menu) / ::part(item) (packages/app/src/solid/chrome.css).
  • <MoreMenu>: a <ui-dropdown> whose items are data; choosing one CLICKS the <ui-item>, so onClick works in menus and dropdowns alike.
  • ui-* events: ref={on("ui-change", handler)}; native events: onClick.
  • Runner-reachable files import peers DIRECTLY ($/app/solid/ThingExplorer, .../tracked), never the $/app/solid barrel: it pulls in $/app/editor (see Limits).
  • Dialogs: editor.alert() / confirm() / prompt() / promptForNumber() go to UI.modals; choose() to a Solid <Chooser> (packages/app/src/solid/modals/), mounted on <body> and removed once hidden.

Two JSX flavours in one package, told apart by ONE first-line marker.

  • packages/app/tsconfig.json: jsx: preserve, jsxImportSource: @solidjs/web. Solid is the default.
  • A React .tsx starts with /** @jsxImportSource react */. TypeScript reads it; reactFiles() in packages/app/vite.shared.ts reads the same marker (in REACT_DIRS: app/src, core/src) to hand the file to @vitejs/plugin-react instead of @solidjs/vite-plugin.
  • Marked today: core's App.tsx, List.tsx; the forms' Form.tsx, FormStore.tsx, components.tsx, wrappers.tsx; two tests (solid.test.tsx, reactView.browser.test.tsx).
  • A missing marker: tsc usually fails; else it fails at runtime.
  • NOTE: the file list is read when the config loads -- restart vite after adding a marker.
  • appConfig() (same file) is every vite*.config.ts and vitest.config.ts's base: standard decorators FIRST (the Solid compiler must see decorator-free code), both JSX plugins, @spell-app/solid-element from source, Lightning CSS with ui's CSS_TARGETS (errorRecovery on, for Semantic UI's invalid selectors), optional icon packs.
  • NOT_SOLID_SOURCE: the Solid plugin leaves node_modules alone except @solidjs/router, which ships JSX source.

Under Observable, Thing, List and the editor store, in packages/util/src/spell/: cells.ts, packages/util/src/spell/Cell.ts, Derived.ts, Reaction.ts, Schema.ts, extend.ts, spellDecorators.ts.

  • The truth is each object's record, a Map (keys stay in first-set order; a plain object would hoist "2", "10"). Cells only say WHO read WHAT.
  • Push-pull with an equality cutoff: a derived value (Derived, derive(), @derived) re-validates by pulling its sources and only notifies if its value really changed.
  • Readers are Reactions: one per Solid computation, per React view, per observe(). A reader never re-runs for a change its own run made.
  • One cells context per page, on globalThis (Symbol.for("@spell-app/cells")): the app's $/util and every spell-runtime.js copy (one per <spell-app>) share the "who is reading" slot, the pending checks and the host's flush. Sources are duck-typed across copies; CONTEXT_VERSION guards the shape.
  • Values are not made reactive: no proxies, === holds everywhere. Change a list or object a prop holds IN PLACE and nobody hears: set the prop to a new one (spell's List copies on write).
  • Types live in a per-class schema (schemaOf(Class)). Hand-written classes declare them with decorators, compiled spell with static { this.declareProp(...) }: the same runtime shape. Thing / List check a declared type on the program's console when a value CHANGES; undeclared props are observed per class and widened with a dev warning.
  • Decorators (hand-written classes only; compiled spell runs from a blob: URL): @prop({ type, default }) accessor, @derived, @thing (runs create() exactly once, after the most-derived class's field initializers; runsCreate() in Thing / List). Used by EditorStore (packages/app/src/editor.ts), SpellConsole (packages/core/src/console.ts), FormStore.
  • The editor store is class EditorStore extends Observable with @prop accessors (projectRoot, project, file, projectPage, runtimeLoaded, selection, showingMatchRuleNames, notice, error): editor.x = y call sites didn't change. Solid 2 has no mutable store.
  • spellCore.flush() / flushCells(): pending derived checks, then the host's Solid flush(). Tests and imperative code call it, never Solid's directly.

util and core never import Solid, so each renderer is wired to cells from outside.

Solid: bridgeSolid(), installed by the host

  • bridgeSolid({ enableExternalSource, flush }) (packages/util/src/spell/bridges.ts) makes EVERY Solid computation (JSX expression, memo, effect compute) a cells reader. So a plain {editor.notice} in JSX is reactive.
  • Called by packages/app/src/solid/cellsBridge.ts, imported for its side effect, before anything renders, by each host: index.tsx, packages/app/src/runner/main.tsx, SpellAppElement.tsx, SpellEditorElement.tsx, and tracked.ts.
  • ONCE per Solid, however many hosts call it (remembered in the cells context): Solid pipes every enableExternalSource() into the last, so a second would wrap every computation twice.
  • So spell-runtime.js holds no Solid (element.build.test.ts).

tracked(): one shared read

  • tracked(read) (packages/app/src/solid/tracked.ts): a Solid memo over a read of spell state, read() run once per change however many places read the accessor. ~57 call sites.
  • Boxed, equals: false: a function or Promise is a VALUE; every re-read notifies.
  • Re-reads on Solid's schedule: never mid-write, ten writes = one read. So program code (a Thing's computed property) is safe in it.
  • Its value is Solid's, so STAGED: right after a write the accessor is old until the microtask or flush(); a plain editor.x read never is.
  • Owned by the calling owner; with none, its own root, ended by dispose().
packages/app/src/solid/tracked.ts · the memo 
export function tracked<T>(read: () => T): TrackedAccessor<T> {
  if (getOwner()) return Object.assign(memoOf(read), { dispose: () => {} })
  return createRoot((dispose) => Object.assign(memoOf(read), { dispose }))
}

function memoOf<T>(read: () => T): Accessor<T> {
  const box = createMemo(() => ({ value: read() }), { equals: false })
  return () => box().value
}

React: view()

  • view(Component) (packages/util/src/spell/view.ts): a class component becomes a subclass rendering inside a Reaction (forceUpdate() on a change); a function component a wrapper holding one. Same API as easy-state's view().
  • Used by Thing.Component, List and the forms (F): what compiled spell draws with.
  • The only file in util importing react; util is sideEffects: false, so bundles that never call it drop it.
  • Plain code: observe(fn) re-runs fn synchronously (e.g. SpellModels).

Two Solids on one page fail SILENTLY: the fork's register() swaps existing.Component across copies, and the second copy's components render in the first's roots. So our separate builds share one.

  • Why one entry, not two: with two, rolldown split Solid into a shared ui/customElement.js. As a dynamic import of spell-solid.js, everything ui needs from Solid is exported by it (preserveEntrySignatures: "allow-extension").
  • Why not one build with three entries: cssCodeSplit: false would put Monaco's CSS in spell-app.css (CODE-DEBT).
  • base: "./": Vite's preloading of ui's chunks finds them beside the bundle, not at the page's / (which 404s).
  • sharedSolid() (packages/app/vite.shared.ts): an enforce: "pre" resolveId making solid-js, @solidjs/web, @spell-app/solid-element and $/ui externals, written ./spell-solid.js / ./spell-ui.js by output.paths. Any other Solid / ui specifier (solid-js/store, $/ui/runtime) is a build ERROR.
  • Pinned by packages/app/src/runner/element.build.test.ts (from each chunk's sourcemap sources): Solid only in spell-solid.js, ui only in spell-ui.js + ui/, spellCore only in spell-runtime.js, which never loads Solid or ui; Monaco only in <spell-editor>'s lazy chunks; every bundle parses.
  • <spell-app> (packages/app/src/runner/SpellAppElement.tsx) and <spell-editor> (packages/app/src/spellEditor/SpellEditorElement.tsx) are customElement()s from @spell-app/solid-element, with a BaseElement holding their methods (run(), restart(), compile(), save(), assets).
  • Every attribute is a property too. Code an editor pushed is the property-only prop pushed, dropped when project / src / scopes / name / editor change.
  • <spell-editor> keeps its state in ownedWrite signals its component draws.
  • Leaving the page disposes a microtask later, so a same-tick move keeps the app.
  • Each <spell-app> runs on its OWN copy of spell-runtime.js (loadRuntime()): its own spellCore, console, listeners and mount point.
  • The VS Code runner (packages/app/src/runner/main.tsx, VSCodeRunner.tsx) is the same Solid runner UI in a webview; packages/vscode/src/RunnerPanel.ts writes its HTML and CSP (everything from the runner folder, in localResourceRoots).
  • The app speaks Fomantic's icon names ("ellipsis horizontal", "app store ios"). Each surface says so with <ui-root icons="fomantic"> around itself: the editor's packages/app/index.html, <spell-app>'s shadow root, the VS Code webview (display="immediately" on the last two).
  • NOT page-wide from code a host page loads: 27 names mean another icon in Font Awesome (x, warning ...), and a host's own <ui-*> must keep theirs. Only the editor app adds the pack page-wide, for dialogs on <body> (addAppIconsPageWide()).
  • packages/app/src/solid/loadUI.ts is the ONE place the app loads $/ui: the whole barrel, by dynamic import() (~2 MB unminified, off first paint), then UI.load(). Nothing under node. Never reachable from spell-runtime.js.
  • Builds emit ui's icon packs beside the chunk holding BuiltInPacks (appConfig({ iconPacks: true }), iconPacksBesideBuiltIns(); a build error if no chunk holds it): assets/icon-packs for the app, icon-packs beside spell-ui.js for element / runner. All three packs: 2,170 files, 2.2 MB.
  • @solidjs/router 2.0.0-next.35, pinned exactly (packages/app/src/pages/routes.tsx). The same URLs as @reach/router's: /edit/..., /run/..., anything else the project chooser.
  • Each page's URLs are ONE route with a path array, so moving between files keeps the page mounted; route components follow params with followRoute().
  • explicitLinks: true: only <a link> clicks; a running program's own links stay its own.
  • editor.ts navigates through packages/app/src/pages/navigation.ts navigate() (no Solid), which the root layout hands its useNavigate() to.
  • Hotkeys: ONE keydown listener on document while the editor page is up (packages/app/src/pages/editorHotkeys.ts). Mod+Shift+R reloads the file (React's shift-command+r never matched).
  • packages/parser/src/ast/AST.ts and renderAST.ts build P.Markup: plain data ({ tag, attrs, children }, text, arrays). The app's ASTViewer draws it with P.render.toDOM() in render, inside its <ErrorBoundary>.
  • So the parser has no React and no Solid: AST.ts loads wherever the parser does, and the CLI / language server / package tests compile with tools that can't do Solid JSX.
  • The tree is static (a new compile makes a new AST): reactivity would buy nothing.

The decisions behind it, condensed; each links to its full entry in the plan doc.

  • Spell state in cells, not Solid signals (D4): Solid 2 stages writes, and spell is imperative (set then print must be exact). Measured: solid/experiments/read-after-write.mjs, entanglement.mjs.
  • Full cells as their own phase, after the shell (D13): first a bridge over easy-state (P4), then cells replace it (P11), so the Solid UI didn't wait on the riskiest change.
  • The Solid bridge is the host's; one cells context per page (D25): util / core stay Solid-free, every runtime copy reaches the one bridge.
  • React bridge = view() on cells (D26): easy-state's API, so Thing.Component, List and the forms only changed their import.
  • Compiled props declare type / default in the class schema (D27): declareProp() lands where @prop does; the old 3-argument setProp() still works for programs compiled before.
  • tracked() kept, as a memo; deferred gone (D28, superseding D20's trackedProgram()): with the bridge every read is on Solid's schedule.
  • Editor store = EditorStore (D29): an Observable with @prop accessors; call sites unchanged.
  • @thing in spellDecorators.ts; runsCreate() guard (D7, D8): spell-only, so not beside @proto (which ui re-exports); create() exactly once for compiled, decorated and mixed chains, compiled output unchanged.
  • Compiled spell stays React (D9, D30): core rendering, JSX emit and the projects' SUI.* move are their own thread; the app's own UI is React-free, the CLI's Ink UI kept.
  • Design from 2026-09-30 stands (D3): ui from source, clean break in spell JSX, incremental phases.
  • Bottom-up (D14): panes (P6), web components (P7), then the shell (P8), through a throw-away Solid-in-React island adapter, gone at P8.
  • Solid rc.13 first (D1): the app never moved Solid twice; ui's suites caught RC changes first.
  • Merge at the end (D2): main stays React-only until the migration lands.
  • Solid by default, React files marked (D11): app's tsc follows $/ui into ui's 138 Solid .tsx with app's JSX setting, so React-by-default would mean touching all of ui. One marker, no path list.
  • One Solid per page across builds (D21): a third build makes spell-solid.js / spell-ui.js.
  • $/ui workspace alias (D5): one workspace, one hoisted node_modules; no sibling ../ui alias.
  • <Errored>, not createErrorBoundary (D10): rc.13 moved it to solid-js/internal; never import from there.
  • Lightning CSS errorRecovery (D12): Semantic UI's CSS has invalid selectors (:before.ui); browsers drop them too.
  • $/ui loaded once, Fomantic icon names (D15): loadUI.ts; page-wide only in the editor app.
  • Shared conventions (D16): menus, MoreMenu, on(), ErrorBoundary.
  • Dialogs build their own <ui-modal> (D18): editor.modals, ModalRoot and friends gone.
  • Solid Monaco editors reuse the React-free plumbing (D19): Monaco stays a lazy chunk (4.46 MB, reachable only through import()).
  • Elements on customElement() + a base class (D22).
  • @solidjs/router@next, navigation handed over (D23).
  • AST views draw P.Markup, not Solid JSX (D24, superseding D17's React host): the parser must load in node tools; the pane's DOM is byte-identical to the React one (Todos, Solitaire).

Accepted for now; each is an open caveat or issue in the plan doc.

  • A value changed IN PLACE notifies nobody (C17). easy-state made nested objects reactive (editor.file.someArray.push() redrew); cells follow props only. Audited: spell's List copies on write, Loadable's loadState uses dotted setState, compiled examples hold only primitives and Lists. A plain array a PROGRAM keeps in a prop and changes with spellCore.append() won't redraw. The planned Proxy for class-less data isn't built.
  • Effect compute errors don't reach <Errored> (C10): in rc.13 they go to the console, fallback never shown. Read a value that may throw in RENDER, or give the effect an { effect, error } bundle.
  • Solid dev warnings (C18): the editor pages log STRICT_READ_UNTRACKED, WIDE_SCOPE_DEPS (a router memo with 31 sources) and HOT_SCOPE_TIME (now naming tracked()'s memo), as before P11. Calculator's validateDOMNesting and Solitaire-import's createRoot() warnings are React's, from the programs.
  • Two renderers for spell output (C5): React (programs) inside Solid UI on one page; CODE-DEBT.
  • The $/app/solid barrel isn't runner-safe (C9, C15): it pulls in Actions, hence $/app/editor. RunnerConsole imports ConsoleLines.tsx and tracked directly; the explorers import peers directly and don't load ./loadUI (it throws under node, where their tests render), so whoever mounts them in a runner must. ConsoleLines' lines is a value: the caller tracks the top level.
  • Two vite copies (C8): packages/ui/node_modules/vite is its own, so ui's plugin types don't match app's (an as unknown cast in packages/app/vite.shared.ts). Harmless at runtime so far.
  • Solid RC churn (C2): re-run solid/experiments/* on every bump (SOLID_NODE_MODULES=<dir> picks the version), diff, update solid-2.md.
  • Visual tests local only (C6): yarn test:visual --os local, 582 passed on rc.13; the Linux (Docker) run wasn't done.
  • ui bugs (C1, I1): <ui-item icon> in a <ui-menu> draws a 0 x 0 svg (HACK: <Action> / <MoreMenu stub> slot a <ui-icon>, packages/app/src/solid/Actions.tsx); an inverted coloured menu draws dark item text; a host aria-label never reaches <ui-dropdown>'s combobox. In SUSPECTED-BUGS.md; known ones in spell-docs/spell-ui-findings.md.
  • UI.modals.prompt() takes no input type (I2): HACK fitInput() in packages/app/src/solid/modals/dialogs.ts sets type=number, min / max / step / placeholder on the appended dialog's input and vetoes ui-approve while it's invalid. Fix: an input option on ui's ModalOptions.
  • Dialogs changed from the React modals (C12):
    • text only: message / header / ok / cancel are strings
    • a dimmer click no longer cancels (closedby=closerequest); Escape does
    • confirm() focuses Cancel first
    • prompt() resolves undefined when empty
    • promptForNumber() resolves the string, as its signature says
    • choose() is a list of <ui-radio> / <ui-checkbox>, not a searchable dropdown; multiple + OK with nothing chosen resolves []
  • FileDropdown renders every item (was C14): no lazyLoad; a <ui-dropdown> in a <ui-item>, value held at editor.file.path, choosing CLICKS the item.
  • MatchView has no collapsing (C11): neither had React's; only the rule-names toggle.
