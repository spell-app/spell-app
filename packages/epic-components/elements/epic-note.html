<epic-note> The <epic-note> element: a small UPDATE or DONE note in prose that stays.

A small note in prose that stays: an orange UPDATE card (changed since you looked) or a green DONE card (decided or done). It draws the heading, the label then the note's title; the note is its children.

For anyone reading or writing an epic page's markup, or changing this element.
Its vocabulary (every name it uses): EpicNote.en.ts.
Its component: EpicNote.tsx, with its style sheet (.css) and tests beside it.

A note with no body is its heading alone: <epic-note state="done" title="option A, 2026-10-06"></epic-note>.

Its parents:

  • Anywhere prose goes: it's a prose element:
    • <epic-item>: among an item's own text, before its cards
    • <epic-answer>, <epic-more>, <epic-reply>: the cards under an item
    • <epic-option>: an option card's pros and cons
    • <epic-field>: a phase's field, or a labelled block
    • <epic-updated>: a change to a phase's plan
    • <epic-section>: an Overview sub-section's prose, or a report's
    • <epic-version>: an earlier version, kept as it was
    • another prose element (a note inside an aside), or plain HTML around it (a <li>, a <div>)

Its children:

  • prose: the note
  • or nothing: the heading alone

Not <epic-update>: that one belongs to a phase, and goes when the phase is done. This one stays.

A slot is where the element's own children show.

Slot Holds
(default) The note.

A part is a piece of the drawing a page's CSS can reach.

Part Is
base The card: orange (update) or green (done).
header Its heading: the fold chevron, the label, then the title. A click folds it.
toggle The fold chevron, a <button>, first in the heading; only with a body.
label UPDATE or DONE.
body The note. Not drawn when empty; hidden (until-found) while folded.

A state is set by the element on itself; none is ever written in the doc.

State When
open Unfolded. It starts so.
  • One meaning per colour (decision Q20): update orange, changed since you looked; done green, decided or done.
  • A card: a hairline in its colour, a faint fill of it, and the heading's text in that colour's readable ink (light and dark).
  • The label is bold and letter-spaced; the title follows it after · .
  • It folds by its heading, chevron first, when it has a body. It starts open; folded, the note is hidden="until-found".
  • At most 44em wide (--epic-note-width). No fill lifecycle: it's not a button.
  • Claude writes it inside the HTML it passes to spell dev plan-doc (add ... --details, decide --details, details --file, updated): no command makes one by itself.
  • The epic tool turns the OLD hand-shaped markup into this element, so a doc never holds the old shape.
    • It does this in any HTML a command takes: add --details, decide --details, details --file, updated.
    • The code that does it: IncomingHtml and ProseRewrite.
    • Prose edited by hand in a part file isn't passed through it.
    • The old shape: a hand-written ui-message.plan-update.
  • The converter did the same to every converted doc (ProseUpgrader).
  • The tool never removes one.
