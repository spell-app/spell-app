<Section title="State">
  Fomantic's `state` behaviour (`$('.button').state({ text: { inactive, active } })`) is two attributes on the
  button, not an element of its own:  a `toggle` button already switches `active`, so only the texts were missing.
  `inactive-text` replaces the content while the button is not `active`, `active-text` while it is.  With only one of
  them, the button's own content shows in the other state.

  <Example title="State texts" description="The label says the state:  click to follow, click again to unfollow." class="ui-cluster">
    <ui-button toggle inactive-text="Follow" active-text="Following"></ui-button>
    <ui-button toggle primary active inactive-text="Subscribe" active-text="Subscribed"></ui-button>
  </Example>
  <Example title="One text" description="With only `active-text`, the content is the inactive label." class="ui-cluster">
    <ui-button toggle icon="bell" active-text="Watching">Watch</ui-button>
  </Example>

  Because the label SAYS the state, a `toggle` button with a state text leaves `aria-pressed` off:  a toggle button
  whose name changes would announce the state twice (WAI-ARIA APG).  Listen for `ui-toggle` as usual.

```js
document.querySelector("ui-button[active-text]").addEventListener("ui-toggle", (event) => {
  event.detail.active ? follow() : unfollow()
})
```

  Not ported:  Fomantic's hover texts (`activate` / `deactivate`, which change the name under the pointer), `flash`,
  `sync` across buttons, and the API-request and `automatic` states.
</Section>

<Section title="Behaviour">
  Attributes are the vocabulary of the element:  most of them turn into Fomantic's class words in the shadow root
  (`<ui-button size="small" primary basic>` renders `ui small basic primary button`).  A boolean attribute is true when
  present, empty, `"true"` or `"yes"`, and false for `"false"` or `"no"`.  `medium` is a real size that means "default".

  `ui-toggle` is the only custom event:  a plain click is the native `click`.

```js
const toggle = document.querySelector("ui-button[toggle]")
toggle.addEventListener("ui-toggle", (event) => console.log(event.detail.active))
```

  Invoker commands work from a `<ui-button>` like from a native `<button>`:  `commandfor` is the id of the target
  (looked up in the button's own tree) and `command` the action, with no script.  `show-modal` / `close` /
  `request-close` act on a `<dialog>`, `show-popover` / `hide-popover` / `toggle-popover` on a popover, and a
  custom `--name` arrives as a `command` event on the target (`<ui-modal>` answers `--show`, `--close` and
  `--toggle`).  The shadow `<button>` can't see a light-DOM id, so the element hands it the target element
  (`commandForElement`);  in browsers without invokers (`UI.browser.supports.invokers`) a click runs the built-in
  commands itself.

  <Example title="Invoker commands" description="A `<ui-button>` opens and closes a popover and a modal with `commandfor` and `command`.">
    <ui-button commandfor="button-invoker-popover" command="toggle-popover">Toggle popover</ui-button>
    <div id="button-invoker-popover" popover style="padding: 1em">A native popover.</div>
    <ui-button primary commandfor="button-invoker-modal" command="--show">Open modal</ui-button>
    <ui-modal id="button-invoker-modal" header="Invoked" content="Opened by a ui-button." closable></ui-modal>
  </Example>

<Section title="Theming">
  Theme with the public `--ui-button-*` tokens:  set one on the element, on any ancestor (a group, a toolbar,
  `:root`), or on the inner box through `::part(button)`.  They inherit into the shadow root, where the sheet reads
  each through a private alias, so nothing inside blocks them.  Set on a `<ui-buttons>`, they reach every button in
  the group.

```css
/* every button on the page */
:root {
  --ui-button-radius: 999px;
}
/* one region */
.toolbar {
  --ui-button-padding-inline: 1.5em;
}
/* one kind, on its box */
ui-button.cta::part(button) {
  --ui-button-background: var(--ui-yellow);
}
```

  Variations build on the base tokens:  `compact` scales your `--ui-button-padding-block`, while `circular`
  replaces the radius whatever you set.  To restyle a variation itself, target it with plain properties:
  `ui-button[circular]::part(button) { border-radius: 0.5em }`.  Never set the `--_ui-*` / `--_button-*` names:  they're the
  sheet's private plumbing.

<Section title="Accessibility">
  - The shadow root holds a real `<button>` (or an `<a>` when `href` is set), so focus, Enter and Space, form
    submission and the accessible name come from the browser.  `delegatesFocus` means the host is never a tab
    stop of its own and the focus ring is drawn on the inner control.
  - An icon-only button needs a name:  put `aria-label` on the host.
  - `toggle` buttons expose `aria-pressed` and update it with `active`.
  - `loading` sets `aria-busy`;  `disabled` disables the inner control.
  - `type="submit"` and `type="reset"` act on the enclosing form, and `name` / `value` are submitted with it.
  - `<ui-buttons>` is a `role="group"`;  label it with `aria-label` when the group needs a name.
  - Without JavaScript the native fallback keeps a plain `<button>` styled by the same class words, so the button
    still renders, focuses and submits its form.
</Section>

<Section title="Framework usage">
  Define the elements first, then use the tag like any other.  Events are `ui-*`, so use your framework's custom-event syntax.

```jsx
// React 19
<ui-button primary toggle onui-toggle={(event) => setOn(event.detail.active)}>Vote</ui-button>
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-button primary toggle @ui-toggle="(event) => (on = event.detail.active)">Vote</ui-button>
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref
<ui-button
  primary
  toggle
  ref={(el) => el.addEventListener("ui-toggle", (event) => setOn(event.detail.active))}
>
  Vote
</ui-button>
```
