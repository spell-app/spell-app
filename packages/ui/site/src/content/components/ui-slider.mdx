<Section title="Behaviour">
  A slider is a form control.  With a `name` it submits `value` with the form;  a `range` submits two entries under
  that name (start, then end).  The attributes are the starting (and reset) values;  the `value` / `end` properties
  are the live ones.  `min` / `max` / `step` default to Fomantic's 0, 20 and 1, and `step="0"` allows any value.
  `smooth` lets the thumb glide under the pointer while the value still snaps.

  `ui-input` fires on every move and `ui-change` when a key press or a drag ends, both with `{ value, end }`.
  Setting `value` inside a `ui-input` handler wins, so you can clamp or reject a move.  Custom step labels are the
  `stepLabels` property:

```js
const size = document.querySelector("#size") // <ui-slider id="size" labeled max="4" aria-label="Size">
size.stepLabels = ["XS", "S", "M", "L", "XL"]
size.addEventListener("ui-change", (event) => console.log(event.detail.value))
```

<Section title="Theming">
  Theme with the public `--ui-slider-*` tokens:  set one on the element, on any ancestor (`:root` included), or on
  the slider's box through `::part(slider)`.  They inherit into the shadow root, where the sheet reads each through a
  private alias, so nothing inside blocks them.  `inverted` swaps in its own `--ui-slider-inverted-*` colours.  Style
  the pieces with `::part()`:  `track`, `track-fill`, `thumb`, `labels` and `label`.

```css
ui-slider {
  --ui-slider-track-height: 0.25em;
}
ui-slider::part(thumb) {
  box-shadow: none;
}
```

<Section title="Accessibility">
  Each thumb is an ARIA `slider` (the APG pattern) with `aria-valuemin`, `aria-valuemax` and `aria-valuenow`, and
  `aria-orientation` when `vertical`.

  - A single slider's thumb is named by the host's `aria-label` or a `<label for>`.  A `range` is a group named that
    way, with two thumbs, "Minimum" and "Maximum" (translatable);  each stops at the other.
  - Step labels are hidden from assistive tech:  the thumb's value is what's announced.
  - `readonly` stays focusable and announced but can't change;  `disabled` leaves the tab order.
  - If the element can't render, its native fallback is the browser's range input (two for a `range`), so the value
    can still be set and submitted;  Fomantic's track and thumbs, labels, `vertical` / `reversed` and `step-labels`
    are dropped.

  | Key                           | Action                                                        |
  | ----------------------------- | ------------------------------------------------------------- |
  | Arrow keys                    | Move the thumb one step the way the arrow points               |
  | Page Up / Page Down           | Move two steps                                                 |
  | Home / End                    | Move to the thumb's lowest / highest position                  |
  | Tab                           | Move to the next thumb (a `range` has two), then out           |

  On a `vertical` slider the minimum is at the top, so Arrow Down increases;  on a `reversed` one Arrow Left does.
</Section>

<Section title="Framework usage">
  `value` / `end` are plain attributes and `stepLabels` a property;  listen for `ui-input` or `ui-change`.

```jsx
// React 19
<ui-slider name="volume" max={10} value={volume} onui-input={(e) => setVolume(e.detail.value)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-slider name="volume" max="10" :value="volume" :stepLabels="labels" @ui-input="(e) => (volume = e.detail.value)" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref;  `prop:` for the property
<ui-slider name="volume" max="10" value={volume()} prop:stepLabels={labels} ref={(el) => el.addEventListener("ui-input", (e) => setVolume(e.detail.value))} />
```

</Section>
