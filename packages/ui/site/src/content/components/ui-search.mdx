<Section title="Behaviour">
  Results come from one of two places:

  - the `source` property, searched in the page:  `search-fields` picks the fields, `full-text-search` how loosely
    they match (`exact`, `fuzzy`, `prefix`, `some`, `all`), `ignore-diacritics` lets `a` match `á`, `max-results`
    caps the list;
  - or a server:  `url` is a template with `{query}` (`/api/search?q={query}`).  Typing waits `search-delay` ms, a
    newer query cancels an older one, and answers are cached per query.

  A result is Fomantic's `{ title, description, image, price, category, url }`.  Choosing one fires the cancelable
  `ui-select` first;  then its title goes into the input (`ui-change`), the results close, and a result with a `url`
  is followed.  `ui-search` fires as a query starts (once it is `min-characters` long) and `ui-results` when a server
  answers.  The search is a form control too:  with a `name` it submits the input's text.

```js
const search = document.querySelector("ui-search")
search.source = [
  { title: "France", description: "EU", url: "/countries/fr" },
  { title: "Ghana", description: "AU", url: "/countries/gh" }
]
search.addEventListener("ui-select", (event) => {
  event.preventDefault() // stay on the page
  console.log(event.detail.result.title)
})
```

<Section title="Theming">
  Theme with the public `--ui-search-*` tokens:  set one on the element, on any ancestor (`:root` included), or on
  one piece through `::part(input)` / `::part(results)`.  They inherit into the shadow root, where the sheet reads
  each through a private alias, so nothing inside blocks them.  `--ui-search-results-max-height` replaces the
  viewport-based height of `scrolling` results at every width.  `prompt` is the text field itself.

```css
ui-search {
  --ui-search-prompt-radius: var(--ui-radius);
}
ui-search::part(results) {
  --ui-search-results-width: 24em;
}
```

<Section title="Accessibility">
  The text field is an ARIA 1.2 combobox with a list of results (the WAI-ARIA authoring practices pattern).

  - `role="combobox"` with `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` and `aria-activedescendant`
    pointing at the highlighted result;  focus stays in the text field.
  - The results are a `listbox` of `option`s;  a `category` search groups them in named `group`s.
  - A hidden status message announces how many results there are, or the no-results / error message.
  - Name the search with `aria-label` on the host or a `<label for>`;  the placeholder alone is not a name.
  - If the element can't render, its native fallback is a text input with the browser's suggestions (a `<datalist>`)
    from `source`:  titles only, no remote results, no events.

  | Key                     | Action                                                              |
  | ----------------------- | ------------------------------------------------------------------- |
  | Arrow Down / Arrow Up   | Move the highlight through the results (stops at the ends)          |
  | Enter                   | Choose the highlighted result;  with none highlighted, submit the form |
  | Escape                  | Close the results;  when they are already closed, clear the text     |
  | Tab                     | Leave the search                                                    |
</Section>

<Section title="Framework usage">
  Set `source` as a property, not an attribute, and listen for `ui-select` or `ui-change`.

```jsx
// React 19
<ui-search name="country" source={countries} onui-select={(e) => setCountry(e.detail.result)} />
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-search name="country" :source="countries" @ui-select="(e) => (country = e.detail.result)" />
```

```jsx
// Solid 2:  no `on:` namespace -- listen through a ref;  `prop:` for the property
<ui-search name="country" prop:source={countries} ref={(el) => el.addEventListener("ui-select", (e) => setCountry(e.detail.result))} />
```

</Section>
