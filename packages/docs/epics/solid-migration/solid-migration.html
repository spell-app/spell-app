D16 Shared Solid UI conventions (P6a): Action, MoreMenu, on(), ErrorBoundary
  • Menus: <ui-menu> of <ui-item link>; sub-menus <ui-menu position>; hosts are display: contents, so page CSS styles ::part(menu) / ::part(item) (chrome.css).
  • <MoreMenu> is a <ui-dropdown> whose items are DATA: choosing one clicks the <ui-item> (so onClick works in menus and dropdowns alike) and resets the value; it provides the InDropdown context, so <Action> renders its icon as the item's icon attribute there and keeps titles text.
  • ui-* events: ref={on("ui-change", handler)} ($/app/solid on()); native events: onClick.
  • editor reads: tracked(() => editor.x) in the component body, the accessor read in JSX.
  • Actions.PROJECT_DROPDOWN_ACTIONS / FILE_DROPDOWN_ACTIONS are components now, not element arrays.
  • <ErrorBoundary fallback onError> wraps <Errored>; replaces subclassing React's ErrorHandler.
D17 P6c: ASTViewer mounts renderAST's React tree through a local React-in-Solid adapter

src/solid/ASTViewer.tsx keeps ast.component (React, from $/parser's renderAST.tsx, P8's) and mounts it with a private <ReactHost>: a React root on a display: contents div, re-rendered per new element, unmounted on a microtask at cleanup. Why not Solid: the drawing is spread through ~60 renderChildren() methods in AST.tsx (2.7k lines), not one file. No flushSync (inside a solidIsland() it runs in React's commit, where it can't flush): a React error boundary (<ReactCatcher>) calls onRendered after each commit, which re-applies scroll/highlight. ast.component throwing is read in render so the Solid <ErrorBoundary> catches it (an effect's error would halt Solid). C12 P6f dialogs: what changed from the React modals
  • Text only: message / header / ok / cancel are strings (no ReactNode, no SUI.ButtonProps); extra props no longer reach a modal.
