<Section title="Behaviour">
  A popup finds its TARGET in this order:  the `target` property (any element), else `for` (the id of an element in
  the same document or shadow root), else the element just before it.  It then sits in the top layer, positioned
  by CSS anchor positioning:  no script measures anything, and when there is no room it flips to the other side
  (top to bottom, left to right) by itself.

  `on` picks what opens it:

  - `hover` (the default):  pointer hover and keyboard focus, after `show-delay` (50ms);  it hides `hide-delay`
    (70ms) after the pointer leaves.  The popup stays open while the pointer is over it, so its text can be read
    and selected (WCAG 1.4.13).  `hoverable="false"` is Fomantic's default instead:  it hides as the pointer
    leaves the target, even onto the popup.
  - `focus`:  keyboard or pointer focus on the target only.
  - `click`:  a click toggles it;  it behaves as a small non-modal dialog, for content you interact with.
  - `manual`:  only your code, through `open`.

  A native button can drive it with no script, through an invoker command:  `--show`, `--close` or `--toggle`.  The
  popup always opens at ITS target, whichever button sent the command (a `manual` popup suits this).

  <Example title="Invoker commands" description="`commandfor` names the popup, `command` is `--show`, `--close` or `--toggle`.  It appears at the avatar, not at the buttons.">
    <div class="ui small basic buttons">
      <button type="button" class="ui button" commandfor="popup-invoker-tip" command="--toggle">Toggle</button>
      <button type="button" class="ui button" commandfor="popup-invoker-tip" command="--close">Close</button>
    </div>
    <span id="popup-invoker-target" class="ui label">Anna</span>
    <ui-popup id="popup-invoker-tip" for="popup-invoker-target" on="manual" content="Anna, project owner"></ui-popup>
  </Example>

  Escape and a click elsewhere close it.  `open` is the controlled state:  writing it shows or hides the popup and
  fires nothing;  the user's own changes dispatch the cancelable `ui-open` / `ui-close` first.  Content comes from
  the `header` / `content` shorthands (Fomantic's `title` / `content`), slotted markup, or `<ui-header>` /
  `<ui-content>` parts.

```js
const popup = document.querySelector("ui-popup")
popup.target = document.querySelector("#avatar") // wins over `for`
popup.addEventListener("ui-close", (event) => {
  if (form.dirty) event.preventDefault() // keep it open
})
popup.open = true // show it from code:  no event
```

  The CSS-only tooltip is a plain attribute on any element:  `data-tooltip` (the text), `data-position` (the same
  twelve positions, default `top center`), `data-inverted` and `data-variation`.  It lives in the page stylesheet
  (`ui.css`), so it works with no script and costs nothing.  But it cannot flip, cannot hold markup, and its text
  is a CSS pseudo-element, which screen readers do not reliably announce:  use it for hints only, and a
  `<ui-popup>` for anything that matters.

```html
<button data-tooltip="Add users" data-position="bottom left" data-inverted data-variation="small">+</button>
```

<Section title="Theming">
  Theme with the public `--ui-popup-*` tokens:  set one on the element, on any ancestor (`:root` for every popup),
  or on the box through `::part(popup)`.  They inherit into the shadow root, where the sheet reads each through a
  private alias, so nothing inside blocks them.  `wide` and `very wide` swap the max width for
  `--ui-popup-wide-width` / `--ui-popup-very-wide-width`;  a slotted header reads `--ui-popup-header-font-size`
  from the popup.  The CSS-only tooltip reads `--ui-tooltip-*` tokens on the element that carries it.

```css
:root {
  --ui-popup-radius: 0.5em;
}
ui-popup.help {
  --ui-popup-max-width: 320px;
}
[data-tooltip] {
  --ui-tooltip-distance: 0.75em;
}
```

<Section title="Accessibility">
  - The ARIA pattern follows `on`:
    - `hover`, `focus` and `manual` popups are tooltips:  the popup has `role="tooltip"` and the target is
      `aria-describedby` it, so its text is read as the target's description.  Keep that text short, and put
      nothing interactive in it.
    - `click` popups are non-modal dialogs:  `role="dialog"`, named by `header` or the popup's `aria-label`;  the
      target gets `aria-haspopup="dialog"`, `aria-expanded` and `aria-controls`.
  - The ARIA goes on the element that actually takes focus:  for a `<ui-button>`, its inner `<button>`.
  - Hover popups also open on keyboard focus, stay open while hovered, and close with Escape:  hoverable,
    persistent and dismissible, as WCAG 1.4.13 asks.
  - A target with only an icon still needs its own name (`aria-label`):  a tooltip describes, it does not name.
  - The CSS-only `data-tooltip` text is a pseudo-element and is not reliably announced;  never rely on it alone.

  | Key               | Action                                                    |
  | ----------------- | --------------------------------------------------------- |
  | Tab (onto target) | Shows a `hover` or `focus` popup;  leaving the target hides it |
  | Enter / Space     | Toggles a `click` popup (the target's own activation)     |
  | Escape            | Closes the popup                                          |

  - If the element fails to render, its native fallback never shows the popup:  no positioning, triggers, events
    or Escape.  A tooltip-like popup copies its text into the target's native `title` (when it has none), so the
    hint survives;  a `click` popup shows nothing.
</Section>

<Section title="Framework usage">
  Set `target` as a property when the target is not a sibling or an id, and listen for `ui-open` / `ui-close`.

```jsx
// React 19
<ui-popup target={anchorEl} on="click" header="Share" onui-close={(e) => setOpen(false)}>...</ui-popup>
```

```html
<!-- Vue 3.5: compilerOptions.isCustomElement = (tag) => tag.startsWith("ui-") -->
<ui-popup :target="anchorEl" on="click" header="Share" @ui-close="open = false">...</ui-popup>
```

```jsx
// Solid 2:  no `on:` namespace, so add `ui-*` listeners in a ref callback
<ui-popup
  prop:target={anchorEl}
  on="click"
  header="Share"
  ref={(el) => el.addEventListener("ui-close", () => setOpen(false))}
>
  ...
</ui-popup>
```

</Section>
