<Section title="Behaviour">
  A rail is positioned against the nearest positioned box around it:  a `<ui-segment>`, or any element of yours with
  `position: relative`.  It takes no room in the layout, so leave space beside the container for an outside rail (or
  use `internal`).  Put anything in it:  a segment, a sticky menu, an ad.  It has no events.

  <VocabularyTable family="ui-rail" />
</Section>

<Section title="Theming">
  Theme with the public `--ui-rail-*` tokens:  set one on the element, on any ancestor (a region, `:root`), or on the
  rail's box through `::part(rail)`.  They inherit into the shadow root, where the sheet reads each through a private
  alias, so nothing inside blocks them.  `--ui-rail-width` is Fomantic's 300px;  `close` and `dividing` rails add
  their own distance to it.

```css
/* every rail on the page */
:root {
  --ui-rail-width: 240px;
}
/* one layout */
.docs-page {
  --ui-rail-distance: 2em;
}
```

  <CssTokens family="ui-rail" />
</Section>

<Section title="Accessibility">
  - A rail is a plain block with no role:  its content carries the meaning.  If the rail is a region of its own (a
    table of contents, related links), put a named landmark inside it, e.g. `<nav aria-label="On this page">`.
  - A rail comes before or after the main content in the source, wherever you wrote it;  it is only moved visually.
    Write it where it makes sense to read it.
  - An outside rail can end up off screen on a narrow viewport.  Hide it, or move its content into the page, on
    small screens.
  - If the element can't render, its native fallback keeps the same box and class words, so the rail is still
    positioned by the same styles.
</Section>
