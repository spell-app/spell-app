# P2 -- the remaining doc elements

Read `BRIEF.md` beside this first.  The infra is BUILT (P2 infra agent);  copy its patterns:

- Model element:  `packages/ui/src/docs-components/ui-docs-example/` (every family file:  controller, vocabulary,
  fallback, css, tests, examples).  Barrel + types:  `src/docs-components/index.ts`,
  `src/docs-components/docs-components.types.ts`.  Data access:  `src/docs-components/SiteData.ts`.
- Data:  `packages/ui/site/_data/components.json` (generated by `yarn site:data`, from `tools/SiteDataBuilder.ts`,
  `tools/FamilyTokens.ts`;  page meta in `site/_data/pages.json`).  Shape:
  `{ $comment, version, topics:[{id,title}], components:[SiteTag], docs:[SiteTag], families:{folder -> {folder,
  mainTag, title, summary, status, docs, tags, tokens:[{name, default, description?, type}]}} }`;  a `SiteTag` is
  `{tag, name, folder, mainTag, main, href, topics, aka, description, noun, attributes:[{name, kind, values?,
  valueSet?, default?, aliases?, description}], slots, events, parts, states, texts}`.
  If you need a field that isn't there, add it to the builder + types (small, additive) and regenerate with
  `yarn site:data` -- and say so in your report;  other agents may do the same:  re-read the builder right before
  editing, keep edits local.
- Adding a docs element:  copy `ui-docs-example/` -> `ui-docs-<name>/`;  topic `documentation` + `aka`;  import
  the families of every `ui-*` tag its shadow root renders in its barrel and add those tags to `DocsJSXTags`;
  `yarn gen:root`.  Do NOT run `yarn site:bundle` / `site:build` (the lead does, once, after all of you):  test
  with vitest browser tests, plus `yarn dev`-style or a scratch page if you need a look.
- Pages load:  `<link rel="stylesheet" href="_assets/site.css">` + `<script type="module" src="_assets/site.js">`
  (`../_assets/` from `components/`).  The page server for this checkout:  `yarn server url <ABS path>` from the
  worktree root.
- `<ui-*>` inside your shadow root for every visible piece (tables are `<ui-table>` around a native `<table>`,
  menus `<ui-menu>` + `<ui-item>`, etc.).  Something a widget can't do = a GAP:  plan-doc issue
  `Gap:  <ui-tag> <what>`.
- Other agents build the other doc elements in parallel in their own `ui-docs-<name>/` folders;  shared files
  (`index.ts` barrel, `docs-components.types.ts`, `DocsJSXTags`, the catalog) get small local edits only:  re-read
  right before editing.
- Checks before reporting:  `yarn ts` and your element's tests (`yarn vitest run --project browser
  src/docs-components/ui-docs-<name>`) in `packages/ui`.  Don't run `yarn review` (the lead runs it once).
- Don't commit.  Report (under 250 words):  attributes / events / slots of your element as built, data fields
  added, test results, plan-doc ids.
