D13 Theme joypixels: not ported (remote CDN images)

Fomantic's joypixels theme is only @emojiPath: https://cdn.jsdelivr.net/joypixels/assets/9.0/png/unicode/128/ plus ~3,800 per-emoji background-image rules. Decided NOT acceptable for a theme sheet: (1) a stylesheet that makes third-party requests on every emoji (privacy, offline, CSP), (2) JoyPixels' free licence needs attribution and its own notice says self-hosting may need another licence, (3) ~400 KB of per-emoji CSS, (4) <ui-emoji> renders the native glyph with no per-emoji hook, by design (ui-emoji.css header). No joypixels.css is written, so the theme list doesn't offer a no-op. The right shape is an opt-in emoji IMAGE set, like icon packs: see the <ui-emoji> gap issue.

D14 Theme resetcss: in @layer ui.reset, page-only

Eric Meyer's reset in ui.theme would beat typography.css (ui.base) and native.css (ui.components); Fomantic loads its reset FIRST and styles on top. So resetcss.css is the one sheet in @layer ui.reset, and every selector starts at :root so the copy adopted into shadow roots (shadow: true) matches nothing (a div { padding: 0 } there would strip component boxes). themes.test.ts's layer test got a LAYER_EXCEPTIONS map (resetcss: ui.reset).

D19 Themes may write a component's private variation tokens

A Fomantic variable that themes a VARIATION (secondary menu, styled accordion, basic button) has no public token to set: the variation writes the component's private alias itself (--_ui-menu-active-background, --_button-weight). Theme sheets (package code, pinned by themes.test.ts) may write those on the variation's box in their overrides half, and may READ --_button-edge* so a variation keeps its own look. Their own looks travel in theme-private tokens (--_raised-ring ...) declared on :root so groups hand them to members. Pages still theme with public tokens only. (T2, P6)

D29 Theme families derived at build time into components.json

tools/ThemeFamilies.ts (run by yarn site:data) reads every src/styles/themes/*.css and writes components.json themes: [{ name, title, families, global }]. A sheet touches a family through a class-grammar compound naming a noun (.ui.labeled.icon.button: a noun that is an attribute of another noun's tag is a modifier), a tag selector, or a declared --ui-<tag>-* token; global means it re-declares a foundation token on :root or styles page markup. Titles are hand-kept in pages.json themes (seeded from each sheet's header comment). for lists only themes touching that family, like Fomantic's per-page N Themes; site-wide-only themes (systemfont, rtl, resetcss) aren't listed under any for. Why build time: reading the sheets in the browser would load every theme chunk to fill one menu. Pinned in tools/SiteDataBuilder.test.ts.

  • Remembered (wrapped localStorage, the SAME keys as the Astro ComponentBrowser, so viewers keep theirs): favourites, view, open topics. Topics start CLOSED (as Astro); on load, the current page first topic opens if no open topic holds it (not remembered; closing it sticks).   • Rows: a link <ui-item> (yellow status <ui-label> for in-progress / planned) plus a toggle tertiary star <ui-button>, in a two-column grid via the sub-menu ::part(menu). Only main tags can be current (as Astro). Docs-only tags never listed.
