Binding power

P2 / D21: the smaller design replaces the design doc's (OperatorExpression, {x:operand}, kept alternatives).

  • precedence keeps ONE job: which whole match wins a Choice. New bindingPower, on operator (suffix) rules only: how tightly they bind, read by the existing shunting-yard.

  • Slots: a list prefix's last slot is {list:single_expression}; absolute value / round take {expression:arithmetic_expression}; statements and slots closed by a word keep {expression}.
  • Give-back in Sequence: a word that fails because the slot before swallowed it re-parses that slot shorter. Fixes remove the card of the pile. ~35 lines, the only core change.
  • The model: Parser Model.

Q2 Paren-free signatures: `a|an <known type>` is a parameter, `the ...` is words? → D2

D26 Operators get `precedence`; a Choice's tie-break becomes `priority` UPDATE

From the P3 prototype review. The prototype called how tightly an operator binds bindingPower (table BP); Owen: swap the words instead.

  • precedence = how tightly an operator binds: * before + before is before and. What every programmer already means by it. Set on operator (suffix) rules only, from one named table.

I3 D24 (bounded call arguments inside expressions) not prototyped: it needs a mechanism beyond §4.5 UPDATE

Options:

  1. Twin on registration (~25 lines, spell-side): SpellParser registers a call rule under single_expression as a memoized, frozen copy whose last {x:expression} slot is {x:single_expression}. Declarations, imports and the journal stay as they are. Cost: a new concept (a rule's 'expression twin'), and the language server's references / go-to-definition from a call INSIDE an expression must map the twin back to its ScopeRule.instances entry.
  2. Declarations list both rules: change SPELL: DECLARES to allow a rule list. Touches the saved format, so it belongs with P4's version bump.
  3. Defer to P5: bound only calls whose return type is known.

Recommend 1 if D24 stays; it's the only option that leaves saved declarations alone.
