<Section title="Behaviour">
  A comment is made entirely of [content parts](../ui-parts/), which take the comment's look:  `<ui-avatar src>` is the
  picture, and a `<ui-content>` beside it holds `<ui-author>` (who), `<ui-meta>` (when:  Fomantic's `.metadata`),
  `<ui-description>` (the text:  Fomantic's `.text`) and `<ui-actions>`.  There are no shorthand attributes.

  A `<ui-comments>` placed inside a comment is that comment's thread of replies, indented below it, and threads nest
  as deep as the conversation goes.  A thread has no variations of its own:  `threaded`, `minimal`, `inverted` and
  `size` are set once on the outer list and reach every thread.  `collapsed` and `disabled` work anywhere:  on the
  list, a thread or one comment.  Neither element fires events of its own;  wire your own handlers to the action
  buttons, and set `collapsed` to fold a thread away.

```js
const thread = document.querySelector("ui-comment ui-comments")
const toggle = document.querySelector("#show-replies") // a <button aria-expanded="true">
toggle.addEventListener("click", () => {
  thread.toggleAttribute("collapsed")
  toggle.setAttribute("aria-expanded", String(!thread.hasAttribute("collapsed")))
})
```

<Section title="Theming">
  Theme with the public `--ui-comments-*` and `--ui-comment-*` tokens:  set one on the list, on any ancestor (`:root`
  for every list), or on its box through `::part(comments)`;  its comments and threads inherit them.  `--_ui-comments-minimal` is the switch `minimal` sets;  use the attribute.
  The parts inside a comment also read a few tokens that are unset by default, so they are not in the table:
  `--ui-comment-avatar-width` (`2.5em`), `--ui-comment-content-margin` (`3.5em`, the space beside the avatar),
  `--ui-comment-author-color`, `--ui-comment-meta-color`, `--ui-comment-text-color` and `--ui-comment-action-color`.

```css
ui-comments {
  --ui-comments-max-width: 50em;
  --ui-comment-distance: 1em;
  --ui-comment-avatar-width: 3em;
  --ui-comment-content-margin: 4em;
}
```

<Section title="Accessibility">
  - Each comment is an `<article>`, and a reply's article sits inside the article it answers, which is how HTML
    describes a thread of user comments.  The list itself has no role:  give it a heading, as the
    `<ui-header level="3">` in the first example does.
  - Put real `<button>`s in `<ui-actions>` for actions and links for navigation, so focus, Enter and Space come from
    the browser.  `minimal` shows the actions while the comment is hovered OR holds keyboard focus, so a focused
    action is never invisible.
  - `<ui-avatar>` is decorative by default (`alt=""`), since the author's name sits beside it;  set `alt` when the
    picture says something the name doesn't.
  - `collapsed` hides a comment or thread from everyone, screen readers included.  A button that toggles it should
    carry `aria-expanded`.
  - `disabled` fades the comment, blocks the mouse and sets `aria-disabled`.  Its buttons and links stay in the tab
    order;  add `inert` when they must not be reached at all.
  - Label the reply field, as the examples do with `aria-label`.
  - If a list or comment can't render, its native fallback keeps the same boxes (`<article>` for a comment, the
    `reply` box) and class words, so the conversation still reads in order.  It drops the comment styling of the
    parts, and counts a thread only when it sits directly inside a `<ui-comment>`.
</Section>
