3. Overview

Details of the plan: the part that becomes durable docs in the last phase.

3.1 Structure
  • bin/spell.mjs → tsx → src/main.ts (commander) → src/commands/<name>Command.ts: (session, args, options) => exitCode.
  • CliSession owns SpellDiskWorkspace + SpellLanguageService + ScopeExplorer: the CLI sees what an editor does.
  • Child processes in src/runner/ (run / test, now speed) never import $/cli values.
  • Runs spell's SOURCE, no build (C1).

3.2 Scope packs
  • <Project>.scopes.js: the Type Explorer's data for a page with no parser (e.g. <spell-app>).
  • Written after a CLEAN compile (compiled, no file errors) by three writers, all through SpellDiskWorkspace.writeScopes(), so byte-identical: the language server, yarn scopes, and now spell compile / spell watch (P1).
  • Not with --stdout or --check-only: those write nothing.

3.3 spell speed
  1. One side = a child process running SP.spellParser.speedTest(), printing JSON.
  2. --against <ref>: temp git worktree of the ref, root node_modules symlinked in, the runner COPIED in (D3), run there, worktree removed.
  3. Each side 3 runs (--runs); combined: mean of averages (integer), lowest min, highest max.
  4. Table: Previous / Current / Change, bold row headers, no ms, right-aligned equal columns.

3.4 Language tools
  • parse: a line's match tree + compiled output; --in parses in a project's scope.
  • repl: the same, line after line, in an Ink screen.
  • explain: hover text + rule syntax, via workspaceSymbols() + describeRecord().
  • new: project.json + a starter .spell (D4).

4. Caveats
  1. C1 CLI runs spell's working copy: a half-done change in lsp/src/ or SpellProject breaks spell silently
  2. C2 speed --against symlinks today's root node_modules into the old tree: a ref with different deps may fail
  3. C3 format relies on formatting() being whitespace-only (P.TokenFormatter)
  4. C4 repl's interactive screen is tested only through ink-testing-librarydetails

    The piped mode runs end to end in cli.test.ts; the live screen wasn't driven in a real terminal tonight.

  5. C5 explore e: one-line descriptions onlydetails

    A description of several lines would be flattened by a one-line field, so e refuses and points at o (open in editor). Never edits test projects.

  6. C6 A browser run serves what was compiled at start: no live reload

7. Decisions

What was decided, and why. Settled: don't re-argue without new facts.

  1. D1 All phases in one go, no stops; commit per phase on worktree-cli-additions only (never main, never pushed)details

    Owen, 2026-10-01, going to bed. A blocker that needs Owen: record as a question here, take the safest option, keep going. yarn vscode after each phase.

  2. D2 spell speed --against <ref> builds the temp worktree itselfdetails

    Replaces the manual speed-test routine. Plain spell speed = working copy only.

  3. D3 speed runner is copied into the other tree, not run from oursdetails

    Aliases ($/spell ...) only resolve inside a tree: a script outside it can't import spell.

  4. D4 spell new defaults to @user (projects/user/), writes a tiny starterdetails

    Starter: a comment naming the project + print "hello from <name>". Written by the CLI itself, NOT projectUtils.createProject(), whose getIndex() writes Untitled.spell.

  5. D5 explore e edits descriptions in an inline Ink text field
  6. D6 Small commands (P2) before language tools (P3)
  7. D7 Ink 6 + React 19: dropped
  8. D8 test --watch = watch --test on the same targets: one implementation
  9. D9 format requires targets, as compile / check do
  10. D10 Scope-pack test checks content, not byte-identity with the scopes scriptdetails

    The scopes script takes a root's project id, not a temp folder. All three writers call SpellDiskWorkspace.writeScopes(). By hand: spell compile @examples/Solitaire @examples/FizzBuzz @examples/Calculator rewrote their CHECKED-IN packs unchanged: byte-identical to the language server's.

  11. D11 No VS Code extension rebuild after these phasesdetails

    Nothing here changes the extension or the server's behaviour (P1 only edits a comment in lsp/src/scopes.ts). Run from this worktree, the rebuild would also install an extension built from the worktree over the main checkout's.

  12. D12 speed: sides take turns run by run; one fluke dropped (average over 1.25x the median, 3+ runs); Change shows + for slowerdetails

    Turns: a busy moment hits both sides alike. Fluke rule makes Owen's 'may discard one anomalous run' mechanical. The + sign isn't in Owen's example (only negatives and 0): added so slower is unmistakable.

  13. D13 parse / repl lines parse in a scope of their own, inside the project's with --indetails

    CLI.lineScope(): a ProjectScope whose parent is the project's, so its types and phrases are known but nothing typed lands in the project. repl commits each line there, so x is 3 then print x works. No rule given: statement, then expression; several lines: block.

  14. D14 explain: rules by name or first word; declarations (--in) as the editor's hover, minus its rule sectiondetails

    The hover's first section is the DECLARING statement's rule (e.g. type), which says nothing about the thing.

  15. D15 Test name filter is --name <text>, not a second positional (CHANGED from the old plan)details

    The old plan said spell test . "deck creation". But test takes several targets, so a name there can't be told from a target. Now: spell test . --name "deck creation", which watch --test takes too.

  16. D16 watch rebuilds an importer from scratch, as if its project.json changeddetails

    A compiled import's declarations are only read on a full parse (SpellProject.loadImportScope()), so an incremental re-parse wouldn't see them. Only among WATCHED projects. Not after the first build: everything is building then anyway.

  17. D17 Target prompt: only when no target was typed, no project is here, and there's a terminaldetails

    Owen, 2026-10-01: in a project folder, use that project; otherwise shell-autocomplete style -- domain, then project folders, then files with 'entire project' first.

  18. D18 Recent picks: packages/cli/.recent-targets.json, gitignored, last 3details

    Per checkout (Owen's choice). Only what the prompt picks is remembered.
  19. D19 One local server for icons --open and run; SPELL_NO_BROWSER=1 prints the URL instead
  20. D20 Browser runs use the spell-app element's src= mode, dist-element built on demanddetails

    Compiled JS + scope pack served beside each other: no app server, no /api. A fresh checkout has no dist-element/: yarn build:element runs once.

  21. D21 spell serve runs the dev server: vite + express, as the app's yarn startdetails

    Owen, 2026-10-01: editor UI with hot reload, plus /api for saving files.

  22. D22 P7, P8, P10 in one go, commit per phase; then report (P9 docs after)
  23. D23 icons: keywords match only at the start of a word; names and aliases anywheredetails

    Otherwise bell found brain by its keyword cerebellum. dumbbell still matches, by name.

  24. D24 spell serve runs app's start:dev + start:server itself, not yarn startdetails

    yarn start runs yarn install and yarn stop, which would stop other checkouts' servers. Each runs in its own process group so Ctrl-C stops what yarn started. A busy port is refused (vite --strictPort), not drifted from. No target outside a project: the app's chooser, not the prompt -- the app is a chooser itself.
