RunnerSplit A runner's two panes, one above the other, with a bar to drag between them.

How a runner lays itself out: the running app on top, and the debug pane below it while it's open, with a bar between them to drag. Every runner draws it, in a page and in VS Code alike.

Written for: anyone changing how a runner lays out its app and debug pane Live: inside a real <spell-viewer>, from the app's element build this page loads

The calculator example, with its debug pane open: everything under the toolbar is a RunnerSplit, the app above, the bar, the debug pane below. Drag the bar to move it; click Debug to close the bottom pane.

Live, from the app's element build, which this set's pages load: /element/spell.pack.js. The app package builds it with yarn build:element.

<spell-viewer>'s runner splits its app from its debug pane:

SpellAppRunner.tsx · the app above, the debug pane below · 9 lines
  • split is where the bar is, in one of two units. With "%", the default, it's the top pane's share of a fixed height.
  • With "px", for a runner as tall as its app (a <spell-viewer> with no height), it's the bottom pane's height.
  • Dragging shows as it goes, but onSplit is told only when the bar is let go: so VS Code writes its settings file once.
  • Without showBottom, the top pane fills it all, and there's no bar.
  • The top pane is drawn once and never again, so the running app's mount point stays put. The bottom pane is drawn each time it's shown.
  • The bottom pane is usually a RunnerPane.
